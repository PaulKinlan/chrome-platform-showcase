Checkable state lab

Menu items become radios or checkboxes by ancestry: wrap them in <fieldset checkable=single> (exclusive, role menuitemradio) or checkable=multiple (independent, role menuitemcheckbox). The state model is deliberately asymmetric — checked is a live IDL attribute that reflects no content attribute, while defaultchecked is a reflected content attribute that only sets initial state. This lab probes each rule against the real IDL and runs the equivalent manual pattern with a state ledger.

<menulist id=sort-menu>
  <fieldset checkable=single>      <!-- role menuitemradio, exclusive -->
    <legend>Sort by</legend>
    <menuitem defaultchecked>Recently added</menuitem>
    <menuitem>Date created</menuitem>
  </fieldset>
  <fieldset checkable=multiple>    <!-- role menuitemcheckbox -->
    <menuitem defaultchecked>Show ruler</menuitem>
    <menuitem>Show outline</menuitem>
  </fieldset>
</menulist>
// item.checked   → live state, reflects NO content attribute
// item.defaultChecked ↔ defaultchecked attribute (initial state only)
// activation: click event, then (if not defaultPrevented) checked flips + 'checked' event
