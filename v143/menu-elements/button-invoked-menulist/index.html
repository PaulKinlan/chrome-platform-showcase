Button-invoked menulist

A <menulist> doesn't need a menubar — any command invoker can open one, which is the everyday "actions" dropdown in tables, toolbars, and cards. This page invokes a real standalone menulist from a plain <button command=… commandfor=…>, tests which command keywords this engine actually honours live (the explainer names toggle-menu; the generic popover commands work too, and the accepted set varies by build — the matrix below is the truth for this browser), and runs the plain-[popover] baseline that works in every modern browser — the machinery menulist inherits.

1 · Native: <button commandfor> → <menulist>

Live markup — the button below carries command="toggle-popover" commandfor="actions".

2 · Baseline: <button popovertarget> → [popover] (works today)

Everything a menulist inherits — invoker wiring, top layer, light dismiss on outside click, Esc to close, :popover-open styling — via the plain Popover API. What it does not give you: menu roles, arrow-key navigation, or checkable state. Try it and compare.

…
<button command=toggle-menu commandfor=menu>Actions</button>  <!-- explainer -->
<button command=toggle-popover commandfor=menu>Actions</button>  <!-- current Chromium -->
<menulist id=menu>
  <menuitem>Rename</menuitem>
</menulist>
// menulist behaves as popover=auto with the invoker as implicit anchor;
// the invoking button gets implicit aria-haspopup=menu + aria-expanded.
