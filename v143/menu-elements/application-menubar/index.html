Application Menubar

A declarative <menubar> with nested <submenu>, exclusive and multi-checkable <fieldset checkable> groups, defaultchecked, and the live checked/defaultChecked/disabled IDL surface.

Behind a flag. Runtime feature MenuElements (status experimental; no dedicated chrome://flags entry). In Chrome 143+ enable chrome://flags/#enable-experimental-web-platform-features and relaunch, or launch with --enable-blink-features=MenuElements.

1 · The menubar

One tab stop for the whole bar; arrow keys move across top-level items; Enter/Space opens a submenu; Escape closes it and returns focus. Checkable items live in <fieldset checkable="single"> (radio semantics, role menuitemradio) or <fieldset checkable="multiple"> (checkbox semantics, role menuitemcheckbox).

2 · Checked-state IDL inspector

Reads checked, defaultChecked, and disabled straight off every <menuitem> in the markup above (in unsupported browsers this honestly reports the IDL members as missing). checked is live state and reflects no content attribute; defaultchecked only seeds the initial state. Checking one item of a checkable="single" fieldset unchecks its siblings.

3 · Parser inspector (works in every browser)

Feeds the exact menubar markup to innerHTML in a detached element and reports what this browser's parser produced — element by element. On an unflagged browser every menu tag comes back HTMLUnknownElement; that is the honest negative result.

code

<menulist>
  <fieldset checkable="single">
    <legend>Zoom</legend>
    <menuitem>50%</menuitem>
    <menuitem defaultchecked>100%</menuitem>
    <menuitem>150%</menuitem>
  </fieldset>
  <fieldset checkable="multiple">
    <menuitem defaultchecked>Show Ruler</menuitem>
    <menuitem>Show Outline</menuitem>
  </fieldset>
</menulist>

item.checked        // live state, no reflected attribute
item.defaultChecked // reflects the defaultchecked attribute
item.addEventListener('checked', e => { /* fires after click, before close */ });
