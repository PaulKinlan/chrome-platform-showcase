Removal event probe

A real same-origin <iframe> runs a widget that listens for pagehide, visibilitychange and unload. It reports each one to this page through a synchronous direct call, so the page can tell whether the handler ran inside its own iframe.remove() call. That is the deprecated behaviour. The HTML Standard fires none of the three when a child navigable is destroyed by removal.

Flag: the new behaviour is behind --enable-blink-features=OmitSubframeDetachmentEventsOnRemoval (status test, so --enable-experimental-web-platform-features does not enable it, and there is no chrome://flags entry). ChromeStatus lists a developer trial from M156 and a deprecation trial in M160–M162. The verdict below comes from what this browser did, not from its version.

what the code does

// inside the widget (frame.html), reporting synchronously to the parent:
addEventListener('pagehide', () => parent.__subframeRemovalReport({ type: 'pagehide' }));
document.addEventListener('visibilitychange', …);
addEventListener('unload', …);

// in this page:
insideRemoval = true;
iframe.remove();          // deprecated: all three handlers run right here
insideRemoval = false;    // spec / flagged Chrome: none of them run at all
