Reverse it yourself

The spec defines side="right" in five words: "then reverse path". So the clearest way to understand the attribute is to actually reverse a path — this page carries a working reverser for absolute M/L/Q/C/A path data, arrows computed from the real geometry to show which way each path runs, and a measured comparison of the two techniques.

Measuring…

Ships in Chrome 156, enabled for everyone. Earlier builds carrying the implementation: launch with --enable-blink-features=SVGTextPathSideAttribute (the exact Blink runtime-flag name, status experimental) or enable chrome://flags/#enable-experimental-web-platform-features. Builds that predate the implementation ignore the attribute regardless of flags — measured on the Chromium 141 this page was built against. Firefox 152 ships it. The manual reversal button below works in every browser, including this one.

what reversing actually takes

// Reversing path data by hand, per segment, back to front:
//   L x,y                   → L (previous point)
//   Q cx,cy x,y             → Q cx,cy (previous point)          // same control
//   C c1x,c1y c2x,c2y x,y   → C c2x,c2y c1x,c1y (previous point) // controls swap
//   A rx,ry rot laf sweep x,y → A rx,ry rot laf (1-sweep) (previous point)
// ...and a new M at what used to be the final point.

The arrows in each panel are not decoration: they are computed from getPointAtLength() on the live path element, so when the button rewrites panel B's path data, its arrows genuinely turn around. The red dot marks each path's start point.
