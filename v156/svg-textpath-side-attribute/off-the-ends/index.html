Off the ends, and around again

The interesting behaviour of text on a path is at the edges: what happens to glyphs pushed past the end, how closed paths wrap, and — new with side — which end startOffset measures from once the path is effectively reversed. This page counts visible glyphs with getExtentOfChar() after every change, so each rule below comes with a measured number, not a promise.

Measuring…

Ships in Chrome 156, enabled for everyone. Earlier builds carrying the implementation: launch with --enable-blink-features=SVGTextPathSideAttribute (the exact Blink runtime-flag name, status experimental) or enable chrome://flags/#enable-experimental-web-platform-features. Builds that predate the implementation ignore the attribute regardless of flags — measured on the Chromium 141 this page was built against. Everything this page measures about startOffset and hidden glyphs is long-shipped behaviour you can exercise right now; the side rows are honestly labelled where they change nothing.

the rules being exercised

  • Open paths clip. The layout algorithm hides any glyph whose midpoint falls before the start or past the end (mid < 0 or mid > length). Drag startOffset towards 125% and watch the visible count fall to zero — that is the rule executing, and this part ships in every browser today.
  • Closed subpaths wrap instead. For a path closed with Z, SVG 2 wraps the offset (mid = mid mod length) and decides visibility from text-anchor and direction — with text-anchor="middle" the window is centred on the offset point. Browsers differ in how completely they implement this; the table above shows what yours measured rather than assuming.
  • side="right" reverses first. The reversal happens before offsets are applied, so startOffset then measures from the other end and the text runs the other way. On a browser without support the side rows measure identical numbers — and the readout says so instead of blaming your browser version (this page was verified to be flag-independent on the build it was written against).

the markup this drives

<path id="p" d="M 40,170 Q 200,40 360,170"/>
<text text-anchor="start">
  <textPath href="#p" startOffset="35%">ROUND AND ROUND WE GO · </textPath>
</text>
