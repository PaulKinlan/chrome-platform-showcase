SVG textPath side attribute

Text on a path always hugged one side of it: the left, relative to the direction the path data happens to run. Putting a label on the other side — inside a circle instead of outside it — meant duplicating the path with its coordinates hand-reversed. SVG 2's side attribute is one word, side="right", that flips the text to the other side, equivalent to reversing the path direction without touching the path data.

concepts

  1. The circle label playground

    One circular path, one label, and a side toggle. Sliders for startOffset and font size, and a geometric probe that measures where the first glyph actually landed — inside or outside the circle — instead of trusting the attribute.

  2. A badge, both arcs readable

    The canonical use case: a round seal with text over the top and under the bottom, both reading left to right. The hand-reversed-path workaround and the side="right" version are rendered next to each other, and the page measures which one your browser draws upright.

  3. Reverse it yourself

    The spec defines side="right" as "reverse the path". Direction arrows are computed from the real path geometry, and a working path-data reverser flips the rendering in any browser today — so you can see exactly what the one-word attribute replaces.

  4. Off the ends, and around again

    What happens at the edges: glyphs pushed past the end of an open path are hidden, closed paths wrap depending on text-anchor, and side="right" moves where startOffset measures from. Every claim on the page is paired with a measured glyph count.

why it shipped

The working group added side in SVG 2 precisely for shapes: a circle, an ellipse, a rectangle each have an inside and an outside, and authors kept needing text on both — a seal with a name curving over the top and a motto curving under the bottom. Without side, the only route was a second path with the geometry reversed by hand: arcs with their sweep flags flipped, curves with their control points reordered. It works, and one of the pages here does it live, but it is exactly the kind of mechanical transformation a renderer should do for you.

This is a "Chromium catches up" feature: Firefox already ships it (Firefox 152), WebKit has an implementation in review, and Chrome 156 closes the gap. It ships enabled for all users, with no origin trial.

the API shape

<!-- Default: text on the left side of the path direction. -->
<text><textPath href="#circle">OUTSIDE THE CIRCLE</textPath></text>

<!-- New in Chrome 156: flip to the other side — equivalent
     to reversing the path direction. -->
<text><textPath href="#circle" side="right">INSIDE THE CIRCLE</textPath></text>

Values are left (the initial value) and right; the attribute is animatable as a discrete flip. The published SVG 2 draft defines only the content attribute — the working group has resolved to add IDL reflection (SVGAnimatedEnumeration side with TEXTPATH_SIDETYPE_* constants, which is what Chromium implements), but that text has not yet landed in the Editor's Draft, so these pages treat IDL reflection as informational rather than as the contract.
