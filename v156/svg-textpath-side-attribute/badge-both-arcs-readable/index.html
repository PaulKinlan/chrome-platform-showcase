A badge, both arcs readable

The round seal is the use case the working group named when it added side: a name curving over the top, a motto curving under the bottom, both reading left to right. Below, the way it has always been done — a second arc with its sweep flag reversed by hand — next to the one-attribute version, with the page measuring which of the two your browser actually draws the right way up.

Measuring…

Ships in Chrome 156, enabled for everyone. Earlier builds that carry the implementation can launch with --enable-blink-features=SVGTextPathSideAttribute (the exact runtime_enabled_features.json5 name, status experimental) or enable chrome://flags/#enable-experimental-web-platform-features; there is no dedicated flags entry. Builds older than the implementation ignore the attribute no matter the flag — this page measured Chromium 141 both ways. Firefox 152 ships it. The hand-reversed badge on the right works everywhere, today.

what the two versions cost

<!-- side attribute: ONE path, the renderer reverses it for you -->
<path id="circle" d="M 310,170 A 110,110 0 0,1 90,170
                     A 110,110 0 0,1 310,170"/>
<text text-anchor="middle"><textPath href="#circle" startOffset="75%">TOP</textPath></text>
<text text-anchor="middle"><textPath href="#circle" side="right" startOffset="75%">BOTTOM</textPath></text>

<!-- workaround: a SECOND arc, sweep flag flipped by hand (0,1 → 0,0) -->
<path id="top-arc"    d="M 90,170 A 110,110 0 0,1 310,170"/>
<path id="bottom-arc" d="M 90,170 A 110,110 0 0,0 310,170"/>

The workaround needs you to know that reversing an SVG arc means flipping its sweep flag — and for curves, reordering control points. Get it wrong and the text renders mirrored or on the wrong side. side="right" is the renderer doing that transformation, defined in the spec as exactly "reverse the path".
