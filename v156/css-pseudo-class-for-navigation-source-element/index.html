The element that started it: :navigation-source

When a link is clicked or a form is submitted, the browser knows exactly which element set the navigation in motion — but until now CSS did not. The :navigation-source pseudo-class matches that element for the whole course of the navigation, so the thumbnail you clicked can grow into the page you are arriving at, without a line of JavaScript.

why it shipped

The motivation comes from view transitions. A cross-document (or intercepted same-document) transition can morph an element on the old page into an element on the new one — but only if the old page knows which element to tag with a view-transition-name. Until now that meant a click handler racing to set an inline style before the navigation proceeded. :navigation-source is the declarative answer: the spec defines it as a CSS reflection of the Navigation API's sourceElement property, matching the <a>, <area>, <form>, submit <input>, or <button> that triggered the current navigation, from the moment the navigation starts until it finishes.

It is part of the CSS Navigation Matching draft, which grew out of the declarative partial updates work: styling that responds to where a navigation is going and what set it off, without intercepting anything in script.

the API shape

/* The spec's own example: tag the clicked link's thumbnail
   so a view transition can morph it into the next page. */
a:navigation-source .thumb {
  view-transition-name: active-image;
}

/* Forms and submit buttons are navigation sources too. */
form:navigation-source .submit,
.submit:navigation-source {
  outline: 3px solid green;
}

The element matches while the current navigation state is non-null — through the navigate event, precommit, commit, and the handler — and stops matching once the navigation settles. History traversals (navigation.back(), the back button) have no source element, so nothing matches.

enabling it now

:navigation-source ships in Chrome 156 for all users. Before that it is an experimental Blink feature: the runtime flag is NavigationSourcePseudoClass (also implied by the wider RouteMatching flag), so in Chrome Canary enable chrome://flags/#enable-experimental-web-platform-features, or launch with --enable-blink-features=NavigationSourcePseudoClass.

These pages were built and verified on Chromium 141, where the flag itself does not exist yet — even flagged runs report the selector as unsupported. Every probe here measures the browser honestly and reports that result; the interactive pages additionally mirror what the pseudo-class will do using the Navigation API's sourceElement, which is already shipping, and label that mirror as a simulation wherever it appears.
