← CSS pseudo-class for navigation source element

v156 · :navigation-source

Thumbnail to hero

This is the use case :navigation-source shipped for. A gallery of prints; click one and its thumbnail should morph into the detail page's hero. The view transition machinery can do the morph — but only if the clicked thumbnail carries the view-transition-name, and only the navigation knows which one that is.

What is real and what is simulated here. The stylesheet contains the spec's own rule — a:navigation-source .thumb { view-transition-name: active-image } — which does the tagging natively in Chrome 156+ (Canary: --enable-blink-features=NavigationSourcePseudoClass or chrome://flags/#enable-experimental-web-platform-features). On this page's verification browser (Chromium 141) that selector is not parsed yet, so a JS mirror reads the same navigation's NavigateEvent.sourceElement and applies an equivalent class — marked with a dashed outline and always labelled a simulation of what the pseudo-class will do natively. The navigations and the view transition are real either way.

The whole trick, in CSS

/* Old page state: the clicked link's thumbnail is named… */
a:navigation-source .thumb {
  view-transition-name: active-image;
}

/* …new page state: the hero has the same name. The browser
   morphs one into the other. No click handler required. */
.hero-art {
  view-transition-name: active-image;
}

Before this pseudo-class, step one needed JavaScript: catch the click, set an inline view-transition-name, and hope you did it before the navigation snapshot. That script race is exactly what the ChromeStatus motivation cites — "a way to visually indicate a relationship between the navigation source and the process of the navigation, e.g. expanding a thumbnail using an animation." Here the demo runs it as a same-document navigation so you can watch it repeatedly; cross-document view transitions use the identical rule.
