v156 · :navigation-source

The forgiving selector gotcha

A selector list dies as a unit: one unknown selector in the commas and the whole rule is discarded, including the parts every browser understands. Adopting a brand-new pseudo-class like :navigation-source is exactly when this bites. The three rules on this page are measured live in your browser — parse survival and rendered effect both.

This page is fully observable today. Unlike the other concepts, nothing here needs Chrome 156: the gotcha is the old behaviour. On a browser without :navigation-source (like the Chromium 141 this was verified on), rule A collapses and rules B and C survive. On Chrome 156+ (or Canary with --enable-blink-features=NavigationSourcePseudoClass) all three survive — run the measurement there and the difference is the feature arriving.

Three ways to write the same intent

A — comma-combined (fragile)

.gotcha .mark-a, .gotcha :navigation-source {
  outline: 4px solid var(--accent-rose); font-weight: 700;
}

This sentence contains a span with class .mark-a that the rule above plainly targets.

B — split into separate rules (safe)

.gotcha .mark-b { outline: 4px solid var(--accent-emerald); font-weight: 700; }
.gotcha :navigation-source { outline: 4px solid var(--accent-emerald); }

This sentence contains a span with class .mark-b, targeted by its own rule.

C — wrapped in :is() (forgiving)

.gotcha :is(.mark-c, :navigation-source) {
  outline: 4px solid var(--accent-blue); font-weight: 700;
}

This sentence contains a span with class .mark-c, sharing a rule via a forgiving list.

Why this matters for :navigation-source specifically

The natural adoption move is to append the new selector to an existing highlight rule — one comma, done. In every pre-156 browser that one comma silently deletes the styling your users already had. The CSS Selectors spec makes :is() and :where() lists forgiving (unknown members are dropped individually) precisely for this migration problem; a top-level selector list is not forgiving, by design. The demos on this feature's other pages keep every :navigation-source rule standalone for exactly this reason.
