Comment thread: mentions & glossary

This is a code-review thread. On desktop, hovering an @mention opens a profile card and hovering a glossary term opens its definition. On a phone, long-pressing those links opens the browser's context menu. With ::interest-button, the touch layout gets one small ⓘ per invoker, and the cards are a single tap away. The ⓘ is shown only to coarse pointers, and the desktop layout stays unchanged.

why this pattern

The explainer's motivating survey found that hovercards are almost never reachable on touchscreens. The context-menu "Show details" item fixes access, but users rarely discover it. A thread full of mentions is exactly where a visible, tappable affordance pays off. It is opt-in because the same designers often don't want it on desktop or in dense layouts, so the any-pointer: coarse query keeps it to touch. When the pseudo-element is not generated, this page adds real <button popovertarget> ⓘ buttons instead. They use tabindex="-1", which mirrors the pseudo-element staying out of the focus order, because keyboard focus on the link already shows interest. The dashed outline marks them as the fallback.
