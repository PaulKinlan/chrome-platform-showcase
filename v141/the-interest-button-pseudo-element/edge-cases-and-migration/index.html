Edge cases & migration

The pseudo-element exists only while its originating element is a valid interest source, it comes after ::after, and the spec deliberately keeps it out of the tab order and the accessibility tree. Each experiment below changes a real DOM condition and measures whether the box is there.

Flag: HTMLInterestForInterestButtonPseudo (experimental). Enable chrome://flags/#enable-experimental-web-platform-features, or launch with --enable-blink-features=HTMLInterestForInterestButtonPseudo. Without it, every "box" readout is 0. The page labels that state as a fallback instead of comparing it against the spec.

Choose deliberately. The hand-rolled button is a real control: keyboard and screen-reader users can reach it, which matters when the hint carries information they need (the toggletip guidance). ::interest-button adds no tab stop and no accessibility node, because keyboard users already show interest by focusing the link and the hint is already exposed through the link. Use it only for supplemental previews.

3 · On browsers without the feature

SituationWhat the user gets
interestfor supported, ::interest-button not (Chromium without the flag)The selector still parses and the rule is kept, but no box is drawn. Long-press, hover and focus still show interest. Nothing breaks.
No interestfor at all (Firefox/Safari today)The selector is invalid there, so an invalid selector drops only its own rule; avoid grouping it with other selectors in one rule. The links work as plain links. Load the interestfor polyfill only if !('interestForElement' in HTMLButtonElement.prototype).
Critical information behind the hintDo not rely on ::interest-button. Use a real toggletip button (left column above) or put the information inline.
