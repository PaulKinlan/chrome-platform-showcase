Rendering probe

The parser check alone is not enough here. This page reads three separate things: whether the selector parses, what getComputedStyle(el, '::interest-button').content returns, and whether a box was actually laid out. For the last one it measures each specimen with the pseudo-element's content switched on and then off. A real box adds about 44px.

Flag: HTMLInterestForInterestButtonPseudo (experimental). Enable chrome://flags/#enable-experimental-web-platform-features, or launch with --enable-blink-features=HTMLInterestForInterestButtonPseudo. Measured in Chromium 153: without the flag the selector parses and computed style reports the content, but the layout delta is 0.

how to read this

If the selector parses but the layout delta is 0, the engine knows the name but has not implemented the box. Chromium 153 without the flag behaves like this. If the delta is about 44px on cards 1–2 and 0 on cards 3–6, the implementation matches the spec's "valid interest sources only, opt-in content" contract. Any other pattern is a real conformance failure, and the probe reports it rather than hiding it.
