The ::interest-button pseudo element

Interest invokers (interestfor) open hovercards on hover or focus — but on a touchscreen there is no hover, and long-pressing a link usually summons the native context menu instead. ::interest-button is the opt-in fix: a button-like pseudo-element rendered next to the invoker that, when tapped, triggers the interest action directly. Developers opt in simply by styling it.

concepts

  1. Pseudo probe — the exact selector contract: CSS.supports("selector(::interest-button)"), paired with an observable check — getComputedStyle(el, "::interest-button") on a real styled invoker — so the probe can't pass on syntax alone.
  2. Touch affordance — the problem it solves, live: hovercard links with styled interest buttons beside them. Hover/focus still works everywhere the invoker ships; the tappable button is the touchscreen path.
  3. Styling lab — the opt-in mechanics: toggle real declarations on and off and read back what getComputedStyle reports for the pseudo-element, including the no-style case that keeps the button hidden.

why it shipped

The Open UI interest-invokers explainer calls touch activation out as the hard case: hover and focus map cleanly to pointer and keyboard, but touch needed either a cumbersome long-press (which fights the context menu on links) or a visible affordance. ::interest-button (CSS Pseudo-Elements 4) renders that affordance as part of the invoker itself — opt-in by styling, so pages that design their own affordance pay nothing.
