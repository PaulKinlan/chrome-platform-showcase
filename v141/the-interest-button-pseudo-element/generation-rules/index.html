what this proves (and what it can't)

  • Generation follows interest-source validity, not just the attribute. Missing targets, href-less anchors, disabled buttons and unsupported elements produce no box.
  • The cases are measured from the pseudo-element's used width (pixels mean a box, auto means none). The rule never sets an explicit width, so that measurement cannot be fooled.
  • Dynamic target (case 4): in Chrome 153 with the flag, creating #gr-late after load did not generate a box until the interestfor attribute was set again. The page reports whatever this browser does and follows up by re-setting the attribute.
  • Mouse on a button's ⓘ: in headless Chrome 153, a touch tap on case 2's ⓘ opened the target, but a mouse click on it did not. Test it yourself with real hardware.
  • Accessibility-tree absence can't be shown from script. It needs DevTools' accessibility pane or a screen reader.
