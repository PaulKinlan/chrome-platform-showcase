Touch-friendly link previews

A reference article where every link has a hovercard. Mouse and keyboard users get the card by hovering or focusing. On a touchscreen, a long-press on a link opens the context menu, so the article adds the spec's recipe: an ⓘ after each link, shown under @media (any-pointer: coarse). Tap the ⓘ to preview, or tap the link to navigate. The log shows which one happened.

Flag: HTMLInterestForInterestButtonPseudo (experimental). Enable chrome://flags/#enable-experimental-web-platform-features, or launch with --enable-blink-features=HTMLInterestForInterestButtonPseudo. Without it the hovercards still work by hover, focus and long-press (that part has shipped), but no ⓘ renders. The readout below says so.

how it is composed

  • interestfor + popover="hint": hovercards that do not close unrelated menus. Each link carries aria-describedby and each card role="tooltip", because activating the link navigates rather than expands.
  • Implicit anchor positioning: position-area: block-end span-inline-end with flip fallbacks, gated in @supports so browsers without anchor positioning keep the centred UA placement.
  • interest-delay: 0.4s 0.2s, and :root:has(:interest-source) sets the start delay to 0, so scanning across links after the first card opens is instant.
  • ::interest-button under any-pointer: coarse: the touch affordance, with a 44px minimum box.
