scroll-axis-lock

Browsers "lock" a scroll gesture to one axis when it starts mostly-vertical or mostly-horizontal — great for pages, wrong for maps, whiteboards, and 2D canvases. scroll-axis-lock: none is the one-line opt-out: gestures on that element keep their true diagonal vector from the first pixel, on the compositor, with none of the touch-action: none + JavaScript reimplementation that 2D UIs resort to today.

concepts

  1. Value probe

    The exact CSS surface, read live: CSS.supports("scroll-axis-lock", "none"), the computed value on a real element for both keywords (auto · none), and rejection of invalid values — an honest three-state readout on any engine.

  2. Dual pan stage

    Two identical map-style pans, one auto, one none. Drag or wheel-scroll diagonally in each: a live trace plots every (scrollLeft, scrollTop) sample, so a locked gesture draws an L-shaped path while a free one draws your true diagonal — measured, not claimed.

  3. 2D swipe-dismiss

    The mobile-gesture use case: a photo card that dismisses as you scroll it away vertically while keeping natural horizontal drift (scroll-axis-lock: none). Dismissal progress and drift are computed from the real scroll offsets and shown live.

why it shipped

The workaround today is grim: touch-action: none, manual touchmove math on the main thread, and hand-applied transforms — added latency, jank under load, broken overscroll and accessibility. Axis locking is a UA heuristic, so opting out belongs in CSS where the compositor can honour it natively. The property is deliberately small (auto | none, not inherited) and pairs naturally with its sibling in this release, single-axis scroll containers — one feature makes an axis not scrollable at all, the other frees a two-axis scroller from gesture locking.

trying it

The runtime feature ScrollAxisLock is marked stable for Chrome 153. Axis locking only applies to gestures (touch pans and wheel/trackpad scrolls) — script scrolling is never locked — so the demos here read real gesture traces; on a browser without the property they honestly show default locking on both stages.
