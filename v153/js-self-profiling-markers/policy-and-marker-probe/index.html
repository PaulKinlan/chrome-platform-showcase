Policy & marker probe

Markers sit at the end of a chain of prerequisites, and a useful probe tests each link separately instead of shrugging “unsupported”. This page checks the Profiler global and its exact prototype shape, reads back the actual Document-Policy header this route was served with, checks crossOriginIsolated (the IDL gates marker on it), and then really calls new Profiler(…) and shows you precisely what came back.

Heads up: this showcase route is currently served without Document-Policy: js-profiling (adding it needs a server change that is queued for review), so on this site the constructor attempt is expected to surface Chrome’s real policy error. The v147 worker-profiling demo is served with the header today if you want to see a constructor succeed here. For the marker field itself: Chrome 153 runs the JSSelfProfilingMarkers origin trial, or launch with --enable-blink-features=ExperimentalJSProfilerMarkers (also enabled by --enable-experimental-web-platform-features); markers additionally require cross-origin isolation.

why each check matters

  • Global + prototype shape — the base API shipped in Chrome 94; Profiler must be a constructor whose prototype has stop(), sampleInterval, stopped, and inherits from EventTarget (for samplebufferfull).
  • Document-Policy header — profiling is opt-in per response so the engine only pays collection overhead where the page asked for it. The probe re-fetches this page and reads the header out of the real response rather than guessing from the constructor error.
  • crossOriginIsolated — the marker IDL is [CrossOriginIsolated] ProfilerMarker? marker; without COOP+COEP a 153 build with the origin trial still returns marker-less samples.
  • Real constructor call — the only honest support signal. Success starts a real (immediately stopped) profile; failure shows Chrome’s exact DOMException.

the code

// Read the real policy header off the real response — no guessing:
const res = await fetch(location.href, { cache: "no-store" });
res.headers.get("document-policy");   // e.g. "js-profiling", or null

// The honest capability signal is the constructor itself:
try {
  const p = new Profiler({ sampleInterval: 10, maxBufferSize: 100 });
  const trace = await p.stop();       // real trace, even if nearly empty
} catch (err) {
  err.name;     // "NotAllowedError" / DOMException — surface it verbatim
}
