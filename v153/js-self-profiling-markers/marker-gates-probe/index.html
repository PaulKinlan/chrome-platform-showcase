Marker gates probe

A marked sample needs three doors to open, and each one is probed for real here: the document policy (this page's server sends Document-Policy: js-profiling, and the probe constructs an actual Profiler to prove it), cross-origin isolation (the proposal gates marker on [CrossOriginIsolated]), and the engine implementing markers at all (probed by inspecting a real captured trace).

Runs automatically on load.

Gate 1 · Document-Policy: js-profiling

…

Without the policy header, new Profiler() throws NotAllowedError. This page's route serves the header, so construction should genuinely succeed here — try the release index in a console for the opposite result.

Gate 2 · crossOriginIsolated

…

The proposal marks the field [CrossOriginIsolated]: without COOP+COEP isolation, samples stay unmarked even on an implementing engine — deliberate, since markers reveal coarse GC/render timing.

Gate 3 · engine implements the marker field

…

The only honest test is a real capture: profile for 150ms under induced work and check whether any sample object carries a marker member.

// Gate 1 — the policy (server-side header, probed by constructing):
const profiler = new Profiler({ sampleInterval: 10, maxBufferSize: 10000 });

// Gate 2 — isolation (the marker field is [CrossOriginIsolated]):
window.crossOriginIsolated;

// Gate 3 — the field itself, from a real trace:
const trace = await profiler.stop();
trace.samples.some((s) => "marker" in s);
