Spell Check Custom Dictionary API

Every domain has words the spell checker wrongly red-squiggles — product names, tickers, fictional species. document.spellCheckCustomDictionary.addWords([...]) / removeWords([...]) gives the page a transient, per-document dictionary layered on top of the browser's: ignored-word semantics (never written into the user's persistent dictionary), write-only by design, and scoped to the document so SPAs can swap vocabulary per view.

concepts

  1. Surface probe

    Detect the exact shipped members — document.spellCheckCustomDictionary, addWords, removeWords — and make a real call, with the exact SpellCheckCustomDictionaryAPI flag steps when absent. Includes the secure-context gate.

  2. Domain-vocabulary editor

    A live editing surface full of legitimately unusual words plus a word manager driving the real API: add your vocabulary and (on supporting engines with spell check enabled) watch the false-positive squiggles disappear from the textarea — with squiggle state honestly labelled as a manual observation, since no API reads it back.

  3. SPA view-scoping ledger

    The explainer's sharpest design point: the interface is write-only, so a long-lived document must keep its own ledger. Switch between two mock app views and watch the page call removeWords(old) + addWords(new) for real while maintaining the ledger the API deliberately doesn't provide.

why it shipped

Users can add words to their personal browser dictionary — one word at a time, per user, per machine. Pages know their own vocabulary and could always suppress false positives better, but had no hook (short of spellcheck="false", which throws away real checking). The Igalia-led proposal keeps every guarantee conservative: additive only, ignored-not-learned semantics (transient, never persisted), no read-back of the user's dictionary (a fingerprinting surface), and document scoping with an explicit removeWords() so SPA vocabularies don't leak between views.

enabling it

In developer trial in Chrome 153 behind SpellCheckCustomDictionaryAPI (experimental in runtime_enabled_features.json5): launch with --enable-blink-features=SpellCheckCustomDictionaryAPI, or enable chrome://flags/#enable-experimental-web-platform-features. The interface is [SecureContext]. Seeing squiggles change also requires spell checking to be on in the browser and an editable field with focus.
