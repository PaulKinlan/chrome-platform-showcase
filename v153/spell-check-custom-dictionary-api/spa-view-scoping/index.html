SPA view-scoping ledger

The interface is deliberately write-only — no has(), no iteration (reading back would leak dictionary state). So a single-page app must keep its own ledger and retract each view's vocabulary on navigation, which is exactly why removeWords() exists. Switch views below: every switch makes the real removeWords(outgoing) + addWords(incoming) calls and updates the page-side ledger.

The dictionary surface is not exposed here — switches still run the same code path and log each call's genuine failure, and the ledger logic (the part the API leaves to you) works everywhere. Chrome 153+ with the SpellCheckCustomDictionaryAPI flag makes the calls real.

const ledger = new Set();                    // the read model is YOURS to keep

function switchView(nextWords) {
  const dict = document.spellCheckCustomDictionary;
  dict.removeWords([...ledger]);             // retract the outgoing view
  ledger.clear();
  dict.addWords(nextWords);                  // install the incoming view
  nextWords.forEach((w) => ledger.add(w));
}
// Without removeWords, every view's vocabulary would leak into the next —
// the SPA case the explainer calls out explicitly.
