Subdividing one buffer

The explainer's second use case: divide a single variable into multiple logical variables. The sliders pack a 16-byte header, an f32 position array, and a u32 index array into one storage buffer bound once as an unsized buffer. In the shader, bufferView<SectionHeader> reads the directory, bufferArrayView carves out two runtime-sized arrays (with arrayLength reflecting each carve's byte size), and bufferLength reports the whole binding — no 256-byte per-binding alignment, no copies.

Needs buffer_view in navigator.gpu.wgslLanguageFeatures. If missing: chrome://flags/#enable-unsafe-webgpu + relaunch, or --enable-unsafe-webgpu (headless: add --enable-features=Vulkan). The packing diagram and CPU reference always work; the GPU column reports honestly.

Note what the two bufferArrayView calls enforce: each carved array's arrayLength comes from the byte size passed at the call, so reading past a section into its neighbour is out of bounds for that view — the robustness argument the webgpu-samples wireframe port makes for preferring bufferArrayView over raw offsets.
