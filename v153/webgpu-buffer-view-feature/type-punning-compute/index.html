Type punning without copies

The explainer's first use case: reinterpret the bytes of one bound variable as several types. Enter four floats — they are written once into a single 16-byte storage buffer, then a compute shader reads those same bytes twice via bufferView<vec4f> and bufferView<vec4u> and writes back the raw bit patterns. The readback is compared bit-for-bit against a CPU DataView reference, so a wrong reinterpretation cannot pass silently.

Needs buffer_view in navigator.gpu.wgslLanguageFeatures. If missing: chrome://flags/#enable-unsafe-webgpu + relaunch, or --enable-unsafe-webgpu (headless: add --enable-features=Vulkan). The CPU reference column always works; the GPU column reports honestly.

the shader

Without buffer_view this needs either two bindings over the same GPUBuffer range (each padded to 256-byte storage alignment) or a bitcast per scalar after loading through a single declared type. The view built-ins reinterpret the memory itself, which also works for aggregates that bitcast cannot express. The shader additionally sums the float view and returns bufferLength(&src), both checked below the table.
