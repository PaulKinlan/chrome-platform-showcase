WGSL compile test bench

Six minimal WGSL programs exercise the exact surfaces buffer_view ships: the requires buffer_view; directive, the opaque buffer / buffer<N> type, and the bufferView, bufferArrayView, and bufferLength built-ins. Each compile is real — createShaderModule() on your GPU — and the page shows the raw getCompilationInfo() messages. Two programs are contract negatives that must fail even where the feature is supported.

On a browser without buffer_view every program below fails at line 1 with the real error feature 'buffer_view' is not supported — that is the honest expected result, not a demo bug. To get the success path pre-flip: chrome://flags/#enable-unsafe-webgpu + relaunch, or --enable-unsafe-webgpu (headless: add --enable-features=Vulkan).

what the messages mean

getCompilationInfo() resolves with a list of GPUCompilationMessage objects (type, line, column, text). A clean list on programs 1–4 proves the feature end-to-end; error messages on programs 5–6 prove the spec's safety contract — the buffer type is not constructible or assignable, and a bufferView<T> whose MinTypeSize(T) exceeds the declared buffer<N> size is a shader-creation error.
