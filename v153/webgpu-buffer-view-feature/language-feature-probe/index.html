Language feature probe

buffer_view is a WGSL language feature, not a device feature. This probe reads the real navigator.gpu.wgslLanguageFeatures set, then requests a real GPUAdapter so it can tell apart four honest outcomes: no WebGPU at all, WebGPU with no usable adapter, an adapter without buffer_view, and full support.

ChromeStatus lists this for Chrome 153. In current Tint source the feature is gated unsafe-experimental: if the verdict below says missing, enable chrome://flags/#enable-unsafe-webgpu and relaunch, or start Chrome with --enable-unsafe-webgpu (headless: add --enable-features=Vulkan so an adapter exists at all).     4 · adapter.features (GPUFeatureName set)

    Listed to prove the point: buffer_view is not a GPUFeatureName, so it never appears here — checking adapter.features for it is the wrong detection.

      the right detection

      if (navigator.gpu?.wgslLanguageFeatures.has('buffer_view')) {
  // safe to createShaderModule with `requires buffer_view;`
}

      This mirrors the detection the official webgpu-samples wireframe demo uses. wgslLanguageFeatures is available on navigator.gpu before any adapter is requested, so a page can decide which WGSL to ship without waiting on requestAdapter().
