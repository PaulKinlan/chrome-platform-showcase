v153 · Interop · Event loop

Interoperable dispatch timing for transitionrun and media query events

Two long-standing Blink timing quirks, aligned with the HTML event-loop spec (and with Gecko and WebKit): transitionrun now fires in the same rendering update that created the transition (step 3.11) instead of slipping a frame, and media query change events fire at step 3.10, deterministically before any pending animation events instead of intermixed with them. No new API — the demos here measure the actual timing your browser exhibits.

concepts

  1. transitionrun latency lab

    Start a real transition and count the requestAnimationFrame ticks that pass before transitionrun arrives — the whole change in one number. Old Blink: the event slips into a later iteration. Spec-aligned engines: it lands in the same rendering update, before the next frame's callbacks.

  2. MQ-vs-animation order

    A sandboxed iframe hosts a width-based media query and a transition; one button resizes the iframe and retriggers the transition in the same breath, and the inner document reports the exact order its change and transitionrun events arrived — step 3.10 before 3.11, or intermixed.

  3. Creation-context comparison

    The subtle half of the fix: transitions created "earlier in the same iteration". This lab creates one transition inside a plain task and one inside a requestAnimationFrame callback — the creation contexts the old delay treated differently — and compares their measured event latencies side by side.

why it shipped

Code that starts a transition and listens for transitionrun to kick off coordinated work (measurements, class swaps, analytics marks) behaved differently per engine: Blink delivered the event a frame late for same-iteration animations, so anything keyed on it lagged ~16ms behind Firefox and Safari — and media-query listeners could observe animation events before the change that logically caused the new state. Both fixes are pure spec alignment (event-loop processing model steps 3.10/3.11), shrinking real-world interop bugs rather than adding surface.
