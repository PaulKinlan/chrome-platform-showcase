Codec probe matrix

Every cell below is a real navigator.mediaCapabilities.decodingInfo() call for an IAMF codec string — the four substream codecs the spec's §6.4 grammar allows, at each of the three IA profiles — plus non-IAMF baseline rows so you can tell "this browser answers audio queries fine, and says no to IAMF" apart from "the probe surface is missing".

On stable Chrome today the whole IAMF block should honestly read not supported — decoding is anticipated to ship in Chrome 153 (the milestone this page tracks) but as of this build is still gated behind a build with ENABLE_IAMF_TOOLS plus --enable-features=IamfAudioDecoding (no chrome://flags entry exists). The baseline rows prove the negative is a real answer from a working decodingInfo(), not a broken probe.

code path

const info = await navigator.mediaCapabilities.decodingInfo({
  type: 'media-source',                       // MSE is where IAMF ships
  audio: {
    contentType: 'audio/mp4; codecs="iamf.000.000.Opus"',
    //                              ^ primary_profile . additional_profile . substream codec
    //                                000 Simple · 001 Base · 002 Base-Enhanced (IAMF §4)
    channels: '2', bitrate: 128000, samplerate: 48000,
  },
});
// info.supported / info.smooth / info.powerEfficient — per spec, an
// unsupported-but-valid configuration RESOLVES with supported:false.
