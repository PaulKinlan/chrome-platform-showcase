Single-capability toggle lab

What separates <camera>/<microphone> from <usermedia>: after the grant, each element becomes a browser-enforced toggle for its one track — a second click flips the track's enabled state, and the element keeps monitoring enabled/muted/ended so its UI can never lie about the hardware. This lab wires both elements to a live preview and level meter, and records every event and track transition in a ledger.

imperative comparison — NOT the element

Rehearse the same contract with getUserMedia()

This engine doesn't ship the elements, so this button runs the imperative flow the elements automate: getUserMedia({video:…}) / ({audio:…}), the same track wiring, the same enabled/muted/ended monitoring into the ledger, and a page-provided toggle standing in for the element's trusted one. Every outcome below is the real result of the calls on this device — including permission or no-hardware failures.

const cam = document.querySelector("camera");
cam.addEventListener("track", () => {              // single track, not a stream
  video.srcObject = new MediaStream([cam.track]);
  watch(cam.track);                                 // enabled / muted / ended
});
cam.addEventListener("error",  () => log(cam.error?.name));  // e.g. NotAllowedError
cam.addEventListener("cancel", () => log("prompt dismissed"));
// Second click on the element = browser-enforced toggle of cam.track.enabled.
// <usermedia> deliberately skips this: two tracks, one toggle = ambiguous.
