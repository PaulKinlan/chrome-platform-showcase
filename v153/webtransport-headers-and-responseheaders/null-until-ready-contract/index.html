null-until-ready contract

A detail with a lesson in it: responseHeaders reads null from construction until the session establishes, then becomes a Headers object — a value that changes across reads, which is why Chromium's IDL carries a comment noting the spec's [SameObject] label is wrong. The button runs the whole lifecycle for real against an unreachable endpoint (so the null phase is guaranteed observable) and cleans up.

2read responseHeaders IMMEDIATELY (pre-establishment)idle
3await outcome (ready would flip it to Headers; failure keeps it null)idle
4close() and final readidle
