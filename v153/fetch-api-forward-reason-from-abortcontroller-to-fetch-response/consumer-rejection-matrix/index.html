Consumer rejection matrix

A Response body can be consumed six ways, and the Fetch Standard says an abort must forward its reason to all of them. This tool runs one real chunked fetch per consumer — text(), json(), arrayBuffer(), blob(), bytes(), and a raw body.getReader().read() — aborts each mid-body with the reason kind you choose, and tabulates exactly what each rejection was.

A full run performs six real fetches to this site’s streaming route and deliberately cancels every one (six net::ERR_ABORTED DevTools entries). Rows run sequentially; a run takes roughly six seconds.

reading the matrix

With a custom reason, a spec-compliant browser (Firefox today, Chrome 153+) shows yes in the identity column for every row — one reason object, forwarded everywhere. Pre-153 Chromium shows no on every row with a generic AbortError substitute; the messages even differ by consumer ("The user aborted a request." for buffered consumers, "BodyStreamBuffer was aborted" for raw reads), which is exactly the inconsistency the spec text removes. With no argument, every branch correctly reports the minted AbortError DOMException — identity with a reason you never supplied is impossible, so that column is marked n/a.

the code

async function probe(consume) {
  const controller = new AbortController();
  const res = await fetch(STREAM_URL, { signal: controller.signal });
  const pending = consume(res);      // res.text(), res.blob(), reader.read()…
  await delay(400);                  // headers done, body still streaming
  controller.abort(reason);
  try { await pending; } catch (err) { return err; }
}
