Reason relay

One real fetch against a server route that streams its body slowly. Once the headers arrive — so the fetch promise has already resolved — the demo aborts with a marked custom reason and inspects exactly what response.text() rejects with. A spec-compliant browser (Chrome 153+, Firefox) relays your reason; older Chromium substitutes a generic AbortError.

Run the litmus

The abort reason is new DOMException("showcase-relay: deadline exceeded while reading the body", "TimeoutError") — its name and message are the markers the verdict looks for. The abort fires as soon as the first chunk has genuinely arrived, and the route holds all further chunks for 6 seconds — so the body read is provably still pending when the abort lands, no matter how the transport buffers.

code path

const controller = new AbortController();
// hold=6000: server sends chunk 1, then holds — the body stays pending
const response = await fetch('../slow-body?chunks=3&delay=100&hold=6000', { signal: controller.signal });
const probe = response.clone().body.getReader();
const pendingText = response.text();
await probe.read();          // chunk 1 confirmed — text() is provably mid-body
controller.abort(new DOMException('deadline exceeded while reading the body', 'TimeoutError'));
try { await pendingText; } catch (err) {
  // Chrome 153+ / Firefox: err IS your TimeoutError, message intact
  // Chromium <153:        err is a generic AbortError — the reason was dropped
}
