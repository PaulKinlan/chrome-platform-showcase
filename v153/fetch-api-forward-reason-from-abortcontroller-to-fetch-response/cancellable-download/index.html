Cancellable download

In real apps, the code that aborts (a cancel button, a route change, a timeout) and the code that consumes the body (a progress loop, a parser) live far apart. Forwarding the reason means the consumer’s catch block finally knows why it died. This demo streams a chunked response with live progress; cancel it or let a real AbortSignal.timeout() kill it, and watch the catch handler branch on the reason it actually received — including the honest pre-153 fallback via signal.reason.

how the catch handler branches

    
class UserCancel { constructor(bytes) { this.kind = "user-cancel"; this.bytes = bytes; } }

try {
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    received += value.byteLength;
  }
} catch (err) {
  if (err instanceof UserCancel) {                 // Chrome 153+: forwarded
    show(`You cancelled at ${err.bytes} bytes`);
  } else if (err instanceof DOMException && err.name === "TimeoutError") {
    show("Took too long — retry?");                // AbortSignal.timeout(), forwarded
  } else if (err instanceof DOMException && err.name === "AbortError") {
    // Pre-153 Chromium lands here for EVERY abort. The workaround:
    const why = controller.signal.reason;          // …if you still have the controller
    show("Aborted, generic reason; signal.reason says:", why);
  }
}
