Two-phase timeline

An abort can land in two different windows of a fetch's life: phase 1, before the headers arrive (the fetch promise itself rejects — reason forwarding here shipped years ago), and phase 2, after the headers but mid-body (the body-read promise rejects — forwarding here is what Chrome 153 fixes). This tool runs both against the same streaming route and shows, per phase, whether your reason survived.

Phase 1 · abort before the headers resolve the fetch promise

The abort fires synchronously, immediately after fetch() is called — the request never gets a response. The rejection surfaces on the fetch promise itself.

Phase 2 · abort after the headers, mid-body

The fetch promise has already resolved with a Response; response.text() is reading the streaming body when the abort fires. The rejection surfaces on the body-read promise.

code path

// Phase 1 — reason lands on the fetch promise (long-standing behavior)
const c1 = new AbortController();
const p1 = fetch(url, { signal: c1.signal });
c1.abort(new DOMException('phase-1 marker', 'TimeoutError'));
await p1;                    // rejects with YOUR reason in any modern browser

// Phase 2 — reason lands on the body read (fixed in Chrome 153)
const c2 = new AbortController();
const res = await fetch(url, { signal: c2.signal }); // headers in, promise resolved
const body = res.text();
c2.abort(new DOMException('phase-2 marker', 'TimeoutError'));
await body;                  // Chrome 153+/Firefox: YOUR reason · older Chromium: generic AbortError
