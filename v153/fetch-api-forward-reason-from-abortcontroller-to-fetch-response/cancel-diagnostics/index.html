Cancel diagnostics

The product case for reason forwarding: a download with a progress bar, a user cancel button, and a hard deadline from AbortSignal.timeout() — combined into one signal with AbortSignal.any(). The catch handler wants to tell the user why the download stopped. With forwarding, the rejection carries the cause; without it, user-cancel and timeout arrive as the same generic AbortError and the UI can only shrug.

Download with a deadline

class UserCancelledError extends Error {
  constructor() { super('You cancelled the download.'); this.name = 'UserCancelledError'; }
}
const user = new AbortController();
const signal = AbortSignal.any([user.signal, AbortSignal.timeout(deadlineMs)]);
const response = await fetch(url, { signal });
const reader = response.body.getReader();
try {
  for (;;) { const { done } = await reader.read(); if (done) break; /* progress */ }
} catch (err) {
  if (err instanceof UserCancelledError)  show('Cancelled — resume any time.');
  else if (err?.name === 'TimeoutError')  show('Too slow — deadline exceeded.');
  else if (err?.name === 'AbortError')    show('Stopped — but this browser dropped WHY.');
  else                                    show('Network failure: ' + err);
}
// cancel button: user.abort(new UserCancelledError())
