Zip basics

The smallest real call: hand Iterator.zip an iterable of iterables, get back an iterator of position-aligned tuples. Because the return value is an Iterator Helper, the zip drops straight into a helper chain — the advanced composition here pipes tuples through .map() without any glue code.

what makes it “the iterator zip”

Three things distinguish the standard from a quick arr1.map((v, i) => [v, arr2[i]]):

  • Any iterables, not just arrays — generators, Maps, Sets, and plain iterator objects all zip; try Input C empty vs filled to see arity change. (Primitives, including strings, are deliberately rejected — see the edge lab.)
  • Lazy — tuples are produced one next() at a time; nothing is materialised up front. The chained .map() proves the output is a real Iterator Helper, not an array.
  • A defined length policy — by default iteration stops with the shortest input and the longer ones are closed. The mode matrix covers the other two policies.
