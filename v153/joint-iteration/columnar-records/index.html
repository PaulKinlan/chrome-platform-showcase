Columnar records

APIs, CSV parsers, and analytics stores love column-oriented data — one array per field. UIs want rows. Iterator.zipKeyed is the missing converter: give it { name: […], year: […] } and it yields one record per row with the keys you named, no index arithmetic, no hand-rolled loop. This page builds a real table from live-edited columns and surfaces the two contract details that surprise people.

two contract details worth knowing

1. Records have a null prototype. Each yielded object is created with OrdinaryObjectCreate(null) — Object.getPrototypeOf(record) === null, so there is no inherited toString, no hasOwnProperty, and no prototype-pollution surface. The report line above checks the real prototype of the first record on every run. Use record.name or Object.entries(record); don’t call Object.prototype methods on it.

2. undefined-valued keys are skipped, not padded. An own enumerable property whose value is undefined is treated as “not there at all” — the key simply never appears in any record. Tick the checkbox above to watch the discovered column disappear rather than throw or fill with undefined.

const records = Iterator.zipKeyed({
  name: ["Ceres", "Pallas", "Juno", "Vesta"],
  discovered: [1801, 1802, 1804, 1807],
  diameter_km: [946, 512, 247],           // one short
}, { mode: "longest", padding: { diameter_km: "n/a" } });

records.toArray()
// [ { name: "Ceres",  discovered: 1801, diameter_km: 946 },
//   { name: "Pallas", discovered: 1802, diameter_km: 512 },
//   { name: "Juno",   discovered: 1804, diameter_km: 247 },
//   { name: "Vesta",  discovered: 1807, diameter_km: "n/a" } ]  // keyed padding
