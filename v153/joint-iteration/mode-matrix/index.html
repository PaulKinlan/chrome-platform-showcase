Mode matrix

One options bag decides what a length mismatch means. This tool runs the same unequal inputs through all three modes at once — shortest truncates, longest pads, strict throws — and spies on the options object to prove padding is only ever read when the mode is longest.

Probing this browser…

Three modes, one run

Blank = no padding option = pad with undefined.

mode: "shortest"

The default. Stop at the first exhausted input; close the others.

—

mode: "longest"

Keep going until every input is done; exhausted inputs yield their padding value.

—

mode: "strict"

Lengths must match exactly, or the mismatch round throws TypeError.

—

the options contract

Iterator.zip(inputs, { mode: "longest", padding: ["?", "rest"] })
// padding is an ITERABLE for zip — one value per input, by position.
// Too short → remaining inputs pad with undefined. Read eagerly, up front.

Iterator.zip(inputs, { mode: "anything-else" })   // TypeError
Iterator.zip(inputs, { mode: "longest", padding: 7 })  // TypeError — not an object
Iterator.zip(inputs, { mode: "shortest", padding: ... })  // padding never even read

That last line is observable: the spy above wraps the options object in a padding getter and reports whether the engine touched it. Per spec, Get(options, "padding") only happens when mode is "longest" — a detail that matters if your padding is computed lazily or has side effects.
