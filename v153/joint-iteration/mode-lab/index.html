Mode lab

The same mismatched inputs — [1,2,3], ['a','b'] — run under every length policy, so the three behaviors sit side by side: shortest truncates, longest pads (with the per-input padding vocabulary), and strict throws a real TypeError. Below that, the two argument-validation contracts the spec adds.

Longest-mode padding vocabulary

Padding is per-input: for zip it's an iterable aligned by position; omitted entries and omitted padding default to undefined. Non-object padding is a TypeError before any iteration starts.

Argument validation

Two contracts the spec pins before any zipping happens: an unknown mode string throws, and a primitive inside the iterable-of-iterables is rejected (reject-primitives in GetIteratorFlattenable — strings do NOT get silently iterated as characters).

Iterator.zip([[1,2,3],['a','b']]).toArray()                          // [[1,'a'],[2,'b']]
Iterator.zip([[1,2,3],['a','b']], {mode:'longest'}).toArray()        // […, [3, undefined]]
Iterator.zip([[1,2,3],['a','b']], {mode:'longest',
                                   padding:['?','∅']}).toArray()     // […, [3, '∅']]
Iterator.zip([[1,2,3],['a','b']], {mode:'strict'}).toArray()         // throws TypeError
Iterator.zip([[1],[2]], {mode:'zippy'})                              // throws TypeError
Iterator.zip([[1,2], 'ab'])                                          // throws TypeError (primitive)
