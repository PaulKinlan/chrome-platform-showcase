Edge cases & iterator closing

A joined iterator is a consumed iterator, and abrupt completions close it — return() is called, finally blocks run, resources get released. This lab executes each failure path against instrumented iterators (generator finally flags where iteration has started, a return() spy where it hasn’t), then reports the spec’s expectation next to what the running engine actually did.

the instrumentation gotcha that case 5 exists to teach

A finally block cannot observe every close. The spec runs ToString(separator) before the first next(), and if it throws, closes the iterator via IfAbruptCloseIterator — return() really is called (verified against the native implementation on V8 15.0.245, 2026-08-16). But if your instrument is a generator’s finally, you will see nothing: calling return() on a generator that has never started executing finishes it without entering the body, so no try was entered and no finally runs. Case 5 therefore spies on return() itself with a hand-rolled iterator object, while cases 3–4 — where iteration has already started — use the generator-finally instrument. Pick the right probe or you will misdiagnose the engine.

// WRONG probe for a pre-iteration close: unstarted generator, finally never entered
function* g() { try { yield 1; } finally { closed = true; } }  // stays false

// RIGHT probe: spy on return() directly
const it = {
  next() { return { value: 1, done: false }; },
  return() { returnCalled = true; return { done: true }; },   // ← observes IteratorClose
};
Iterator.prototype.join.call(it, { toString() { throw new RangeError("boom"); } });
