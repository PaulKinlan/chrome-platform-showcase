Iterator Join

Iterator.prototype.join(separator) concatenates an iterator's values into a string — exactly like Array.prototype.join, but on any iterator: generators, Sets, Map keys, helper chains. Until now you either paid for Array.from(it).join()'s full intermediate array or hand-rolled a reduce that allocates every intermediate string and throws on an empty iterator.

concepts

  1. Join anywhere — one editable separator, four different iterator sources (generator, Set, Map.keys(), helper chain), each joined with a real call and shown as-is.
  2. No array detour — the motivation, live: the two old workarounds run beside the new method, including the real TypeError an empty iterator throws at bare reduce — a pitfall that works (fails) in every browser today.
  3. Join semantics — the edge contract: the default comma, ToString of exotic separators, null/undefined elements becoming empty strings, one-shot exhaustion, and the non-object receiver TypeError.

why it shipped

Joining is one of the most common terminal operations on a sequence, and the iterator-helpers family (map, filter, take, toArray…) had no string-building terminal. The proposal (stage 3, with test262 tests) fills that gap with semantics deliberately identical to Array.prototype.join — including the comma default and the null/undefined-to-empty-string rule — so the mental model transfers unchanged. Chrome 153 ships it on %IteratorPrototype%, where every built-in iterator and helper chain inherits it.
