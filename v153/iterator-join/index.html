Iterator Join

Iterator.prototype.join(separator) concatenates whatever an iterator produces into a string — the missing sibling of Array.prototype.join() for the iterator-helpers world. No intermediate array, works on generators and any iterator chain (map, filter, take…), and keeps Array's stringification rules.

concepts

  1. Join playground

    Probe the exact surface (Iterator.prototype.join), then drive it live: type values and a separator, run the real call on a generator, and see the string it returns — or the genuine unsupported readout with the browser's actual error, never a shimmed result presented as native.

  2. Lazy pipeline join

    The reason it exists: join at the end of an iterator-helpers chain. An infinite generator flows through the real take() / map() / filter() helpers (shipped since Chrome 122) and terminates in .join() — with a live counter proving no intermediate array was built.

  3. Array-parity table

    The contract that makes it learnable in one sentence: same semantics as Array.prototype.join. The table runs both sides live for the tricky cases — undefined/null become empty strings, default separator is a comma, empty input gives "" — and flags any divergence for real.

why it shipped

Iterator helpers (Chrome 122) made lazy pipelines idiomatic — but ending a pipeline in a string still required [...iter].join() or iter.toArray().join(), materialising an array just to throw it away. join() completes the helper set as a proper consumer method, mirroring a pattern nearly every language with iterators has (Python's str.join, Rust's itertools::join).

enabling it

In developer trial in Chrome 153: enable chrome://flags/#enable-javascript-harmony or launch with --js-flags=--harmony-iterator-join (V8 staging flag), or --enable-experimental-web-platform-features. The demos probe the real prototype and never fake support.
