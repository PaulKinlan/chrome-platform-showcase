Iterator Join

Joining values into a string is trivial for arrays and clumsy for everything else: Array.from(map.keys()).join(", ") materialises the whole sequence just to concatenate it. The TC39 Iterator Join proposal (Stage 3) adds Iterator.prototype.join(separator), the missing terminal step for iterator-helper pipelines — same contract as Array.prototype.join, but streaming, with no intermediate array. These demos call the real method when your engine ships it and fall back to a clearly labelled spec-model when it doesn't.

concepts

  1. Pipeline join

    The canonical use: end a real .values().map().filter() helper pipeline with .join() instead of round-tripping through Array.from. Clean up a messy tag list live and compare the three historical workarounds.

  2. Separator semantics lab

    An inspection matrix over the coercion rules: default comma, empty separator, ToString on numbers and objects, Symbols throwing, and the undefined/null → empty-string rule — each cell run for real against the dataset you pick.

  3. Edge cases & iterator closing

    The failure contract: non-object receivers, Symbol separators and elements, what actually closes the underlying iterator (observed with generator finally flags and a return() spy — they see different things), and the fact that join consumes its receiver.

why it shipped

The proposal’s motivation is code that is everywhere on GitHub: Array.from(thing.keys()).join(...) and friends. Without join, an iterator pipeline has two bad endings — Iterator.from(it).reduce((a, b) => a + sep + b) allocates every intermediate string and breaks on empty iterators, while Array.from(it).join(sep) converts the whole sequence to an array first. Iterator.prototype.join gives helper chains the same one-call ending arrays have had since ES3. It reached Stage 3 with test262 coverage, and V8 ships it on by default (js_iterator_join) in the engine Chrome 153 carries.

the shape

Iterator.prototype.join(separator)  // -> string; length 1

[..."hello"].values().join()          // "h,e,l,l,o"  (undefined separator -> ",")
map.keys().join(" / ")               // streaming — no intermediate array
[1, undefined, null, 2].values().join("|")  // "1|||2" — like Array.prototype.join

Exact contract, verified against the real V8 implementation: the receiver must be an object (else TypeError); ToString(separator) runs before iteration starts; undefined and null elements contribute the empty string but still get separators; Symbol separators or elements throw TypeError; and the method consumes its receiver.

running it today

This is a pure V8 language feature — there is no chrome://flags entry and no Blink runtime flag, because it lives in v8/src/flags/flag-definitions.h as js_iterator_join, already in the shipped set for the V8 in Chrome 153. In Chrome 152 and earlier the V8 snapshot may simply not contain the implementation: Chromium 141 ignores --js-flags=--js-iterator-join entirely (verified 2026-08-16). Outside the browser, deno run --v8-flags=--js-iterator-join runs the real implementation today (verified on Deno 2.9.5 / V8 15.0). Every demo probes typeof Iterator.prototype.join first and labels each result native or spec-model.
