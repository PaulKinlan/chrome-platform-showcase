Lazy pipeline join

An infinite prime generator flows through the real iterator helpers — filter(), map(), take(n) — and terminates in .join(). The pull counter is incremented inside the generator itself, so it proves how many values were actually produced: exactly n, no over-pull, no intermediate array.

Iterator.prototype.join is missing here — the pipeline below still runs the shipped helpers (filter/map/take) for real and then shows the genuine error from the final .join() step. Chrome 153+ with chrome://flags/#enable-javascript-harmony completes the chain.

function* integers() { for (let n = 2; ; n++) yield n; }   // infinite!

integers()
  .filter(isPrime)          // real Iterator.prototype.filter (Chrome 122+)
  .map((p) => `p${p}`)      // real Iterator.prototype.map
  .take(8)                  // real Iterator.prototype.take
  .join(" → ");             // NEW: consumes lazily, builds only the string
// → "p2 → p3 → p5 → p7 → p11 → p13 → p17 → p19"
