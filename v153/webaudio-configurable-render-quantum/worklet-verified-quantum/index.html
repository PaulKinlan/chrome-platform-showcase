Worklet-Verified Quantum

One value, four witnesses. For each renderSizeHint this page creates a real AudioContext, reads the main thread's renderQuantumSize, then loads an AudioWorkletProcessor that reports what the render thread actually sees: the AudioWorkletGlobalScope.renderQuantumSize global, the outputs[0][0].length block it is handed, and the steady-state currentFrame delta between consecutive process() calls. If the four numbers agree, the granted quantum is real — not just an attribute.

Each probe opens its own AudioContext, resumes it, runs the worklet for six callbacks (the first currentFrame delta is discarded — a node can join the graph mid-burst, so only the steady-state delta is trustworthy), then closes the context. "granted ≠ requested" is not a bug — the hint is a hint; the verdict only fails when the four observations disagree with each other, or when the worklet-side feature is missing.

what this proves

The Chrome 153 launch has two halves: the option (renderSizeHint) and the observability (BaseAudioContext.renderQuantumSize on the main thread, renderQuantumSize in the AudioWorkletGlobalScope, and process() receiving blocks of exactly that many frames). A browser could expose the attribute but keep rendering at 128 — this page catches that honestly, because the worklet's currentFrame delta cannot lie about the block size the render thread is really using.
