v153 · responsively-sized iframe

Double opt-in sizing lab

Responsive iframe sizing only activates when both documents agree: the embedder sets frame-sizing: content-height on the <iframe>, and the embedded document declares <meta name="responsive-embedded-sizing"> in its <head>. Below, four live same-origin iframes each hold a child document with exactly 420px of content. A ResizeObserver reports every frame's real box live — only the fully opted-in pair may grow past the 150px default.

1 — both sides opt in

iframe { frame-sizing: content-height }
<meta name="responsive-embedded-sizing"
      allowedorigins="'self'">
…

Expected with the feature: grows to ≈420px, no inner scrollbar. Without it: stays 150px.

2 — embedder only

iframe { frame-sizing: content-height }
(child has NO meta tag)
…

Expected always: stays 150px — the child never granted size exposure.

3 — child only

iframe { /* no frame-sizing */ }
<meta name="responsive-embedded-sizing"
      allowedorigins="'self'">
…

Expected always: stays 150px — frame-sizing's initial value auto ignores the child's size.

4 — opt-in restricted to another origin

iframe { frame-sizing: content-height }
<meta name="responsive-embedded-sizing"
      allowedorigins="https://example.com">
…

Expected always here: stays 150px — this page's origin is not in the child's allowedorigins list (Chromium matches it with CSP frame-ancestors syntax).

what the probe checks

The support probe asks CSS.supports("frame-sizing", "content-height") — the exact property and keyword from CSS Sizing 4 §5.3. The behavioural verdict then checks the measured boxes: case 1 must exceed 160px while cases 2–4 stay at the 150px default. A parser that accepts the keyword but never grows case 1 is reported as a mismatch, not a pass.
