Seamless embeds without the resize script

The canonical use case from the explainer: a third-party comment widget. The left article uses the 2015-era workaround — a fixed iframe plus a postMessage script that reports the widget's height late, after script and (simulated 600ms) network delay, jolting the content below it. The right article just declares frame-sizing: content-height and lets the engine size the frame from the child's natural 384px height at load, before the resize script would even have run. Both columns are measured live: settle time, final height, and any layout-shift performance entries this page accumulates.

reading the numbers honestly

Responsive sizing is one-shot at child load, so the frame still transitions 150px → 384px once — but it happens as part of the load-time layout the engine already performs, not ~600ms later from script. If this browser lacks frame-sizing, the right column keeps the 150px default with an internal scrollbar, and the table will show that: the legacy column then wins on final height, which is exactly why the workaround scripts exist today. Reserving the space up front (e.g. min-height or aspect-ratio on the iframe) remains the way to avoid even the one-shot shift.
