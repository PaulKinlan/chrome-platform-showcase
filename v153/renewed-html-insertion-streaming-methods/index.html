Renewed HTML insertion&streaming methods

A coherent family of HTML-setting methods replaces today's disjointed mix of innerHTML, insertAdjacentHTML, createContextualFragment and friends: positional one-shot methods (appendHTML, prependHTML, beforeHTML, afterHTML, replaceWithHTML), streaming variants that return a WritableStream (streamHTML, streamAppendHTML, …), a runScripts option on the unsafe setters, and trusted-types integration via createHTMLParserOptions — all sharing the same safe/unsafe split and sanitizer options.

concepts

  1. Positional one-shot methods

    Probe and call the ten new positional setters — appendHTML/prependHTML/beforeHTML/afterHTML/replaceWithHTML and their Unsafe twins — against a live stage, with the exact legacy insertAdjacentHTML mapping each one replaces.

  2. Streaming into a WritableStream

    Call streamHTML/streamAppendHTML/streamPrependHTML, write chunked markup — including tags split across chunk boundaries — through the returned WritableStream, or pipe a whole ReadableStream into it.

  3. The runScripts option

    Run the same script-bearing markup through setHTMLUnsafe (inert by default), setHTMLUnsafe(html, {runScripts: true}), and today's only script-running inserter, createContextualFragment, and compare which markers actually execute.

  4. Trusted types parser options

    Probe TrustedTypePolicy.createHTMLParserOptions, bless a sanitizer-carrying options dictionary when supported, and contrast it with today's string-transforming createHTML flow that can't participate in streaming or the sanitizer.

why it shipped

Updating HTML dynamically from script currently spans several disjointed APIs, each with subtly different behaviour for insertion point, sanitization, script execution, and trusted types — a recipe for confusion and injection bugs. The renewed method family exposes every permutation (position × one-shot/stream × safe/unsafe) as an explicit, consistently-named method with shared sanitizer/runScripts options and first-class trusted-types support, effectively superseding insertAdjacentHTML and the script-running quirk of createContextualFragment.

flag status

Chrome 153 targets this behind the experimental Blink runtime feature NewHTMLSettingMethods (depends on SetHTMLCanRunScripts, StreamingSanitizer, TrustedTypesCreateParserOptions). To try it: in Chrome/Canary 153+ enable chrome://flags/#enable-experimental-web-platform-features and relaunch, or launch with --enable-blink-features=NewHTMLSettingMethods,SetHTMLCanRunScripts,TrustedTypesCreateParserOptions. Every demo below degrades honestly and labels exactly what is missing when the methods are absent.
