Trusted types parser options

Trusted types today transform HTML strings (createHTML) — which cannot stream and cannot cooperate with the Sanitizer. The renewed API lets a policy bless a whole parser options dictionary via createHTMLParserOptions(), so a policy can inject a sanitizer, flip runScripts, and still work with streaming setters. (ChromeStatus summarises this as "createParserOptions in trusted types".)

Flag required in Chrome 153. Blink runtime feature TrustedTypesCreateParserOptions (experimental; part of NewHTMLSettingMethods). Enable chrome://flags/#enable-experimental-web-platform-features in Chrome/Canary 153+ and relaunch, or launch with --enable-blink-features=NewHTMLSettingMethods,SetHTMLCanRunScripts,TrustedTypesCreateParserOptions. Without it, this page still demonstrates — for real — the string-only limitation the new API fixes.

code

// today: the policy can only rewrite a string — no sanitizer, no streaming
const policy = trustedTypes.createPolicy('demo', { createHTML: (s) => s });
el.setHTMLUnsafe(policy.createHTML(hostile));       // onerror= attribute survives!

// renewed API: the policy blesses the *options*, so a sanitizer rides along
const opts = policy.createHTMLParserOptions({
  sanitizer: { removeAttributes: [{ name: 'onerror' }] },
  runScripts: false,
});
el.setHTMLUnsafe(hostile, opts);                    // sanitizer strips onerror
readable.pipeTo(el.streamHTMLUnsafe(opts));         // …and it streams, too
