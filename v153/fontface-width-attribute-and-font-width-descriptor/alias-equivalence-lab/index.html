Alias equivalence lab

Renames only work if both names are truly one thing. This lab checks the equivalences live: the nine width keywords and the percentages the engine computes for them, the font-width ↔ font-stretch property aliasing in both directions, and — the part that bites real projects — whether a font-width descriptor participates in face selection the same way the legacy spelling does, proven with a narrow and a wide face you can measure.

Face selection through the width descriptor

Two faces of one family are registered from real font data — a narrow instance (0.5× advances) covering 50%–99% and a wide instance (2× advances) covering 100%–200%. Each @font-face rule is written with both descriptor spellings; the readout shows which spelling this browser’s parser kept. If selection honours the ranges, the 75% sample must measure roughly a quarter of the 150% sample.

the code

@font-face {
  font-family: "WSel";
  src: url(narrow.ttf);
  font-stretch: 50% 99%;   /* legacy spelling — parsed everywhere      */
  font-width: 50% 99%;     /* CSS Fonts 4 spelling — Chrome 153+       */
}
/* …second face covers 100% 200% with 2× advances… */

.sample-a { font-stretch: 75%; }   /* must select the narrow face  */
.sample-b { font-stretch: 150%; }  /* must select the wide face    */
