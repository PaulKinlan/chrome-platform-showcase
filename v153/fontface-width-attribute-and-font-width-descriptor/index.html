FontFace width attribute and font-width descriptor

CSS Fonts 4 renamed font-stretch to font-width — the property was never about stretching glyphs, it selects a face’s width (or drives a variable font’s wdth axis). Chrome 153 ships the loading-API half of that rename: FontFace.width (with stretch kept as a binding alias for the same attribute), a width member in the FontFace constructor’s descriptor dictionary, and the font-width descriptor inside @font-face. These demos probe each new surface exactly, and drive a real variable-width font you can measure.

concepts

  1. Descriptor & attribute probe

    Falsifiable checks of each exact new surface: "width" in FontFace.prototype, the constructor’s width dictionary member, the width↔stretch alias binding, @font-face { font-width: … } parse-and-read-back, and — separately — the font-width property question.

  2. Variable width stage

    A slider drives a real wdth-axis variable font (built with fontTools for this demo) from 50% to 200% via font-width when supported, font-stretch otherwise — with measured advance widths and a low-level font-variation-settings comparison row.

  3. Alias equivalence lab

    The migration story, evaluated live: keyword→percentage mapping (ultra-condensed…ultra-expanded), property aliasing in both directions, FontFace attribute aliasing, and width-descriptor face selection between a narrow and a wide face.

why it shipped

CSS Font Loading and CSS Fonts 4 define width as the primary FontFace attribute and font-width as the primary @font-face descriptor, keeping stretch/font-stretch as legacy aliases. Chromium previously ignored the width constructor member and the font-width descriptor entirely, which failed Web Platform Tests and meant code written against the current spec silently lost its width configuration. Chrome 153 aligns the implementation: width and stretch read and write the same underlying descriptor, in either syntax.

the shape

/* CSS — new descriptor name, old one still works */
@font-face {
  font-family: "Inter Var";
  src: url(inter.woff2);
  font-width: 75% 125%;   /* Chrome 153+; alias of font-stretch */
}

// JS — new attribute + constructor member
const face = new FontFace("Inter Var", "url(inter.woff2)", { width: "75% 125%" });
face.width;    // "75% 125%"
face.stretch;  // "75% 125%" — same attribute, binding alias
face.width = "condensed";   // updates .stretch too: one value, two names

running it today

There is no flag for this one — no matching entry exists in runtime_enabled_features.json5, so it cannot be pre-enabled in Chrome ≤152; it simply ships with 153. Everything here feature-detects at runtime: on an older browser the probes report each missing surface honestly, and the stage falls back to the long-shipped font-stretch alias (labelled), which drives the same wdth axis.
