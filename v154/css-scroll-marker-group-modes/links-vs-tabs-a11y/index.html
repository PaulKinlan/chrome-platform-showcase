v154 · scroll-marker-group modes

Links mode vs tabs mode, by hand

The two mode keywords are shorthand for two well-worn ARIA patterns. Below, both patterns are built the long way — real HTML, real keyboard handling — so you can feel the focus-order difference in any browser today. This is the semantic target the CSS maps to, not ::scroll-marker output: what you keyboard through here is what Chrome 154 will hand you for free from one declaration.

Try this: click "Park focus before the markers" in each half, then press Tab repeatedly. The links half costs one stop per marker on the way through. The tabs half costs exactly one — arrow keys (← →, Home, End) move within the strip, and Tab drops you straight into the open panel. The focus journal at the bottom records every stop.

The same widget, two semantics

links · the default

navigation landmark + anchor links — every marker a sequential tab stop

::scroll-marker-group → role: navigation
::scroll-marker       → role: link
originating element   → (unchanged)
1 2 3

Chapter one

Activating a link scrolls this pane and moves the sequential focus starting point here — press Tab after clicking and you continue from the chapter, not the link strip. That is links-mode activation, and it is native anchor behavior.

Chapter two

All three links above stay in the tab order all the time. A screen reader announces the strip as a navigation landmark containing three links.

Chapter three

Nothing about these chapters changes role — links mode leaves the content's own semantics alone.

tabs

WAI-ARIA tablist — one tab stop, roving tabindex, arrow keys

::scroll-marker-group → role: tablist
::scroll-marker       → role: tab
originating element   → role: tabpanel

Slide one

Activating a tab keeps focus on the tab — that is tabs-mode activation. Press Tab from the strip and you land in this panel; the other panels are hidden entirely, the way 154 prunes inactive panels from the accessibility tree.

Slide two

Only the selected tab has tabindex="0"; the others sit at -1. Arrow keys move the 0 around — the roving tabindex the spec's focusgroup gives you natively.

Slide three

Home and End jump to the first and last tab. Twenty carousel dots cost a links user twenty stops — a tabs user still pays one.

One divergence to know about: the spec activates a tab on arrow-key focus as well as on click — automatic activation, in APG terms — and this reference implementation does the same. And where the APG pattern needs the script above to hide inactive panels, 154's tabs mode does the pruning itself.
