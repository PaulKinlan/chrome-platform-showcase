A tabbed interface on tabs mode

A settings panel is the canonical tabs use case: few panels, focusable content inside each, and screen-reader users who expect the WAI-ARIA tabs contract. Here the whole thing is a scroll container — each panel's ::scroll-marker is its tab, and scroll-marker-group: before tabs asks the browser for tablist semantics with no ARIA attribute anywhere in the markup.

Focus trace — try Tab and the arrow keys

Nothing focused inside the panel yet. Click into the settings area, then press Tab and the arrow keys.

The trace reports real focusin events. A focused ::scroll-marker is a pseudo-element, so the DOM reports its scroll container as the active element — the trace labels that case rather than pretending the page can see the marker itself.

/* The entire tab machinery. No role attributes, no script. */
.settings {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-marker-group: before tabs;   /* <- the new part: tabs mode */
}
.panel { flex: 0 0 100%; scroll-snap-align: start; }
.panel::scroll-marker { content: attr(data-tab); }
.panel::scroll-marker:target-current { background: white; }
