Gamut, clipping, and the transfer function

color(display-p3-linear 1 0 0) names the most saturated red a P3 panel can make — a color that does not exist inside sRGB. Whether you can see the difference is a hardware question, and CSS can answer it honestly: the color-gamut media feature reports what your display covers, and the transfer function is the only math between the new space and the one that shipped in 2023.

display-p3-linear ships in Chrome 144 — on this page only the third red patch depends on it, and it labels itself unsupported on older builds instead of rendering a fake. Everything else here (the media query, the display-p3 patches, the converter) runs on any current Chrome.

These are live matchMedia() states, re-evaluated automatically if you drag the window to another monitor:

    The computed values are the browser's own getComputedStyle() serializations — note that the P3 declarations are kept in their own space, not converted to sRGB at computed-value time. Any clipping or gamut-mapping happens later, at paint, against your actual display. That is why the same stylesheet is richer on a P3 panel with no code changes.

    The converter: display-p3 ⇄ display-p3-linear

    Per §10.5, the two spaces share primaries and white point; only the transfer function differs — display-p3 uses the sRGB curve, display-p3-linear uses none. Edit either side and the other follows. This arithmetic is page JavaScript, shown for education — it is the spec's math, not browser output.

    display-p3 (gamma-encoded)
    display-p3-linear (linear-light) 
    gamma → linear:  c_lin = c ≤ 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ^ 2.4
linear → gamma:  c     = c_lin ≤ 0.0031308 ? 12.92 · c_lin : 1.055 · c_lin ^ (1/2.4) − 0.055
