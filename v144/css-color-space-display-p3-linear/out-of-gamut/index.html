Off the edge of the gamut

In color(), values below 0 and above 1 are not errors — the spec keeps them, unclamped, for later gamut mapping. Push these sliders out of range and read back exactly what the browser stores, in the new linear space and — as the shipped control — in plain display-p3.

The display-p3 row uses the same numbers as gamma-encoded components — a different color, but the identical contract: this browser already ships that space, so you can watch out-of-range preservation work today even where the linear space is missing. A row that says "unsupported" is the parser dropping the declaration, not this page guessing.

why the linear space needs more bits

CSS Color 4's serialization table asks for 10 bits of precision for display-p3 but 12 for display-p3-linear. Gamma encoding spends its resolution where eyes are sensitive — dark tones. A linear encoding spends it evenly, so near black it has far fewer usable steps; without the extra bits, gradients band. Same gamut, different bookkeeping.

/* Spec §13: an out-of-gamut color and its in-gamut clip. */
color(display-p3 0.3265 0.9165 -0.1262)       /* out of gamut     */
color(display-p3-linear 0.0871 0.8205 -0.0146) /* same, linear     */
color(display-p3-linear 0.0871 0.8205 0)       /* clipped to gamut */
