Display P3, with the gamma taken back out

Every predefined RGB color space in CSS stores its channels gamma-encoded — good for perception, wrong for physics. Chrome 144 adds display-p3-linear to color(): the same wide Display P3 primaries, but linear in light intensity, so doubling a channel doubles the photons. That is the space you want for physically based rendering, light mixing, and the HDR work this keyword is paving the way for.

concepts

  1. The predefined-space matrix

    All ten predefined spaces in CSS Color 4, probed one by one with CSS.supports(), then round-tripped through getComputedStyle() to show exactly how each one serializes. Where display-p3-linear lands in your browser is the first row worth reading.

  2. Linear vs gamma interpolation

    Why a linear-light space exists at all: mix two colors in srgb and the midpoint goes muddy; mix them in srgb-linear and it behaves like light. Live gradients and color-mix() readouts prove it today, and the display-p3-linear pair lights up when your browser has it.

  3. Gamut, clipping, and the transfer function

    What your display can actually show — a live @media (color-gamut) readout — plus out-of-gamut behavior for P3 primaries against sRGB red, and a working converter between display-p3 and display-p3-linear coordinates with the transfer-function math on the table.

why it shipped

The spec's definition is one sentence: display-p3-linear is the same as display-p3 except that the transfer function is linear-light — no gamma encoding. Red, green and blue chromaticities, the D65 white point, the gamut: all identical. Only the meaning of the numbers changes. In display-p3, 0.5 is "half as bright as it looks"; in display-p3-linear, 0.5 is half the light.

CSS already had this arrangement once — srgb and srgb-linear — and Chromium's stated motivation for the P3 version is physically based rendering and high dynamic range, with a planned follow-up adding it to PredefinedColorSpace so canvas can draw in it too. Linear-light spaces are also where physical light mixing belongs: CSS Color 4 §13.2 names display-p3-linear, alongside srgb-linear and CIE XYZ, as the interpolation spaces that are linear in light intensity.

One practical wrinkle the spec calls out: because linear encoding spends its precision differently, display-p3-linear needs at least 12 bits per component to round-trip without banding, where gamma-encoded display-p3 gets away with 10.

the API shape

/* One more keyword in color()'s predefined-rgb set */
color: color(display-p3-linear 0.3081 0.014 0.0567);
/* …which is the same color as (spec §10.5's own example): */
color: color(display-p3 0.591 0.123 0.264);

/* And one more rectangular interpolation space */
background: linear-gradient(in display-p3-linear, red, lime);
color: color-mix(in display-p3-linear, red, lime);

enabling it now

This ships in Chrome 144 (desktop, Android and WebView together), enabled for all users — no origin trial, no chrome://flags entry. The Blink runtime feature is ColorSpaceDisplayP3Linear, landed with status stable, so any build that contains the implementation has it on by default. The flip side: builds before 144 do not carry the code at all, so no flag can switch it on there — the honest fix is Chrome or Chromium 144+ (Canary today). These pages were built and verified on Chromium 141, where every display-p3-linear probe genuinely reports unsupported; each demo says so on screen and keeps its srgb-linear and display-p3 halves fully live, because both of those have been in Chromium for years.
