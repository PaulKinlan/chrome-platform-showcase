CSS color space display-p3-linear

Every display-p3 color has a hidden twin: the physically linear light values behind the gamma curve. Chrome 144 lets you write those values directly — color(display-p3-linear r g b) — the same wide P3 gamut, but with numbers proportional to actual light intensity, which is what you want when you are mixing light rather than picking paint.

concepts

  1. The linear swatchboard

    Three sliders, one color() function. Drive the linear-light components directly, watch the browser resolve them — or, on a browser without the space, watch the declaration get dropped and see exactly what an honest fallback looks like.

  2. The gamma decoder

    The whole feature is one transfer function. Decode any display-p3 color into its linear twin channel by channel, check the spec's own worked pair, and — where the browser can — prove the two notations resolve to the same color using relative color syntax.

  3. Mixing light, not ink

    Interpolate the same two colors in four spaces at once — gradients and color-mix() side by side. Gamma-space mixing muddies the midpoint; linear-light mixing behaves like two lamps in a room. srgb-linear already ships, so the comparison runs even where display-p3-linear does not.

  4. Off the edge of the gamut

    Push components past 0 and 1 and read back what the browser actually stores. color() keeps out-of-range values unclamped — the spec's own gamut-mapping examples, live, with the linear space's higher-precision requirement explained.

why it shipped

CSS already had srgb-linear, the linear-light twin of sRGB. It did not have the linear twin of display-p3, which left a hole: anyone doing physically based color math on a wide-gamut display had to convert into sRGB-linear or XYZ and lose the natural fit to the P3 primaries. display-p3-linear closes that hole — identical primaries and white point to display-p3, but with a unity transfer function, so component values are proportional to emitted light.

The stated motivation on the ChromeStatus entry is physically based rendering and high dynamic range, and the next step is already named there: the same keyword is planned for canvas's PredefinedColorSpace, so a page will be able to draw into a linear-light P3 buffer. One practical warning travels with it: because the linear encoding spends its precision differently, the spec requires more bits — 12 rather than display-p3's 10 — to avoid banding.

the API shape

/* Same P3 primaries, D65 white point — but linear-light components. */
color: color(display-p3-linear 0.3081 0.014 0.0567);
/* ...is exactly the same color as (spec §10.5 example): */
color: color(display-p3 0.591 0.123 0.264);

/* And it is an interpolation space (spec §13.2): */
background: linear-gradient(in display-p3-linear, red, green);
color: color-mix(in display-p3-linear, red 50%, green);
