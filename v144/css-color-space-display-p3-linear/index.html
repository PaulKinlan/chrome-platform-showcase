CSS color space display-p3-linear

Chrome 144 adds display-p3-linear to the predefined color spaces usable in the color() function: the same wide-gamut Display P3 primaries and D65 white point as display-p3, but with a linear-light transfer function — no gamma encoding. Component values are proportional to light energy, which is what you want for physically-correct math: blending, interpolation, and interop with linear-light pipelines in WebGPU and canvas.

concepts

  1. Linear-Light Swatches

    The canonical surprise: color(display-p3-linear 0.5 0.5 0.5) is not mid grey. Drive r/g/b sliders and compare the same numbers rendered in display-p3 and display-p3-linear, with the browser's own computed-style serialization as the readout.

  2. Transfer Curve Converter

    An inspection tool for the transfer function. Slide a linear-light value, watch the encoded equivalent move along the curve, and — on Chrome 144+ — cross-check the JS math against the browser's own relative-color-syntax conversion.

  3. Gradient Midpoints

    Why linear-light exists: interpolation. Probe whether gradients and color-mix() accept display-p3-linear as an interpolation space, and compare midpoint brightness against gamma-encoded interpolation on live gradient bars.

  4. Gamut Edges & Fallback

    The edge cases: out-of-range components like 1.25, none channels, relative-color-syntax conversion from sRGB with a matrix-math cross-check, and an honest @supports fallback pattern for browsers before Chrome 144.

why it shipped

CSS already had srgb-linear for linear-light math in the sRGB gamut, but no linear-light space covering the wide Display P3 gamut that modern screens actually have. Adding display-p3-linear completes the pair: authors can now do physically-meaningful color math (energy-proportional blending, correct midpoints, HDR-adjacent pipelines) without leaving the P3 gamut, and hand values straight to linear-light rendering targets like WebGPU canvases.
