HDR ramp: standard vs extended

Two float16 canvases receive identical drawing calls: a brightness ramp from black up to several times SDR white (color(srgb-linear 4 4 4) is four times as bright as white), plus a "sun" at the peak value. The top canvas asks for toneMapping: {mode: "standard"} and the bottom one for {mode: "extended"}. Both bitmaps hold the same values above 1.0, and the readback below proves it. The mode only decides whether the display may show them brighter than white.

Creating both contexts…

What you see depends on your screen. On an SDR display, both canvases look identical in every browser, because there is no headroom to use. On an HDR display with a browser where the echo says "extended", the right-hand part of the bottom ramp and its sun glow brighter than the page's white. This page cannot measure that physically, so the visual difference is a manual observation. The attribute echo and pixel readback are real measurements.

Readback: what is stored in the extended canvas

getImageData(x, 40, 1, 1, {pixelFormat: "rgba-float16"}) returns the stored values. A value above 1.0 is brighter than SDR white. The 8-bit getImageData() of the same pixel shows what any SDR export gets: everything above 1.0 clips to 255.

the dynamic-range-limit interaction

The explainer says a canvas with "extended" under dynamic-range-limit: standard must look exactly like a "standard" canvas, because extended tone mapping is just a clamp to whatever headroom is available. constrained allows some headroom, and no-limit allows all of it. Use the select to try each value: on an HDR screen, the bottom canvas should step down to match the top one.
