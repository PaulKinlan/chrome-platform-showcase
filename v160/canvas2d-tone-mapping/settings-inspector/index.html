Settings inspector

Pick a colorSpace, colorType and toneMapping, and the page creates a fresh canvas with canvas.getContext('2d', settings). It then compares what you asked for with what ctx.getContextAttributes() reports back. That echo is the only honest support signal. A browser without the feature still accepts the dictionary and validates the enum, then silently reports {mode: "standard"}.

reading the results

    
    
      
  • honoured: the echo matches the request. This is the only state that shows the feature is live.
    • 
      
  • ignored: you asked for "extended" and the echo says "standard". Chrome builds before the feature had toneMapping in the IDL dictionary but did not store it, so the echo is always the default. This page treats that as unsupported. It is the "ignored dictionary member" trap.
    • 
      
  • TypeError, or nothing: "reinhard" is listed under the explainer's future directions but is not yet in CanvasToneMappingMode. A build that reads the member rejects it with a TypeError, while a build that never reads it lets it through silently. Neither result is evidence of support: Chrome 153 throws with --enable-experimental-web-platform-features and ignores the value without it, yet in both cases it still reports "standard" for "extended". Some colorSpace values (rec2100-*, *-linear) sit behind their own flags and throw a TypeError when those flags are off.
    • 
      
  • unorm8 + extended is legal, but 8-bit values cannot exceed 1.0, so there is nothing above SDR white to show. Extended range needs float16 (or an HDR colorSpace such as rec2100-pq).
    • 
      
  • Calling getContext() a second time returns the same context and ignores the new settings, so tone mapping is fixed when the context is created.
