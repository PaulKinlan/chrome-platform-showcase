Canvas2D tone mapping

A float16 2D canvas can already store values brighter than SDR white, but every browser displays it clamped to the standard dynamic range. This feature adds toneMapping: {mode: "standard" | "extended"} to CanvasRenderingContext2DSettings. With "extended", the canvas may use the display's HDR headroom, and "standard" keeps today's behaviour. The dictionary is the same CanvasToneMapping that WebGPU already uses, now moved into HTML, so 2D canvas, WebGL and WebGPU share one way to control HDR output.

Behind a flag in builds where it is not yet on by default. The runtime feature is CanvasToneMapping (status experimental in runtime_enabled_features.json5, crbug.com/448552449). To try it: open chrome://flags/#enable-experimental-web-platform-features, set it to Enabled and relaunch, or start Chrome with --enable-blink-features=CanvasToneMapping (or --enable-experimental-web-platform-features). There is no dedicated chrome://flags entry for this feature. Seeing the visual effect also needs an HDR-capable display. A page cannot measure that, so the demos treat the visual difference as a manual observation, while the attribute echo and pixel values are real measurements.

Probing…

concepts

  1. HDR ramp: standard vs extended

    The basic, canonical use. Two float16 canvases draw the same ramp from black to 8× SDR white plus an HDR "sun", one requesting each mode. The page reads back the stored values, which go above 1.0 in both canvases, alongside the 8-bit view that clips to 255. A CSS dynamic-range-limit switch shows the documented interaction: "extended" under standard should look the same as "standard".

  2. Settings inspector

    An inspection tool that also covers the edge cases. Build any colorSpace × colorType × toneMapping request on an HTMLCanvasElement or OffscreenCanvas, and see what was requested next to what getContextAttributes() reports. It labels four outcomes: honoured, ignored (the member is accepted but reported as "standard"), a TypeError for a future mode such as "reinhard", and the second-getContext() trap. A one-click matrix covers all 14 colour-space and pixel-format combinations.

  3. HDR highlight painter

    A practical product use. Paint specular highlights from 1× to 8× SDR white onto an SDR scene with a pointer or the keyboard. A pixel inspector reads each stamp back. The export step encodes with toBlob(), decodes the file into a fresh float16 canvas and reports whether the highlights survived or were clipped. The explainer says extended canvases should be encoded with HLG or PQ.

  4. Context parity matrix

    An advanced composition. The same {mode} request goes to an on-page canvas, an OffscreenCanvas, an OffscreenCanvas inside a worker, a canvas passed to a worker with transferControlToOffscreen(), and a WebGPU canvas read back through getConfiguration(). The aim is one CanvasToneMapping across every rendering surface.

why it is proposed

The output bitmap of a float16 canvas can represent any colour, but the spec has no way to say whether values above 1.0 are HDR content or just extra precision for SDR content. WebGPU solved the same problem with GPUCanvasConfiguration.toneMapping, and this proposal renames that dictionary to CanvasToneMapping, moves it into HTML and adds it to the 2D settings with a default of {mode: "standard"}, which is what browsers do today. "extended" is defined exactly as in WebGPU: within SDR range the content looks the same as with standard, and values beyond it use whatever headroom the display has, clamped at the limit. The explainer also covers the interaction with dynamic-range-limit, preserving the mode through ImageBitmap and VideoFrame, and HLG/PQ encoding on export. Future directions list Reinhard, reference-white, BT.2408 and SMPTE ST 2094-50 modes, which are not in the enum yet.

the surface

enum CanvasToneMappingMode { "standard", "extended" };
dictionary CanvasToneMapping { CanvasToneMappingMode mode = "standard"; };
partial dictionary CanvasRenderingContext2DSettings {
  CanvasToneMapping toneMapping = {};
};

const ctx = canvas.getContext('2d', {
  colorSpace: 'display-p3',
  colorType: 'float16',                 // values > 1.0 need a float bitmap
  toneMapping: { mode: 'extended' },    // allow HDR headroom on display
});
ctx.getContextAttributes().toneMapping.mode;  // "extended" only when supported
ctx.fillStyle = 'color(srgb-linear 4 4 4)';   // 4× SDR white

use-case portfolio

  • Basic / canonical: HDR ramp.
  • Configuration / inspection tooling: settings inspector (request vs echo, support matrix).
  • Practical product: HDR highlight painter (painting, inspection, export).
  • Edge / failure / migration: settings inspector (ignored member, TypeError on a future mode, unorm8 + extended, second getContext call), HDR ramp (dynamic-range-limit clamp), and painter export (clipping in the file).
  • Novel / advanced composition: context parity matrix (2D, OffscreenCanvas, worker, transferred canvas and WebGPU under one dictionary).

Not built: VideoFrame metadata. The explainer only says frames "should include metadata" from a WebCodecs registry entry that does not exist yet, so there is no observable surface to probe.
