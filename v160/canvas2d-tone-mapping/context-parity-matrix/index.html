Context parity matrix

The proposal moves WebGPU's GPUCanvasToneMapping into HTML as a shared CanvasToneMapping, so one dictionary configures HDR output everywhere. This matrix asks for {mode: "standard"} and {mode: "extended"} on every surface an HDR rendering pipeline might use: an on-page canvas, an OffscreenCanvas, an OffscreenCanvas inside a worker, a canvas handed to a worker with transferControlToOffscreen(), and a WebGPU canvas. It then shows each context's own report of the mode it applied.

why parity matters

A real HDR pipeline often decodes and composites in a worker, renders effects in WebGPU, and presents through a canvas on the page. If the 2D surfaces ignored the mode while WebGPU honoured it, one frame could clip and the next could glow. A row is "honoured" only when that surface echoes "extended" back. The 2D surfaces report through getContextAttributes(), and WebGPU reports through GPUCanvasContext.getConfiguration(). WebGPU shows "blocked" when no adapter is available, as in headless or software-only environments, rather than a guess.

The explainer also says an ImageBitmap made from an extended canvas keeps its tone mapping when it is drawn elsewhere. No API exposes that property on an ImageBitmap, so it can only be checked by eye on an HDR display. It is not part of this matrix.
