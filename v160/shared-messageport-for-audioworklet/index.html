Shared MessagePort for AudioWorklet

The Web Audio spec defines a pair of entangled MessagePorts: audioContext.audioWorklet.port on the main thread and port on the AudioWorkletGlobalScope. With them, a page can talk to the audio rendering scope itself, rather than to one processor, without the dummy "bootstrap" AudioWorkletNode that Emscripten output and other WebAssembly audio engines have needed until now. Firefox shipped this in version 138, and Chromium is catching up.

Enabling it. The Blink runtime feature is AudioWorkletSharedPort. Its status in runtime_enabled_features.json5 is stable, so it is on by default in any build that includes the implementation (ChromeStatus targets Chrome 160). For builds where it was still gated, ChromeStatus lists chrome://flags/#enable-experimental-web-platform-features, and --enable-blink-features=AudioWorkletSharedPort enables it explicitly. A build older than the implementation has nothing to enable: the attribute is simply missing, and every page here reports that. AudioWorklet also requires a secure context (https or localhost).

Probing…

concepts

  1. Port handshake

    The basic surface and a scope inspector. After addModule(), a ping on audioWorklet.port is answered by top-level module code, with no processor involved, reporting sampleRate, currentFrame, renderQuantumSize and port instanceof MessagePort from inside the scope. The page also measures the round trip, checks that a 64 KiB ArrayBuffer is transferred rather than copied, and covers the close() edge case.

  2. Bootstrap-processor migration

    The legacy "bootstrap processor" workaround and the shared port run side by side, followed by the production pattern that detects 'port' in AudioWorklet.prototype and picks one. A separate reader processor confirms which route delivered the config. The page also lists the workaround's failure modes: graph overhead, no transfer list, and ordering races.

  3. Shared wavetable synth

    A practical product: three voices read one wavetable stored in the global scope. A sound change is one message on the shared port, compared with one per voice on the fallback, and each voice reports which table version it is rendering.

  4. Worker → worklet pipe

    An advanced composition. A MessageChannel end is transferred into the scope over the shared port, so a dedicated Worker drives a tremolo LFO straight on the audio thread. The page then blocks its own main thread for two seconds and counts the messages that still arrive.

why it exists

Until now, only AudioWorkletNode.port and AudioWorkletProcessor.port existed, and each pair connects one node to its processor. Anything that belongs to the whole scope, such as a compiled WebAssembly module, a shared sample bank, tuning tables, or a control channel from a worker, had to arrive through some processor's constructor or port. That meant creating a processor whose only job was carrying messages (web-audio-api#2456, resolved by PR #2507). Emscripten's AudioWorklet support had to keep that hack (emscripten#25354), and real-world players that call audioContext.audioWorklet.port broke in Chromium. The spec notes that if you add a message listener, you should close() one end when you are done so it can be garbage-collected.

the surface

[Exposed=Window, SecureContext]
interface AudioWorklet : Worklet {
  readonly attribute MessagePort port;
};
[Global=(Worklet, AudioWorklet), Exposed=AudioWorklet]
interface AudioWorkletGlobalScope : WorkletGlobalScope {
  readonly attribute MessagePort port;
  // registerProcessor, currentFrame, currentTime, sampleRate, renderQuantumSize…
};

// main thread
await ctx.audioWorklet.addModule('engine.js');
ctx.audioWorklet.port.postMessage({ wasm: module }, [/* transferables */]);

// engine.js — top level, no processor needed
port.onmessage = (e) => { /* initialise shared state */ };

use-case portfolio

  • Basic / canonical: port handshake.
  • Configuration / inspection tooling: port handshake, whose scope inspector reports facts from inside AudioWorkletGlobalScope.
  • Practical product: shared wavetable synth.
  • Edge / failure / migration: bootstrap-processor migration, plus the close() and transfer edge cases in port handshake.
  • Novel / advanced composition: worker → worklet pipe.
