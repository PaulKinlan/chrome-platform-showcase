Worker → worklet pipe

A dedicated Worker produces a 4 Hz tremolo LFO at 50 messages per second and sends it straight to the audio rendering thread. The page creates a MessageChannel, passes one end to the worker, and transfers the other end into the AudioWorkletGlobalScope through audioWorklet.port. After that the main thread is no longer on the path. To prove it, the page blocks itself for two seconds while the scope keeps counting the worker's messages.

why this composition matters

Control data for audio, such as sequencer events, MIDI from a Web MIDI worker, or analysis results from a WASM DSP worker, should not wait in the main thread's queue behind layout and input handling. MessagePorts are transferable, so one postMessage(msg, [port]) on the shared port wires any worker directly to the worklet scope, and every processor can read the result. Without the shared port, the only way to transfer a port in is through one specific AudioWorkletNode.port. This page falls back to that route when it has to, and labels it.
