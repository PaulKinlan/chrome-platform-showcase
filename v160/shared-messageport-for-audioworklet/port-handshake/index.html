what this shows

Before this change, code that needed to reach the global scope (an Emscripten runtime, a shared wavetable, a WebAssembly module) had to create a throwaway processor, because only AudioWorkletNode.port existed. The spec defines a pair of entangled ports: AudioWorklet.port on the main thread and AudioWorkletGlobalScope.port inside the worklet. Both are ordinary MessagePorts, so structured clone and transfer lists work. Setting onmessage starts the port implicitly. The spec's note applies too: if you listen on this port, call close() on one end when you are done so the resources can be collected. The edge button shows that after close(), pings go nowhere.
