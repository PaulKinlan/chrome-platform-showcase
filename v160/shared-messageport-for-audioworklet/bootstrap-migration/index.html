Bootstrap-processor migration

Emscripten, MOD players and other WebAssembly audio engines need to get start-up data into the AudioWorkletGlobalScope before any real processor runs. Without a shared port, the only way in is a dummy AudioWorkletNode whose processor constructor copies its processorOptions into a global. This page runs both paths for real, then creates a separate reader processor to confirm what reached the scope and by which route.

before

// main
const boot = new AudioWorkletNode(ctx, 'bootstrap',
  { processorOptions: { config } });
// worklet
registerProcessor('bootstrap', class extends
  AudioWorkletProcessor {
  constructor(o) { super();
    globalThis.sharedConfig = o.processorOptions.config; }
  process() { return false; }
});

after

// main
ctx.audioWorklet.port.postMessage({ type: 'config', config });
// worklet (top level of the module)
port.onmessage = (e) => {
  globalThis.sharedConfig = e.data.config;
};

// migration-safe
if ('port' in AudioWorklet.prototype) { /* after */ }
else { /* before */ }

failure modes this avoids

  • The bootstrap node is a real graph object. If it is never connected, some engines never construct its processor, and if it is connected, it costs render time until it returns false.
  • processorOptions is structured-cloned and cannot carry a transfer list, so large buffers and MessagePorts are copied or not allowed at all. The shared port accepts a transfer list.
  • Ordering is easy to get wrong: a processor created before the bootstrap one finishes sees null. With the shared port, the message is queued in the scope as soon as the module is loaded.
  • Detect the feature with 'port' in AudioWorklet.prototype, the exact attribute you will use, rather than by browser version.
