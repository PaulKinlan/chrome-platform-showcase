SharedWorkerConnectEventEmptyStringData

The connect event a shared worker receives for each new client is a MessageEvent, and the HTML spec says its data attribute is initialised to the empty string. Chromium left it null, unlike Firefox and Safari, which both pass the web-platform test. From Chrome 160, e.data in a connect handler is "". Small, but observable: code that sniffed e.data === null, parsed it as JSON or relied on typeof behaves differently.

No opt-in needed. This is a behaviour fix that ships on by default; ChromeStatus records the Finch name SharedWorkerConnectEventEmptyStringData (a kill switch, not a developer flag). No matching entry was found in runtime_enabled_features.json5 on Chromium main at research time, so there is no documented way to turn the new behaviour on in an older build. Every page reports which value your browser actually produces.

concepts

  1. Connect data probe

    Start a fresh real shared worker and inspect every field of the connect event it received (data, typeof, origin, lastEventId, ports, source, isTrusted), compared against the spec. Plus the contrast that explains it: new MessageEvent("connect").data is still null.

  2. Legacy sniffing audit

    Migration and edge cases: ten common patterns (=== null, ??, ||, JSON.parse, typeof…) run inside the worker against the real event and against the other value, showing which ones change behaviour. Then test your own expression.

  3. Tab presence hub

    The practical setting: one named shared worker coordinating this page, member frames you add and remove, and real tabs. The hub keeps a live roster and logs data for every connect event it receives.

use-case portfolio

  • Basic / canonical: connect-data-probe.
  • Inspection tooling: connect-data-probe's full field table and constructor-default comparison.
  • Practical product use: tab-presence-hub.
  • Edge / failure / migration: legacy-sniffing-audit.
  • Advanced composition: tab-presence-hub composes one shared worker with iframes and real tabs. A deeper composition is not applicable: the change touches one attribute of one event and has no API to combine with (source: the ChromeStatus summary and the HTML spec's SharedWorker constructor steps).
