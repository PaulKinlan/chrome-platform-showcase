Round-trip into string APIs

The practical reason selectorText exists. The rest of the platform names pseudo-elements by string: getComputedStyle(el, "::x"), el.animate(kf, {pseudoElement: "::x"}), el.pseudo("::x"). A reusable helper that is handed only a CSSPseudoElement object (from pseudoTarget, from a framework, from a previous lookup) needs a string that selects exactly that pseudo-element. Run the same helper with selectorText and with the pre-160 workaround, type, and compare.

Probing this browser…
selectorText is behind a flag in this build. The selectorText column will read “not exposed”. Enable chrome://flags/#enable-experimental-web-platform-features and relaunch, or launch with --enable-blink-features=CSSPseudoElementSelectorText / --enable-features=CSSPseudoElementSelectorText. The type column runs for real either way.

the helper

function pulse(pseudo) {
  const key = pseudo.selectorText;                 // Chrome 160+
  const from = getComputedStyle(pseudo.element, key).opacity;
  pseudo.element.animate([{ opacity: from }, { opacity: 0.3 }, { opacity: from }],
                         { duration: 400, pseudoElement: key });
}

// Pre-160 workaround: pseudo.type — fine for "::before", but
// getComputedStyle(html, "::view-transition-group") → empty declaration
// html.animate(kf, { pseudoElement: "::view-transition-group" }) → SyntaxError

Verified on Chromium 153 in this container: with key "::view-transition-group", animate() throws SyntaxError: ::view-transition-group is a syntactically invalid pseudo-element and getComputedStyle returns empty values, while the full "::view-transition-group(panel)" works during a transition.

Findings: the native path

Tested Chrome for Testing 158.0.8127.36 (Linux, headless) with --enable-experimental-web-platform-features, 2026-11-28: during a live view transition, the selectorText key works for animate() and re-selects the same object, while the type key throws SyntaxError: ::view-transition-group is a syntactically invalid pseudo-element. That matches what Chromium 153 showed for the type string, now with the native selectorText side confirmed.
