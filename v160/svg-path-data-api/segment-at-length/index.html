Segment at length

getPointAtLength() has always told you where a distance lands. getPathSegmentAtLength() tells you which command it lands in — the question behind progress-along-a-route UIs, hit-testing a click to a segment, or labelling the leg of a path animation. Scrub the distance, compare the native answer with the cumulative-length workaround everyone wrote before, then try the edges the spec defines.

Chrome 160+ ships this by default. Earlier Chrome/Canary: enable chrome://flags/#enable-experimental-web-platform-features, or launch with --enable-blink-features=SVGPathDataAPI (also --enable-features=SVGPathDataAPI or --enable-experimental-web-platform-features). Chrome 153 behind those flags has getPathData/setPathData but not yet getPathSegmentAtLength. Chrome 158 behind --enable-blink-features=SVGPathDataAPI has all three.

native vs. the old way

// native (Chrome 160+, Firefox 137+)
const seg = path.getPathSegmentAtLength(d);   // {type, values} or null
// distance is clamped to [0, getTotalLength()]; on an exact boundary the
// EARLIER segment wins; NaN/Infinity throw a TypeError (IDL "float").

// the workaround: measure every prefix of the path
const segs = path.getPathData();
let i = 0;
for (; i < segs.length; i++) {
  probe.setPathData(segs.slice(0, i + 1));
  if (probe.getTotalLength() >= d) break;    // O(n) layouts per query
}

The segment returned is as authored (not normalised) and comes from the d attribute’s base value, the same list getPathData() gives you. That makes it easy to go from “the user clicked here” to “edit this command”.

findings

  • Native path agrees with the workaround (verified 2026-11-25): Chrome for Testing 158.0.8127.36 (Linux, headless) with --enable-blink-features=SVGPathDataAPI, both shapes, scrubbed at 0–100%: every native answer matched the cumulative-length loop at 1280×800 and 360×740.
  • Edges: distance −25 returned the first command (M 20 160); total + 100 returned the last (C); the exact length 100 between segments 1 and 2 returned the earlier L; NaN threw TypeError: The provided float value is non-finite.; a new <path> with no d returned null.
  • Default-on Chrome 160 without a flag: not verified (only Chrome 158 was available).
