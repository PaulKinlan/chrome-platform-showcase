Minimal getPathData / setPathData starter

The smallest working round-trip for the SVG Path Data API: normalize an SVG <path> containing quadratic curves and elliptical arcs into plain absolute M/L/C/Z dictionaries with getPathData({ normalize: true }), mutate one control point, and write the array back with setPathData().

How it works

  1. path.getPathData({ normalize: true }) parses the d attribute and converts relative commands, quadratics (Q), and elliptical arcs (A) into plain absolute M, L, C, and Z objects.
  2. Because segments are plain dictionaries ({ type, values }), scripts edit coordinate arrays directly without string parsing or regexes.
  3. path.setPathData(segments) validates the segment list, writes the serialized d attribute back onto the element, and fires MutationObserver records for d.

Common errors and fixes

  • Path becomes empty or truncated without throwing: setPathData() keeps only the valid prefix. The first segment must be M or m, every coordinate must be finite, and arc flags must be 0 or 1.
  • TypeError on setPathData(): every entry must supply both required dictionary members type and values; omitting either throws during WebIDL conversion.
  • CSS d: path(...) or SMIL edits do not appear: getPathData() always inspects the base d attribute, not computed CSS or animated values.

Findings

In Chrome for Testing 153 (checked 2026-11-22) behind --enable-blink-features=SVGPathDataAPI, getPathData() and setPathData() are available and normalize Q/A commands into cubic Beziers, while getPathSegmentAtLength() was still unexposed in 153 and landed later on Chromium main. Default-enabled Chrome 160 builds are not verified in Chrome 160 in this authoring environment; Firefox has shipped the API since 137.
