SVG Path Data API

Three methods on SVGPathElement give structured access to path geometry without parsing the d string: getPathData() returns an array of {type, values} segments (with {normalize: true} reducing everything to absolute M, L, C, Z), setPathData() writes such an array back, and getPathSegmentAtLength() tells you which segment sits at a distance along the path. It replaces the SVGPathSegList API Chromium removed in Chrome 48, and matches what Firefox has shipped since version 137.

Behind a flag in builds where it is not yet on by default. The runtime feature is SVGPathDataAPI (status experimental in runtime_enabled_features.json5). To try it: open chrome://flags/#enable-experimental-web-platform-features, set it to Enabled and relaunch, or start Chrome with --enable-blink-features=SVGPathDataAPI (or --enable-experimental-web-platform-features). There is no dedicated chrome://flags entry for this feature.

concepts

  1. Segment inspector

    The basic surface and an inspection tool. Type or pick any d string and see the browser's own getPathData() result as a table, next to getPathData({normalize: true}): relative commands become absolute, H/V become L, quadratics and arcs become cubics.

  2. Node editor

    The product use case: a small path editor. Drag the anchor and control-point handles with a pointer, or focus one and use the arrow keys. Each move reads the segments with getPathData(), changes one number and writes them back with setPathData(), so no string parsing is involved. Add and remove segments, then copy the serialized d.

  3. Route scrubber

    getPathSegmentAtLength() on a delivery route made of several legs. Move the slider to see which leg covers that distance; the marker uses getPointAtLength() for the same distance. Buttons test the documented edge inputs: negative distances, NaN, distances past the end, an empty path and a path of zero length.

  4. Validation and migration lab

    Edge and failure behaviour. setPathData([{}]) throws a TypeError. Unknown segment types and wrong value counts are skipped without an error. setPathData([]) leaves an empty d="". NaN values are accepted. getPathData() returns the base value while a SMIL animation is running. For migration, the page checks that pathSegList is gone and that polyfills give way to the native methods. Each check shows the expected and observed results side by side.

  5. Shape morph

    A more advanced composition. Two very different shapes, each with its own mix of arcs, quadratics and lines, are reduced to absolute M/L/C/Z with getPathData({normalize: true}). Lines are then turned into cubics, and the longest curves are split until both shapes have the same number of segments. A slider or animation interpolates between them with setPathData() on every frame. This is the D3-style path tween the explainer cites, built without a parser.

why it exists

Path editors such as Boxy SVG and SVG-Edit, D3 path morphing, and animation tools all need the segments of a path. Since SVGPathSegList was removed from Chrome 48 in January 2016, the only option in Chromium has been to parse and re-serialize the d string, usually with path-data-polyfill. The SVG Working Group's replacement is deliberately simple. Segments are plain dictionaries, so setPathData() accepts ordinary object literals (resolved in w3c/svgwg#1082). Values are unrestricted float, so NaN does not throw. Validation has two levels: a structurally broken segment throws a TypeError, while a semantically invalid one is skipped, following SVG's "render what you can" error model. The methods return the base value of d, never the animated value.

the surface

dictionary SVGPathSegment {
  required DOMString type;
  required sequence<unrestricted float> values;
};
dictionary SVGPathDataSettings { boolean normalize = false; };

interface mixin SVGPathData {
  sequence<SVGPathSegment> getPathData(optional SVGPathDataSettings settings = {});
  undefined setPathData(sequence<SVGPathSegment> pathData);
  SVGPathSegment? getPathSegmentAtLength(float distance);
};
SVGPathElement includes SVGPathData;

const segs = path.getPathData();          // [{type:"M", values:[10,80]}, ...]
segs[1].values[0] = 50;
path.setPathData(segs);                    // no parse, no serialize
path.getPathSegmentAtLength(42);           // {type:"C", values:[...]} or null

use-case portfolio

  • Basic / canonical: segment inspector, which reads segments in both raw and normalized form.
  • Configuration / inspection tooling: segment inspector, which compares normalize on and off for any d, with presets covering all 20 commands.
  • Practical product: node editor (round trip through setPathData()) and route scrubber (progress along a route).
  • Edge / failure / migration: validation and migration lab.
  • Novel / advanced composition: shape morph, which normalizes, equalizes and interpolates segments every frame.
