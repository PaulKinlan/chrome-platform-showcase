Annex B literal trap

The grammar adds \A, \z and \Z only under [+UnicodeMode]. Outside u/v, web-compat Annex B keeps treating them as identity escapes — the plain letters A, z, Z — so a pattern copied from Perl or PCRE without the flag compiles happily and silently means something else. Even the explainer’s own /end\Z/ example has no u. This page runs every edge case live.

migration checklist

  • Porting a pattern that uses \A/\z/\Z? Add u or v. A linter can flag \A, \z, \Z in non-Unicode patterns, since they are almost never meant literally.
  • Don’t quantify them (\A*) and don’t put them in a class ([\A]): both are early SyntaxErrors in Unicode mode.
  • \Z absorbs exactly one terminator, and \r\n counts as one. Use \z when trailing newlines must be rejected.
  • Lower-case \a and upper-case \Z are not related: \a stays an invalid escape in Unicode mode.
