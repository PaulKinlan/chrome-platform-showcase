SDP cryptex inspector

Cryptex is signalled by a single SDP line, a=cryptex (RFC 9335 §4). It is a TRANSPORT-category attribute, so under BUNDLE it covers every RTP m= section of the group or none of them — and never the data channel. Build a real offer, see where the line lands, and see exactly which RTP header extensions it would take out of the clear.

what the extensions carry

    
Each a=extmap line is metadata attached in the RTP header of every packet. Without cryptex these bytes travel in the clear even though SRTP encrypts the payload: ssrc-audio-level (RFC 6464) reveals when each participant speaks, abs-send-time/transport-wide-cc expose timing, sdes:mid and rtp-stream-id label streams, and video-orientation/color-space describe the picture. Cryptex reuses the SRTP keys to encrypt the whole extension block and any CSRC list.
