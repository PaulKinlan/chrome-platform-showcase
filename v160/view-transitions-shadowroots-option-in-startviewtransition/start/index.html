Minimal shadowRoots starter

The smallest working example of document.startViewTransition({ update, shadowRoots }). A custom element names its pill inside its own shadow stylesheet, and the caller opts that ShadowRoot into a document view transition without exposing ::part().

How it works

  1. <hello-badge> attaches an open shadow root and declares view-transition-name: hello-pill inside its shadow stylesheet.
  2. document.startViewTransition({ update, shadowRoots: [badge.shadowRoot] }) registers the shadow root alongside the document tree scope.
  3. Once transition.ready resolves, the script inspects document.getAnimations() to verify whether ::view-transition-group(hello-pill) was actually captured by the browser.

Common errors and fixes

  • Shadow element fades instead of morphing: verify the exact ShadowRoot is passed in shadowRoots and that the runtime flag ViewTransitionShadowRoots is enabled in pre-160 Chromium builds.
  • TypeError on call: shadowRoots is typed as non-nullable sequence<ShadowRoot>. Passing null (for instance, closedHost.shadowRoot) or an Element throws immediately during dictionary conversion.
  • InvalidStateError on ready: all listed shadow roots share one flat name namespace with the transition scope. Rename colliding view-transition-name values across participating trees.

Findings

Chromium’s ViewTransitionOptions dictionary reads shadowRoots behind the ViewTransitionShadowRoots Blink runtime feature (enable via chrome://flags/#enable-experimental-web-platform-features or --enable-blink-features=ViewTransitionShadowRoots). In earlier builds (verified in Chrome for Testing 153 and Chromium 157 on 2026-11-22), the dictionary member is ignored and only light-DOM names participate. Default-enabled Chrome 160 behavior is not verified in Chrome 160 in this authoring environment; the live checks table above reports what your running browser actually executes.
