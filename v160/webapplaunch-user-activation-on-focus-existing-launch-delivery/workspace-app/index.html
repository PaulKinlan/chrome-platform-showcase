Workspace app

An installable app with "launch_handler": {"client_mode": "focus-existing"} and three shortcuts, one per workspace. Launches go into the open window instead of spawning duplicates. When a launch targets a different workspace, the launchQueue consumer below tries window.open() to give it its own window. Before this change that call was popup-blocked because the delivery carried no user activation; with it, the user's launch click counts. Every launch is logged with the navigator.userActivation state at delivery and the real window.open() result.

How to observe the real thing (manual)

  1. Install this app: use the browser's install icon in the address bar, or menu → Cast, save and share → Install page as app.
  2. Open it from the OS launcher. It starts in workspace alpha.
  3. With that window still open, right-click (or long-press) the app icon and choose the Workspace Beta shortcut. That is a focus-existing launch: the window comes forward and this page's consumer runs.
  4. Read the newest log row. Chrome 160 with the feature: isActive: true and a new window opened. Earlier builds: isActive: false and window.open() returned null.

Launch deliveries only happen in an installed app window, so a browser tab cannot run this part automatically; the log is kept in this browser's storage so tab and app share it.

In-tab rehearsal of the consumer's decision (simulation)

These buttons call the same consumer function with a hand-made {targetURL} object. They do not produce a launch; they reproduce the two activation states a launch can arrive with, so you can see the real window.open() outcome for each. Rows they add are marked simulated.
