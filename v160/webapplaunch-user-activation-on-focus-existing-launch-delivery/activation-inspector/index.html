Activation inspector

The feature does one thing: when a focus-existing launch is delivered into an open app window, Chrome grants that window transient user activation, as if the user had clicked inside it. This page inspects both halves of that contract in your browser: the Launch Handler surface (window.launchQueue, LaunchParams, display mode) and the activation model it feeds (navigator.userActivation): how long activation lasts, and how one call consumes it.

why this matters for launches

A launch consumer runs from a launchQueue callback, not from an input event in the page. Without a grant, isActive is false there and every activation-gated API refuses. Chrome 160 grants activation at delivery for focus-existing launches, the same treatment a click on a page's own Notification already gets. That activation then behaves exactly as the timer and consumption measurements above show: it expires after a few seconds and the first consuming call (window.open(), requestFullscreen()) uses it up.
