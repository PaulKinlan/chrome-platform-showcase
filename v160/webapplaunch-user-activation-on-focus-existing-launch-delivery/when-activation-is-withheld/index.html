When activation is withheld

The grant is deliberately narrow. The spec runs the activation notification steps only in the focus-existing branch, exactly once per launch, and forbids it for launches the user did not initiate and for re-delivery after a reload. Chromium’s condition is user_initiated() && !started_new_navigation() plus a kill switch. This page logs what really reaches it — including across a reload — and maps every other path to its outcome.

Status: on by default in Chrome 160; reproduce the old behaviour with --disable-features=WebAppLaunchHandlerUserActivation. Real deliveries need this concept installed as an app (shortcut: Launch again (focus-existing)).

launchQueue.setConsumer((params) => {
  // Never branch on the Chrome version: the kill switch, a navigating
  // launch, or a non-user launch all yield false on 160+ too.
  if (navigator.userActivation?.isActive) {
    openSeparateWindow(params.targetURL);
  } else {
    showInAppPrompt(params.targetURL);   // the user's click supplies activation
  }
});
