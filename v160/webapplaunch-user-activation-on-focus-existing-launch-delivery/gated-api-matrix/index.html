Gated API matrix

What does one launch’s activation actually buy you? Pick the activation-gated calls your consumer should attempt, in order, then deliver a launch. Each step records isActive before and after the call — so you can see that one launch is one activation: window.open() and requestFullscreen() each consume it, and whatever runs next is back to square one.

Status: on by default in Chrome 160 (kill switch: --disable-features=WebAppLaunchHandlerUserActivation). Launches are delivered only into an installed app window with "client_mode": "focus-existing"; in a tab the two baseline buttons below run the very same matrix from a real click (activation present) and after the activation has expired (absent, the pre-160 launch state).

how each call reports a missing activation

window.open(url)            // returns null (popup blocked) — consumes activation when it succeeds
el.requestFullscreen()      // rejects TypeError ("Permissions check failed") — consumes on success
showOpenFilePicker()        // rejects SecurityError without activation; AbortError if you cancel
navigator.share(data)       // rejects NotAllowedError without activation; AbortError if you cancel
