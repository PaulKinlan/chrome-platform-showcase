Activation-gated APIs

The ChromeStatus entry names window.open() and requestFullscreen() as the calls a launch consumer could not make before. Activation is a budget, not a permission: transient-activation calls fail once it has expired, consuming calls use it up for everything after them, and sticky-activation calls (vibrate()) only need the page to have been activated once. A launch consumer has the same budget. Pick an API and a timing; each run makes the real call and records isActive before and after.

design rules for a launch consumer

  • Make the activation-gated call synchronously in the consumer, before any await that might outlast the activation window.
  • You get one consuming call per launch. Choose between opening a window and going fullscreen; do not try both.
  • Feature-detect by outcome: window.open() returning null means blocked. Fall back to switching the existing window (no activation needed) so the launch never appears broken.
  • Other client modes do not need this: navigate-new and navigate-existing load a new document, so the launch is an ordinary navigation.
