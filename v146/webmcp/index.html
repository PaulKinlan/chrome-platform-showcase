WebMCP

A browser-native implementation of the Model Context Protocol — sites register structured tools that AI agents can discover and invoke directly, without scraping HTML or relying on hidden APIs.

Behind a flag since Chrome 146; origin trial in Chrome 149–156. The API is document.modelContext (not navigator). To run it locally, turn on chrome://flags/#enable-experimental-web-platform-features, or launch Chrome with --enable-features=WebMCP (or --enable-blink-features=WebMCP), then reload. To ship it to visitors, register for the WebMCP origin trial. Every concept page uses the real API when it is exposed and says so; otherwise it runs the same calls against a labelled in-page stand-in that follows the spec's validation rules.

concepts

  1. Tool Registry Explorer

    Register tools with document.modelContext.registerTool(), read them back with getTools(), unregister them by aborting a signal, and trigger each of the spec's rejection paths (duplicate name, invalid name, empty description, missing execute).

  2. Agent Handshake Simulator

    Step through an agent–page interaction: discovery with getTools(), a call with executeTool(), and the result. The agent's reasoning is scripted, the page's replies are real, and one scenario shows a rejected call and a timed-out one.

  3. Tool call replay

    Type a natural-language prompt and watch a stand-in assistant pick one of the page's registered tools, check the arguments against its inputSchema, and dispatch with executeTool(). Includes a throwing tool, invalid input and a deadline.

  4. MCP Tool Tester

    Pick a registered tool, fill in its parameters and invoke it. The trace shows the MCP tools/call an agent would send, the executeTool() call the page makes, and the MCP result that goes back, with isError for failures.

why it shipped

AI agents interacting with the web today face a fundamental mismatch: websites are designed for human eyes — HTML, visual layouts, implicit affordances. Agents scrape, guess at selectors, and break on every redesign. The Model Context Protocol (MCP) addresses this by letting sites expose machine-readable capability descriptions: here is what I can do, here is how to call it, here is the schema of the result. WebMCP brings MCP natively into the browser via document.modelContext, so any installed AI (Gemini in Chrome, a local LLM, an agentic extension) can discover and invoke tools without HTTP calls to a separate server, without scraping, and with full user-consent visibility. The origin trial starting in Chrome 149 lets developers experiment with the API and give feedback before it becomes a baseline feature.
