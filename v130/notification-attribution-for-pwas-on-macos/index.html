Notification attribution for PWAs on macOS

When a Progressive Web App is installed on macOS, its notifications are natively attributed to the PWA itself — its own name and icon in Notification Center — instead of to Google Chrome. Users can then manage sounds, badges, alert styles, and Focus modes per app, matching native macOS behavior (and WebKit). Two behavior changes ride along: app notifications no longer honor requireInteraction (macOS decides persistence per app), and the Badging API now requires notifications permission. Behind chrome://flags/#enable-mac-pwas-notification-attribution on macOS.

why it shipped

Previously every PWA notification appeared under the "Google Chrome" umbrella in macOS Notification Center, so users could not manage notification settings per app — a Slack PWA and a calendar PWA shared one switch. Attributing notifications to each PWA's App Shim delivers a much-requested native integration, aligns Chrome with macOS platform conventions and with WebKit's existing behavior, and gives per-app control over sounds, badges, alerts, and Focus modes. Admins pre-granting permission via NotificationsAllowedForUrls must additionally deploy a macOS MDM profile for the PWA's bundle ID.
