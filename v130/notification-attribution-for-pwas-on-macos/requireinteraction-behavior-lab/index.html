requireInteraction behavior lab

requireInteraction: true asks the platform to keep a notification on screen until the user acts on it. For notifications attributed to a macOS app that request is now advisory — macOS shows the notification in the per-app style the user chose in System Settings (banner vs alert), exactly as it does for native apps and as WebKit already behaved. The member never left the API: this lab probes the surface for real, fires real notifications either way, and is explicit about which part only your eyes can verify.

The contract, per context:
  • Browser tab (any OS): requireInteraction: true keeps the notification visible until dismissed — the classic behavior, still honored.
  • Attributed macOS app notification: the field is ignored; persistence follows the user's per-app System Settings choice (temporary banner or persistent alert).
  • What a page can probe: only the surface ('requireInteraction' in Notification.prototype, and the instance property reflecting what you passed). Whether the OS held the notification on screen is a manual observation — no API reads the display style back, so this page never claims a behavioral pass.
const n = new Notification("Ping", { requireInteraction: true });
n.requireInteraction   // → true: your REQUEST is reflected back…
// …but on an attributed macOS app notification the OS may still
// show a transient banner: persistence is the user's per-app setting.
