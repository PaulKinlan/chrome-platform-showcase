Telemetry noise filter

The motivating product problem. An offline-capable app reports every rejected fetch() in its service worker to an error dashboard, except the ones it caused itself by answering first. With Navigation Preload it filtered those by message; after moving to "race-network-and-fetch-handler" they all said Failed to fetch and the dashboard lit up. the classifier

const EXPECTED_CANCELLATIONS = new Set([
  // Navigation Preload (already in Chrome):
  "The service worker navigation preload request was cancelled before 'preloadResponse' settled.",
  // Static routing race (Chrome 159+):
  "The service worker race-network-and-fetch-handler request was cancelled before 'fetch()' settled.",
]);

function shouldAlert(error) {
  if (error?.name === "AbortError") return false;           // our own AbortController
  if (error instanceof TypeError && EXPECTED_CANCELLATIONS.has(error.message)) return false;
  return true;                                              // genuine — page someone
}

Matching an exact, implementation-defined string is deliberate here: it is what the Navigation Preload code already did, and it fails safe — on a browser without the change the cancellation still says Failed to fetch and is reported, so you get noise, never a missed outage.
