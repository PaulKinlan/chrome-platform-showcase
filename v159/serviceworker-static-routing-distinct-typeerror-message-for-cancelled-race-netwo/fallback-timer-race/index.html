Fallback-timer race

The exact scenario from the ChromeStatus entry. A static route sends the request down "race-network-and-fetch-handler"; the fetch handler calls fetch(event.request) and races it against an offline-fallback timer inside event.respondWith(). When the timer wins before the server has sent headers, Chrome cancels the raced request — and the worker’s fetch() rejects. Which TypeError message it rejects with is what Chrome 159 changed.

// ../sw.js, install: route the slow URL down the race source
await event.addRoutes({
  condition: { urlPattern: { pathname: "/v151/cpu-performance-api/capability-echo" } },
  source: "race-network-and-fetch-handler",
});

// fetch: race the deduplicated network fetch against a fallback timer
const network = fetch(event.request);
event.respondWith(Promise.race([network, timer(fb).then(offlineFallback)]));
network.catch((error) => report(error.name, error.message));   // verbatim, to this page
