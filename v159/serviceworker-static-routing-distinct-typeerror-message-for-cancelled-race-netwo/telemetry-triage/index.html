Telemetry triage

Why the message changed: offline-capable apps moving from Navigation Preload to race-network-and-fetch-handler found that every cancelled race showed up in error telemetry as "Failed to fetch" — a false outage spike. Navigation Preload already had a distinct cancellation message; now static routing does too. This page sends a burst of real requests through the worker, feeds the worker's real rejections into two error pipelines, and shows what each one alerts on.

1 · Generate traffic

One burst = three requests where the offline-fallback timer beats a slow network (expected cancellations) plus one request that hits a redirect loop (a genuine network failure). All four go through the real worker and its real routing rule.

    3 · The classifier

    const RACE_CANCELLED =
  "The service worker race-network-and-fetch-handler request was cancelled before 'fetch()' settled.";
const PRELOAD_CANCELLED =
  "The service worker navigation preload request was cancelled before 'preloadResponse' settled.";

function triage(error) {
  if (error instanceof TypeError &&
      (error.message === RACE_CANCELLED || error.message === PRELOAD_CANCELLED)) {
    return 'expected-cancellation';   // count it, do not page anyone
  }
  return 'network-error';             // includes "Failed to fetch": alert
}

    Match the exact strings (the race string is verbatim from Chromium's service_worker_global_scope.cc; the preload string is quoted in the ChromeStatus motivation); there is no error code or IDL property for this — the entry is explicit that it is a message-only change with no spec or IDL change. Keep the preload string while you migrate: both paths can coexist.
