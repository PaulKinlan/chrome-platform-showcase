Cancellation lab

The exact situation from the ChromeStatus entry, for real: this page's service worker has a static routing rule with source: 'race-network-and-fetch-handler'. Its fetch handler calls fetch(event.request) — which Chromium deduplicates with the racing network request — and also starts an offline-fallback timer. When the timer wins, the network request is cancelled before its headers arrive, and the worker's fetch() rejects. Which TypeError message it rejects with is what Chrome 159 changes.

the worker code

// install
event.addRoutes([{ condition: { urlPattern: { pathname: '/…/race/*' } },
                   source: 'race-network-and-fetch-handler' }]);
// fetch
const network = fetch(event.request);           // deduplicated with the race leg
const fallback = sleep(timer).then(() => new Response(offlineJSON));
event.respondWith(Promise.race([network, fallback]));
network.catch((e) => report(e.message));
// ≤ Chrome 158:  "Failed to fetch"
// Chrome 159+:   "The service worker race-network-and-fetch-handler request
//                 was cancelled before 'fetch()' settled."
