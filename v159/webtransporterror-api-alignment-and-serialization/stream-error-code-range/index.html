streamErrorCode: all 32 bits, or 8?

streamErrorCode is an unsigned long, so an application can use any code from 0 to 4,294,967,295. Older Chromium accepted the code through an 8-bit (octet) dictionary member, so outgoing codes above 255 were clamped to 255 before they reached the wire. An application using code 4096 for "quota exceeded" would have sent 255. Chrome 159 carries the full value end to end. This page puts boundary values through each constructor this browser accepts and compares the result with what the spec's [Clamp] unsigned long? conversion requires.

"Spec expects" applies WebIDL [Clamp] rules: null stays null, NaN becomes 0, values are clamped to the 0–4,294,967,295 range, and halves round to even. The last column is the HTTP/3 error code the value maps to on the wire (draft-ietf-webtrans-http3 §4.3), so you can see what a narrowed code would have changed in a packet capture.

code path

const QUOTA_EXCEEDED = 4096;
const e = new WebTransportError("quota", { streamErrorCode: QUOTA_EXCEEDED });
e.streamErrorCode;   // 4096 in Chrome 159; the legacy form gave 255
writer.abort(e);     // RESET_STREAM with the full code mapped to HTTP/3

// Guard for older builds: detect narrowing before you rely on a code.
const fullRange = new WebTransportError({ streamErrorCode: 256 }).streamErrorCode === 256;
