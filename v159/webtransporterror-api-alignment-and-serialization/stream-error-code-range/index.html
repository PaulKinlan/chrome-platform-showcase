Stream error code range

streamErrorCode is an unsigned long: a 32-bit application code your protocol defines and the peer sees in RESET_STREAM or STOP_SENDING. Chromium’s legacy dictionary declares it as [Clamp] octet, so anything above 255 collapses to 255. Type a code and compare both conversions, run live in this browser, with the HTTP/3 codepoint the spec maps it to on the wire.

The two “live” cards call the real constructors. The standard card needs Chrome 159 (or chrome://flags/#enable-experimental-web-platform-features in a developer-trial build) and reports the TypeError otherwise. The HTTP/3 codepoint is calculated on this page from the draft’s formula, not read from the network: seeing the real frame needs a WebTransport server, which this site does not run.

Pick a code

Try values above 255, above 4294967295, negative numbers and halves. The cards update as you type.

Neighbouring codepoints on the wire

WebTransport shares the error-code space with HTTP/3, which reserves every codepoint of the form 0x1f × N + 0x21 for greasing. The mapping skips those, so two adjacent application codes sometimes land two HTTP/3 codepoints apart.
