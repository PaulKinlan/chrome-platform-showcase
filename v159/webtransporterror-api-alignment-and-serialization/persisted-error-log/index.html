Persisted error log

IndexedDB stores values using the same structured serialization as postMessage. Once WebTransportError is serializable, a diagnostics log can keep the error objects themselves and read them back after a reload, still answering instanceof WebTransportError. The serialized form carries message, source and streamErrorCode — and Chromium deliberately writes an empty stack field, so stack does not survive.

Writing a WebTransportError into IndexedDB needs Chrome 159 with the WebTransportErrorSerialization runtime switch on (the default; force it with --enable-blink-features=WebTransportErrorSerialization, or chrome://flags/#enable-experimental-web-platform-features in a developer-trial build). Chromium keeps reading stored errors permanently, even with the writer switched off. On a build that cannot write them, put() throws DataCloneError and this page stores a plain record instead, marked as a fallback in the table. The log lives only in this browser (database wte-error-log). “Log a real session failure” targets https://127.0.0.1:44443/never, so Chrome logs an expected “Failed to establish a connection” console error.
