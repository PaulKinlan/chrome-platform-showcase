An error that survives postMessage

Move your networking into a worker and every failure has to cross a thread boundary. Chrome 159 makes WebTransportError structured-clonable, so the error object itself — message, source, nullable streamErrorCode — travels instead of a hand-rolled {msg, code} copy. Two real hops below: a same-thread structuredClone(), and a full round-trip through a dedicated Worker.

Serialization is enabled by default from Chrome 159 (writer side sits behind a runtime kill switch; decoding is permanently enabled for forward compatibility). On earlier builds structuredClone() throws DataCloneError — the table reports that outcome as the honest pre-159 answer.

const err = new WebTransportError("stream reset", {
  source: "stream", streamErrorCode: 4294967295,
});

// hop 1 — same thread:
const copy = structuredClone(err);        // 159+: works; before: DataCloneError

// hop 2 — across a real thread boundary and back:
worker.postMessage(err);                  // worker echoes it straight back
// clone.message, clone.source, clone.streamErrorCode all survive
