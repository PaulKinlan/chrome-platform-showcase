Worker error relay

A common setup keeps the WebTransport session in a worker, so network work stays off the main thread, and lets the page handle the UI. When the session fails, the page needs the error: was it the whole session (source: "session", so reconnect) or one stream with an application code (so react to that code)? With serialization, the worker calls postMessage(error) and the page receives a real WebTransportError. Without it, that call throws, and every application has to write its own conversion. This page runs both paths for real and labels which one this browser took.

Native relay needs Chrome 159 (ChromeStatus also lists chrome://flags/#enable-experimental-web-platform-features). The session failure is real. The default URL points at a port with nothing listening, so ready rejects with a real WebTransportError on any network, and Chrome logs its own "Failed to establish a connection" line in the console. Enter a real server to see the connected case instead.

// worker.js
try { await transport.ready; }
catch (error) {
  try { postMessage({ error }); }                    // Chrome 159+: native clone
  catch { postMessage({ record: { message: error.message,
            source: error.source, streamErrorCode: error.streamErrorCode } }); }
}

// page
worker.onmessage = ({ data }) => {
  const e = data.error ?? rebuild(data.record);      // same shape either way
  if (e.source === "session") scheduleReconnect();
  else handleStreamCode(e.streamErrorCode);
};
