WebTransportError API alignment and serialization

Chromium shipped WebTransportError before the spec settled, and it differed from the spec in three ways. Its constructor took a single dictionary instead of (message, options). It narrowed outgoing streamErrorCode values to 8 bits, although the attribute is an unsigned long. And it could not be structured-cloned, so a worker could not hand the error to the page, and an error could not be stored in IndexedDB. Chrome 159 fixes all three and keeps the old dictionary constructor working for existing code.

Chrome 159 enables this by default. ChromeStatus lists chrome://flags/#enable-experimental-web-platform-features for the developer trial, and the Finch / runtime feature is WebTransportErrorSerialization (status: "stable" in runtime_enabled_features.json5). That switch only stops new errors from being serialized: reading serialized errors stays enabled, so errors already stored remain readable. None of these concepts need a server, because the constructor, the attributes and structured cloning all work locally.

concepts

  1. Two constructor forms, one error

    The basic case, plus migration. Probe whether this browser accepts the standard (message, {source, streamErrorCode}) form, the legacy ({message, streamErrorCode}) form, and structured cloning. Then build an error either way and inspect name, code, source, streamErrorCode and the DOMException ancestry. The legacy form cannot set source, and the page shows that.

  2. streamErrorCode: all 32 bits, or 8?

    The edge cases. Fifteen boundary values (null, 255, 256, 232−1, 232, −1, 2.5, NaN and others) go through each constructor and are compared with WebIDL [Clamp] unsigned long? conversion. A legacy build that clamps codes above 255 shows up immediately. Each row also shows the HTTP/3 error code the value maps to on the wire.

  3. Structured clone across every channel

    An inspection tool for serialization. One error goes through structuredClone(), a MessageChannel, a worker round trip, a BroadcastChannel and an IndexedDB put/get, next to a plain DOMException control on each channel. Every row reports what arrived and whether the message, source and code survived, or the real DataCloneError.

  4. Worker error relay

    The practical product pattern. A dedicated worker owns the transport, hits a real session failure, and relays the real WebTransportError to the page. It uses native cloning where available and a labelled plain-record fallback where not. The page then picks an action from source and streamErrorCode: reconnect with backoff, or handle that specific application code.

why it shipped

Firefox and Safari already implement the spec shape, so code written for them threw a TypeError in Chromium, and Chromium-only code using the dictionary form failed elsewhere. The 8-bit narrowing caused silent corruption: an application that reset a stream with code 4096 sent 255, and a server branching on the code took the wrong path. Serialization matters because WebTransport is exposed in workers and often lives there, and errors are the values most often posted to the page or logged to IndexedDB.

The spec serializes a WebTransportError by running the DOMException steps (name and message) and then copying [[Source]] and [[StreamErrorCode]], so a clone keeps its type, its source and a nullable code. Chrome ships the writer side behind a kill switch, so it can be turned off if it causes problems, while reading stays permanently on so that values already persisted can always be read back.

the API

[Exposed=(Window,Worker), Serializable, SecureContext]
interface WebTransportError : DOMException {
  constructor(optional DOMString message = "", optional WebTransportErrorOptions options = {});
  readonly attribute WebTransportErrorSource source;   // "stream" | "session"
  readonly attribute unsigned long? streamErrorCode;
};
dictionary WebTransportErrorOptions {
  WebTransportErrorSource source = "stream";
  [Clamp] unsigned long? streamErrorCode = null;
};

const e = new WebTransportError("quota", { streamErrorCode: 4096 });
e.name === "WebTransportError"; e.code === 0;
structuredClone(e).streamErrorCode === 4096;   // Chrome 159+
