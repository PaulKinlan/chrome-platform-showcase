Constructor compatibility matrix

Chromium now has two WebTransportError constructors: the spec's (message, options) and the old dictionary form kept as a compatibility overload. WebIDL overload resolution picks between them by the type of the first argument — so a plain object, null, a number and a string each land differently. This page runs ten calls for real and compares what your browser did with three reference behaviours.

Reference columns are derived, the “observed” column is live. “Chromium ≤158 (legacy only)” was recorded in Chrome for Testing 153 (with and without --enable-experimental-web-platform-features — identical). “Chromium aligned” is derived from Chromium's current web_transport_error.idl (both overloads) plus WebIDL overload resolution. “Spec only” is the W3C IDL alone (what an engine without the legacy overload, e.g. Firefox, does). No flag switches between them — the aligned behaviour arrives with the build (ChromeStatus: Chrome 159).

Migration helper: one function, every Chromium

Library code that must run on Chromium builds before and after the change can feature-detect the standard form behaviourally and fall back to the dictionary form, accepting its limits (source is always "stream", codes clamp to 0–255). Run it with your own arguments:

function makeWebTransportError(message, { source = 'stream', streamErrorCode = null } = {}) {
  try {
    const e = new WebTransportError(message, { source, streamErrorCode });
    if (e.message === message && e.source === source) return e;   // standard form honoured
  } catch {}                                                     // legacy-only Chromium: TypeError
  const init = { message };
  if (streamErrorCode !== null) init.streamErrorCode = streamErrorCode;
  return new WebTransportError(init);                            // legacy overload
}

why the legacy overload exists

Chromium shipped new WebTransportError({message, streamErrorCode}) before the spec settled on (message, options). Removing it would break deployed code, so Chromium keeps it — with a UseCounter (WebTransportErrorLegacyConstructor) to measure use before any future deprecation. The cost is visible in rows 4–6 and 9: an object or null first argument means something different in Chromium than in a spec-only engine. Pass a string message and an options object and every engine agrees.
