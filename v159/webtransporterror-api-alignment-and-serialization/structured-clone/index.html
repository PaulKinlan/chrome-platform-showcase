v159 · webtransport · serialization

Structured clone across every channel

The spec makes WebTransportError a serializable object. It runs the DOMException serialization steps, then copies [[Source]] and [[StreamErrorCode]]. Older Chromium did not, so any attempt to send one to a worker, a MessagePort or IndexedDB threw DataCloneError. This page sends one error through five real channels and checks what arrives at the other end. A plain DOMException is sent the same way as a control, which shows each channel works for errors in general, so a failure on the WebTransportError row must come from that type.

Chrome 159 serializes by default. ChromeStatus says the writer side has a runtime kill switch (WebTransportErrorSerialization), while reading a serialized error stays permanently enabled so values already stored in IndexedDB can still be read. On a build without serialization, every WebTransportError row reports the real DataCloneError.

const e = new WebTransportError("reset", { source: "stream", streamErrorCode: 4096 });

structuredClone(e);                    // WebTransportError, fields intact
worker.postMessage(e);                 // arrives as a WebTransportError
port.postMessage(e);                   // MessageChannel, same
new BroadcastChannel("x").postMessage(e);
idbStore.put(e, "last-error");         // persisted, readable later

// Before Chrome 159, each of these threw DataCloneError.
