Two constructor forms, one error

The spec constructor is new WebTransportError(message, options), the same shape as new DOMException(message, name), with options.source ("stream" or "session") and a nullable options.streamErrorCode. Chromium shipped an older form that takes a single dictionary, {message, streamErrorCode}, and has no way to set source. Chrome 159 adds the standard form and keeps the old one so existing code still works. Build an error either way below and inspect what you get.

Chrome 159 enables the standard constructor by default. ChromeStatus lists chrome://flags/#enable-experimental-web-platform-features for developer trials. On a build without it, the standard form throws a TypeError (the string is not a dictionary), and this page shows that error rather than hiding it.

// Standard (Chrome 159+, Firefox, Safari):
const e = new WebTransportError("Upload rejected", {
  source: "stream",          // default "stream"
  streamErrorCode: 4096,     // unsigned long, or null (the default)
});
e.name;              // "WebTransportError"
e.code;              // 0 (no legacy DOMException code)
e instanceof DOMException;  // true

// Legacy Chromium form, still accepted:
new WebTransportError({ message: "Upload rejected", streamErrorCode: 7 });
// source is always "stream" here; there is no member to set it
