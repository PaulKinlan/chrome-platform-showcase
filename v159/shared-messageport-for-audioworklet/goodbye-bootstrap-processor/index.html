v159 · webaudio · audioworklet

Two routes to the same thread

The same worklet module answers on both channels. The old route needs a registered AudioWorkletProcessor, a constructed AudioWorkletNode, and that node's per-node port — three objects to deliver one message. The new route is audioWorklet.port: zero extra objects. Run both and compare what had to exist.

The old route works on every AudioWorklet-capable browser, so this page is fully interactive even pre-159. The new route needs Chrome 159 or --enable-blink-features=AudioWorkletSharedPort — when it's missing, its lane says so instead of pretending.

// OLD — a processor and node exist only to carry messages:

const node = new AudioWorkletNode(ctx, "bootstrap-echo");
node.port.onmessage = handle;

// NEW — the channel is already there:
ctx.audioWorklet.port.onmessage = handle;
ctx.audioWorklet.port.postMessage("ping");
