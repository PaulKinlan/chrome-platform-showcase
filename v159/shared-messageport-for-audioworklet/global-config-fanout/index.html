One message, every processor

The practical case: scope-level state. Three config-gain processor instances all read one module-global config object. A single message on the shared port updates it — no per-node fan-out loop, no N ports. The proof is rendered, not claimed: an OfflineAudioContext renders a constant signal through the three nodes and reports the output level, before and after the broadcast.

Needs Chrome 159 or --enable-blink-features=AudioWorkletSharedPort. Without the shared port, the baseline render still runs (the processors just keep their default gain: 1) and the broadcast step reports that it had no channel — the level simply, and honestly, does not change.

// worklet.js — ONE handler, read by EVERY processor instance
let config = { gain: 1 };
port.onmessage = (e) => { config = { ...config, ...e.data };
                          port.postMessage({ applied: config }); };

// main thread — one message instead of node1.port, node2.port, node3.port…
ctx.audioWorklet.port.postMessage({ gain: 0.25 });
await ack;                       // wait for {applied} before rendering
