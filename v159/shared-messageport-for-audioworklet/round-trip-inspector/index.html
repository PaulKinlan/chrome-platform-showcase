Round-trip inspector

An inspection bench for the two channels into the audio rendering thread: the new context-wide audioWorklet.port ⇄ AudioWorkletGlobalScope.port, and the long-standing per-node AudioWorkletNode.port ⇄ AudioWorkletProcessor.port. Fire a burst of echoes down each, see every message, and compare the measured round-trip times in this browser.

Flag-gated in Chrome. The members are [RuntimeEnabled=AudioWorkletSharedPort] in Blink (status experimental; ChromeStatus: proposed for Chrome 159, already shipped in Firefox 138). To try the real path in a Chrome build that contains the implementation: enable chrome://flags/#enable-experimental-web-platform-features and relaunch, or launch with --enable-blink-features=AudioWorkletSharedPort (or --enable-features=AudioWorkletSharedPort, or --enable-experimental-web-platform-features). Chrome for Testing 153 does not contain the attribute even with those switches (verified) — use a current Canary. Without it, this page says so and runs the labelled old pattern instead.

    how to read it

    Both channels are ordinary MessagePorts posting structured clones to the same rendering thread, so similar latency is the expected result — the win is not speed but not having to own a node to talk to the scope. Numbers are this device's real timings (performance.now() on send, echoed back); large payloads show the structured-clone cost, which is identical on both channels. The node arm exists everywhere AudioWorklet does; the shared arm is reported as unavailable where the attribute is missing — never estimated.
