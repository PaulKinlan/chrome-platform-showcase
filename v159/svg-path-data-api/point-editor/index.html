Point editor

The bread-and-butter job the old SVGPathSegList used to do: drag (or arrow-key) a point, and the page reads getPathData(), changes one number in one plain object, and writes it back with setPathData(). No string parsing, no serializer — the browser re-serializes the d attribute itself, and you can watch exactly what it writes.

Behind a flag. Blink runtime feature SVGPathDataAPI (status experimental). To edit natively:
  1. enable chrome://flags/#enable-experimental-web-platform-features and relaunch, or
  2. launch Chrome with --enable-blink-features=SVGPathDataAPI.
Without it the editor still works, but every write goes through a labelled JavaScript fallback (parse + setAttribute('d')), and the mode line says so.

    handle.addEventListener('pointermove', (e) => {
  const segs = path.getPathData();          // fresh plain objects each call
  segs[i].values[j] = x; segs[i].values[j + 1] = y;
  path.setPathData(segs);                   // browser writes d for you
});
// Make every point absolute (and every curve a cubic) in one line:
path.setPathData(path.getPathData({ normalize: true }));
