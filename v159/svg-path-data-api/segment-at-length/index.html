Segment at length

path.getPathSegmentAtLength(distance) answers "which segment is this far along the path?" — the missing piece next to getTotalLength() and getPointAtLength() for scrubbers, progress-along-a-route UIs and hover-to-highlight editors. Scrub the slider or hover the path; the page asks the native method and, separately, computes a clearly labelled script answer so the two can be compared.

Behind a flag — and newer than its siblings. getPathSegmentAtLength() is gated by the same Blink runtime feature SVGPathDataAPI (status experimental; enable chrome://flags/#enable-experimental-web-platform-features or launch with --enable-blink-features=SVGPathDataAPI), but it landed in Chromium after getPathData()/setPathData(). Chrome 153 with the flag exposes the first two and not this one — so this page probes each method independently and never labels the script answer as native.

    The explainer documents clamping (negative → first segment, past the end → last segment) and null for an empty path. Chromium's current IDL types the argument as a restricted float, under which WebIDL rejects NaN with a TypeError; the explainer's sketch says unrestricted float returning null. This page does not predict — it shows what your build actually does.
