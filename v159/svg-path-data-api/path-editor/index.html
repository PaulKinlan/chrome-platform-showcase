Edit segments, not strings

The write half of the API. This wave shape is a M plus two cubic C segments; each slider edits one number in one segment's values array, and every change round-trips through the real setPathData() — read the current data, mutate one value, write the array back. No string splicing, no reparsing, no precision loss.

Needs the Chrome 159 API (flag: --enable-blink-features=SVGPathDataAPI, see the feature page). Without it the sliders stay functional but the page switches to a clearly-labelled attribute-string fallback path — it tells you on every edit that setPathData() was not used, so the new surface is never faked.

What the element now holds

After each write, the page reads the d attribute back from the live element — on a supporting build this is the serialisation setPathData() produced.

code path

const data = path.getPathData();        // [{type:"M",…}, {type:"C",…}, {type:"C",…}]
data[1].values[1] = crest;              // first control point y
data[1].values[3] = crest;              // second control point y
path.setPathData(data);                 // structured write-back — no string surgery
