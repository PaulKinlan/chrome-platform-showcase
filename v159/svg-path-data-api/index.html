SVG Path Data API

Structured JavaScript access to SVG path data, at last. Three methods on SVGPathElement: getPathData() reads the path as an array of {type, values} segment objects (optionally normalised to absolute M/L/C/Z commands), setPathData() writes such an array back, and getPathSegmentAtLength() returns the index of the segment at a given distance along the path — no more hand-parsing the d attribute with regexes.

concepts

  1. Path inspector — paste any d string, render it, and read it back through getPathData() as a live segment table — with the {normalize: true} option as a toggle so you can watch arcs and relative commands reduce to absolute M/L/C/Z.
  2. Path editor — the write half: sliders bound to individual segment values feed setPathData() and morph a rendered shape in place, round-tripping through the structured representation instead of string surgery on d.
  3. Point along path — drag a distance slider and getPathSegmentAtLength() names the segment under the marker (drawn with the long-shipped getPointAtLength() for contrast), including the boundary behaviour at zero, segment joins, and beyond the total length.

why it shipped

The old SVGPathSegList interface was removed from the SVG spec (and from Chrome in 48) with the promise of something better; for a decade the gap was filled by the path-data-polyfill and ad-hoc d-attribute parsers. The W3C SVG paths spec defines this replacement, Edge's explainer pushed it forward, and Chrome 159 ships it: inspect, edit, and construct paths as data.
