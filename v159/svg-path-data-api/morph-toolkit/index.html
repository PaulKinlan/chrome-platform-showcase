Morph toolkit: interpolation on normalized cubics

Path morphing is the use case that kept crbug 40441025 alive for ten years: to interpolate two paths you need them as numbers, in the same command vocabulary. getPathData({normalize: true}) does both jobs at once — everything becomes absolute M/L/C/Z — and setPathData() writes each interpolated frame back without a single string parse in the hot loop.

Chrome targets the SVG Path Data API for Chrome 159 behind the SVGPathDataAPI runtime flag. On an earlier or unflagged build, launch with --enable-blink-features=SVGPathDataAPI, or flip chrome://flags/#enable-experimental-web-platform-features and relaunch.

how the toolkit works

Both endpoint paths are read with getPathData({normalize: true}), so each becomes a list of absolute M/L/C/Z segments. Every L is then promoted to an equivalent C (control points placed at thirds along the line — geometrically identical), and the shorter list is padded with degenerate cubics that sit on its final point until the counts match. From there, morphing is pure arithmetic: value = a + (b − a) · t for every number, and one setPathData() per frame.

const A = pathA.getPathData({ normalize: true });  // M/L/C/Z only
const B = pathB.getPathData({ normalize: true });
const [fromSegs, toSegs] = matchCubics(A, B);       // same length, same types

function frame(t) {
  stage.setPathData(fromSegs.map((seg, i) => ({
    type: seg.type,
    values: seg.values.map((v, j) => v + (toSegs[i].values[j] - v) * t),
  })));
}
