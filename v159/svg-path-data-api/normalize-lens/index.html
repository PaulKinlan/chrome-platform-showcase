Normalize lens: twenty commands in, four out

SVG paths speak twenty commands; interpolation code wants four. getPathData({normalize: true}) is the built-in converter: relative becomes absolute, H/V become L, quadratics and smooth shorthands become exact cubics, arcs become approximated cubics — and what comes out is only ever absolute M, L, C, Z. Read the same path both ways below: the command tables diverge, the two renderings must not.

Chrome targets the SVG Path Data API for Chrome 159 behind the SVGPathDataAPI runtime flag. On an earlier or unflagged build, launch with --enable-blink-features=SVGPathDataAPI, or flip chrome://flags/#enable-experimental-web-platform-features and relaunch.

Pick a sample to read it both ways.

code path

const raw = path.getPathData();
// "M 10 60 h 40 q 20 -40 40 0 …"  →  M, h, q, a, Z — exactly as authored

const flat = path.getPathData({ normalize: true });
// → absolute M, L, C, Z only:
//   h 40          →  L [50, 60]
//   q 20 -40 40 0 →  C [63.33, 33.33, 76.67, 33.33, 90, 60]   (exact)
//   a 10 10 …     →  C …                                       (approximated)

// Both arrays describe the same geometry — feed `flat` to interpolation code
// that only wants to handle four command types.
