v159 · webtransport · getStats() edge cases

getStats() across connecting, failed and closed

The spec gives getStats() a different answer in each session state. While connecting, the promise waits until the state changes. Once failed, it rejects with InvalidStateError. Once closed, it resolves with the last stats collected, so you can still read a post-mortem after the session ends. The first two runs below need no server: they use a port with nothing listening, which is a real failure (Chrome logs its own "Failed to establish a connection" line in the console for it). The third needs a session you can actually open.

Needs WebTransport.prototype.getStats: Chrome 159, or chrome://flags/#enable-experimental-web-platform-features / --enable-blink-features=WebTransportStats on earlier builds. Runs 1 and 2 work on any network. Run 3 needs an HTTP/3 WebTransport server reachable over UDP (run one locally).

Run 1 · call while connecting, to a session that will fail

Construct a transport to https://127.0.0.1:44443/never and call getStats() on the same tick. The spec says the promise must not settle until the state leaves "connecting", and must then reject with InvalidStateError. The timings show which happened first.

code path

const t = new WebTransport(url);
const early = t.getStats();      // waits while "connecting"

try { await t.ready; } catch {
  await early;                   // rejects: InvalidStateError
  await t.getStats();            // rejects: InvalidStateError
}

t.close();
await t.closed;
const last = await t.getStats(); // resolves: most recent stats
