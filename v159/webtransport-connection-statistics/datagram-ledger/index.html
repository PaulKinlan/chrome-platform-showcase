Datagram ledger: make expiry happen, then count it

Datagrams are allowed to die — that is the point of them. getStats().datagrams is the ledger of how they died: expiredOutgoing (older than outgoingMaxAge before they could be sent), lostOutgoing (sent, then declared lost per RFC 9002 §6.1), droppedIncoming (arrived faster than the app read them), and expiredIncoming (older than incomingMaxAge before being read). This page sets a deliberately tight outgoingMaxAge, queues a burst, and diffs two real snapshots.

Chrome targets WebTransport.getStats() for Chrome 159 behind the WebTransportStats runtime flag (--enable-blink-features=WebTransportStats, or chrome://flags/#enable-experimental-web-platform-features). The ledger needs an established session — that is the spec, not a limitation of this page — so connect to an endpoint you can reach first. Networks that block UDP/QUIC will fail the connection with the real error shown.

code path

const transport = new WebTransport(url);
await transport.ready;

transport.datagrams.outgoingMaxAge = 1; // ms — tight on purpose

const before = (await transport.getStats()).datagrams;

const writer = transport.datagrams.writable.getWriter();
for (let i = 0; i < 200; i++) writer.write(new Uint8Array(1024)); // no await
await new Promise((r) => setTimeout(r, 250)); // let the queue age out

const after = (await transport.getStats()).datagrams;
after.expiredOutgoing - before.expiredOutgoing; // what never made it out
