v159 · webtransport · connection stats

Live stats monitor: poll a real session once a second

The loop the feature was shipped for: connect, then call getStats() on an interval and watch the connection describe itself — the RFC 9002 RTT trio, the estimatedSendRate when one is available, and atSendCapacity. A keepalive datagram per tick gives the estimator real traffic to work with. Every value in the table is read off a real resolved stats object; nothing is simulated.

Chrome targets WebTransport.getStats() for Chrome 159 behind the WebTransportStats runtime flag (--enable-blink-features=WebTransportStats, or chrome://flags/#enable-experimental-web-platform-features). The monitor needs a reachable HTTP/3 WebTransport endpoint; the default is a public echo server. Corporate proxies, container networks, and some VPNs block the UDP/QUIC packets WebTransport rides on — if the connection fails here, the real error is shown and that is the honest outcome, not a page bug.

code path

const transport = new WebTransport(url);
await transport.ready;

const timer = setInterval(async () => {
  const stats = await transport.getStats();
  render(stats.minRtt, stats.smoothedRtt, stats.rttVariation,
         stats.estimatedSendRate, stats.atSendCapacity);
}, 1000);

// optional traffic so the rate estimator has something to chew on:
const writer = transport.datagrams.writable.getWriter();
await writer.write(new Uint8Array(64));
