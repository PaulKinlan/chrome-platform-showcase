Closed & failed connections

The getStats() algorithm has three branches that are easy to miss. A failed connection rejects with InvalidStateError, and that includes a call made while the connection was still trying. A call made while connecting waits for the outcome. A closed connection still resolves, with the most recent stats. The first two experiments need no server. They open a connection that is certain to fail and record what really happens.

Behind a flag in Chrome 153–158. WebTransport.prototype.getStats is gated by Blink's WebTransportStats runtime feature (status: "experimental"; ChromeStatus targets Chrome 159 for desktop, Android and WebView). To try it now: open chrome://flags/#enable-experimental-web-platform-features, set it to Enabled and relaunch — or start Chrome with --enable-blink-features=WebTransportStats. There is no dedicated chrome://flags entry for the stats method itself. Reading statistics also needs a live HTTP/3 WebTransport session, which this site cannot host: use a public echo server or run your own (instructions on the feature page). Every number on this page comes from a real getStats() call — nothing is simulated.

the defensive helper

async function readStats(wt) {
  if (typeof wt.getStats !== "function") return { supported: false };
  try {
    const s = await wt.getStats();
    return {
      supported: true,
      rttMs: typeof s.smoothedRtt === "number" ? s.smoothedRtt : undefined,   // absent until sampled
      sendBps: s.estimatedSendRate ?? undefined,                               // null = no estimate
      bytesSent: Object.hasOwn(s, "bytesSent") ? s.bytesSent : undefined,      // Chromium: absent
      datagrams: s.datagrams,
    };
  } catch (e) {
    return { supported: true, error: e.name };   // InvalidStateError: handshake failed
  }
}
