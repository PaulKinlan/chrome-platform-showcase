WebTransport connection statistics

WebTransport.getStats() returns an asynchronous snapshot of an existing connection's health. It reports round-trip time (smoothedRtt, rttVariation, minRtt, in milliseconds) when QUIC has a sample, an estimatedSendRate in bits per second (or null), and datagrams counters for dropped, expired and lost datagrams. The last snapshot stays readable after the connection closes. Chromium does not expose the spec's byte and packet totals.

How to try it today: the method is gated by Blink's WebTransportStats runtime feature, status: "experimental" in runtime_enabled_features.json5. ChromeStatus targets Chrome 159 for desktop, Android and WebView. Enable chrome://flags/#enable-experimental-web-platform-features and relaunch, or start Chrome with --enable-blink-features=WebTransportStats. Both were tested on Chrome 153, and both expose the method. There is no dedicated chrome://flags entry for it. You also need a live HTTP/3 WebTransport server, which this site cannot host (Deno Deploy serves TCP only). Use a public echo server or run your own. Every demo checks for the method itself and labels its fallback.

concepts

  1. Stats field inspector

    Basic: connect, call getStats(), and check every spec member against the dictionary you got back. Each one is marked returned, null or not returned, next to whether Chromium's IDL declares it. This makes the missing bytesSent/packetsSent totals and atSendCapacity visible, not assumed.

  2. Live stats dashboard

    Inspection tooling: a polling health panel with an interval selector, Start/Stop (an in-flight result after Stop is discarded), pause-while-hidden, RTT and send-rate sparklines with a text table alternative, and the change in each datagram counter since polling started. A burst button generates real traffic.

  3. Adaptive quality controller

    Practical: a bitrate-ladder controller that sizes its budget from estimatedSendRate, steps down on queueing delay (smoothedRtt − minRtt) or new lostOutgoing, and steps up only after a run of healthy snapshots. Three inputs, each labelled: live stats, a recorded real Chrome trace, or what-if numbers you type in.

  4. Closed & failed connections

    Edge cases with no server: getStats() called while a doomed connection is still connecting, and again after it failed. Both reject with InvalidStateError. Also a constructor that refuses a non-https URL, and a defensive cross-browser helper. With a server: stats after close(), the same members in every call within a session, and concurrent calls.

  5. Datagram expiry lab

    Configuration plus composition: inspect and set incomingMaxAge, outgoingMaxAge and the *MaxBufferedDatagrams knobs, and compare 20 edge values against the editor's draft (no server needed). Then overflow the receive queue, age incoming datagrams out, and flood with a tiny outgoingMaxAge, watching the matching counter.

why it shipped

Applications built on WebTransport, such as game netcode, live media and telemetry uplinks, need to tell network latency, congestion and datagram loss or expiry apart from slowness in their own code. Without stats they had to infer all of it from application-level pings. ChromeStatus frames getStats() as one asynchronous call that reads the existing connection's health so a page can adapt how it sends. It creates no connection and changes nothing about transmission. Firefox shipped getStats() in 158. Safari 27.2 exposes the method but returns default-initialised values. WebTransport is an Interop 2026 focus area, and the returned fields differ between engines. That is why every demo here checks each member and never assumes it is there.

the API surface

// Chromium: web_transport.idl
[CallWith=ScriptState, RuntimeEnabled=WebTransportStats]
Promise<WebTransportConnectionStats> getStats();

// Chromium: web_transport_connection_stats.idl
dictionary WebTransportConnectionStats {
  DOMHighResTimeStamp smoothedRtt;          // ms, absent until QUIC has an RTT sample
  DOMHighResTimeStamp rttVariation;
  DOMHighResTimeStamp minRtt;
  required WebTransportDatagramStats datagrams;
  unsigned long long? estimatedSendRate = null;   // bit/s
};
// The W3C dictionary also has bytesSent, bytesSentOverhead, bytesAcknowledged, packetsSent,
// bytesLost, packetsLost, bytesReceived, packetsReceived and atSendCapacity. Chromium omits them.

dictionary WebTransportDatagramStats {
  unsigned long long droppedIncoming;   // receive queue overflowed (incomingMaxBufferedDatagrams)
  unsigned long long expiredIncoming;   // older than datagrams.incomingMaxAge before being read
  unsigned long long expiredOutgoing;   // older than datagrams.outgoingMaxAge before being sent
  unsigned long long lostOutgoing;      // declared lost per RFC 9002 §6.1
};

const wt = new WebTransport("https://example.com:4433/echo");
await wt.ready;
const { smoothedRtt, estimatedSendRate, datagrams } = await wt.getStats();

run your own echo server (Deno)

The demos were verified against this server, running locally. Deno 2.9 has Deno.QuicEndpoint and Deno.upgradeWebTransport behind --unstable-net. Chrome accepts a self-signed certificate only through serverCertificateHashes: ECDSA P-256, valid for at most 14 days. Paste the printed hash into a demo's serverCertificateHashes field. From this public https site, Chrome may also ask for permission before it lets the page reach 127.0.0.1 (Local Network Access). Running the showcase locally avoids that.

openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes \
  -keyout key.pem -out cert.pem -days 10 -subj "/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
openssl x509 -in cert.pem -outform der | openssl dgst -sha256 -binary | base64   # → the hash

// echo.ts — deno run --unstable-net --allow-net --allow-read echo.ts
const endpoint = new Deno.QuicEndpoint({ hostname: "127.0.0.1", port: 4433 });
const listener = endpoint.listen({
  cert: Deno.readTextFileSync("cert.pem"), key: Deno.readTextFileSync("key.pem"),
  alpnProtocols: ["h3"],
});
for await (const incoming of listener) {
  (async () => {
    const wt = await Deno.upgradeWebTransport(await incoming.accept());
    await wt.ready;
    const r = wt.datagrams.readable.getReader(), w = wt.datagrams.writable.getWriter();
    for (;;) { const { value, done } = await r.read(); if (done) break; await w.write(value); }
  })().catch(() => {});
}

Then use the URL https://127.0.0.1:4433/echo. The public servers offered by default, wt-ord.akaleapi.net and wt-ams.akaleapi.net on port 6161, are the ones Microsoft's webtransport-getstats sample uses. Whether you can reach them depends on your network allowing UDP/QUIC.
