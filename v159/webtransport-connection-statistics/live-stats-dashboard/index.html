Live stats dashboard

The spec calls getStats() results snapshots: nothing updates on its own. A connection-health panel has to poll. This one runs getStats() on an interval you choose, plots smoothedRtt against minRtt and the estimatedSendRate trend, and tracks how much each datagram counter has grown. It stops right away when you press Stop, and pauses while the tab is hidden.

Behind a flag in Chrome 153–158. WebTransport.prototype.getStats is gated by Blink's WebTransportStats runtime feature (status: "experimental"; ChromeStatus targets Chrome 159 for desktop, Android and WebView). To try it now: open chrome://flags/#enable-experimental-web-platform-features, set it to Enabled and relaunch — or start Chrome with --enable-blink-features=WebTransportStats. There is no dedicated chrome://flags entry for the stats method itself. Reading statistics also needs a live HTTP/3 WebTransport session, which this site cannot host: use a public echo server or run your own (instructions on the feature page). Every number on this page comes from a real getStats() call — nothing is simulated.

what to look for

On an idle connection the RTT values and the send-rate estimate often stay the same from call to call. QUIC updates them only when acknowledgements arrive, and an idle session sends almost nothing. Press Send burst while polling and the estimate moves. If the server echoes faster than this page reads, droppedIncoming goes up. The datagram counters only ever grow, so the dashboard shows each one's change since polling started. A Chromium source comment warns that the send-rate estimate is poor unless the BBR congestion controller is in use. Treat it as a trend, not a measured throughput.

the code

let timer, generation = 0;
async function poll(wt, gen) {
  const s = await wt.getStats();          // one snapshot
  if (gen !== generation) return;         // Stop pressed meanwhile: drop it
  render(s);
  timer = setTimeout(() => poll(wt, gen), intervalMs);
}
start = () => poll(wt, ++generation);
stop  = () => { generation++; clearTimeout(timer); };
