The connection's own vital signs

The practical loop: connect to a real WebTransport server, push a little datagram traffic so there is something to measure, and poll getStats() once a second into a dashboard — RTT trio, estimated send rate, and the datagram loss ledger. Every number on screen is a value the browser's QUIC stack measured; nothing is synthesised.

Needs Chrome 159 (or --enable-blink-features=WebTransportStats) and a reachable WebTransport server — this showcase's own host cannot terminate QUIC/HTTP3, so the default target is the Edge team's public echo server. Corporate proxies and firewalls commonly block UDP/443; a connection failure here is reported as exactly that, never as missing API support.

code path

const wt = new WebTransport(url);
await wt.ready;

const writer = wt.datagrams.writable.getWriter();
setInterval(async () => {
  const s = await wt.getStats();
  render(s.minRtt, s.smoothedRtt, s.rttVariation,
         s.estimatedSendRate,              // null without a BBR estimate
         s.datagrams.lostOutgoing);
}, 1000);
