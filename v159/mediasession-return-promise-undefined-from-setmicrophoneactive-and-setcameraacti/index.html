MediaSession: Return Promise<undefined> from setMicrophoneActive() and setCameraActive()

navigator.mediaSession.setMicrophoneActive() and setCameraActive() — the calls a video-conferencing page uses to tell the browser whether its mic and camera are live — now return a Promise<undefined> instead of undefined, matching the W3C Media Session spec. In a fully active document the promise resolves with undefined; if the document is not fully active it is rejected with an InvalidStateError. The change lets user agents apply capture-pause policies or ask the user asynchronously, and fixes four WPT idlharness subtests.

No flag to flip. The IDL change in media_session.idl is unconditional (no runtime_enabled_features.json5 entry, no Finch name): Chrome 158 and earlier return undefined, Chrome 159+ returns a promise. Safari 18.4+ already ships the promise; Firefox is positive. Every concept below calls the real methods and labels which shape it observed.

concepts

  1. Return-shape probe

    The exact contract: call both methods for real and inspect the return value — typeof, thenable or not, and how it settles. Also shows why a property check cannot tell (length and toString() are unchanged).

  2. Video-call controls

    The practical product: a real getUserMedia call with mute/camera toggles and togglemicrophone / togglecamera / hangup action handlers. Every toggle awaits the browser's promise, rolls back the track on rejection, and logs the raw outcome.

  3. Detached-document rejection

    The failure path the new return type makes observable: keep an iframe's navigator.mediaSession, remove or navigate the iframe, and call again. The spec requires a promise rejected with InvalidStateError; older Chrome silently returns undefined.

  4. Migration patterns

    Compatibility audit: six real calling patterns — fire-and-forget, await, direct .then(), Promise.resolve() wrapping, and synchronous vs awaited try/catch around an argument error — run against this browser, with which break on the old and new shapes.

why it changed

The methods shipped in Chrome 93 with a void return. The spec was later changed (w3c/mediasession#312) so that a user agent can take time to apply the new state — for example a capture-pause policy, or prompting the user before un-muting — and tell the page when it is done, or that it failed. Chromium's implementation still resolves immediately after forwarding the state to the browser process; what changes for pages is the return shape, the InvalidStateError rejection, and that argument errors now arrive as rejections rather than synchronous throws.

use-case portfolio

  • Basic / canonical and inspection — return-shape-probe.
  • Practical product use — video-call-controls.
  • Edge / failure — detached-document (removed and navigated iframes).
  • Migration — migration-patterns.
  • Advanced composition — video-call-controls composes the promise with getUserMedia track state and browser-UI action handlers. No separate page: the change adds no new capability beyond the return value, and the remaining composition (Document Picture-in-Picture call windows) would exercise the same two calls from another document.

the surface

partial interface MediaSession {
  Promise<undefined> setMicrophoneActive(boolean active);
  Promise<undefined> setCameraActive(boolean active);
};

try {
  await navigator.mediaSession.setMicrophoneActive(false);   // works on old and new
} catch (e) {
  if (e.name === 'InvalidStateError') { /* document not fully active */ }
}
