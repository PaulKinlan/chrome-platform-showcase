MediaSession: Return Promise<undefined> from setMicrophoneActive() and setCameraActive()

Chrome 159 aligns navigator.mediaSession.setMicrophoneActive() and setCameraActive() with the W3C Media Session spec: they now return a Promise<undefined> instead of undefined. In a fully active document the promise resolves with undefined; in a document that is not fully active it rejects with an InvalidStateError DOMException — a state video-conferencing pages can finally observe instead of guessing.

concepts

  1. Return-value probe — call both methods for real and inspect what this build actually hands back: legacy undefined, or the new promise, settled and timed. Includes the one-line migration pattern that is safe on both.
  2. Conference controls — the API's home turf: mic/cam toggle buttons that publish their state through setMicrophoneActive() / setCameraActive() with promise-aware error handling, plus the matching togglemicrophone / togglecamera action handlers the OS media UI calls back into.
  3. Not fully active — the rejection branch: grab a same-origin iframe's mediaSession, detach the iframe so its document stops being fully active, call the methods, and observe the InvalidStateError rejection the spec promises (or this build's actual legacy behaviour, reported honestly).

why it shipped

The W3C Media Session spec (via PR #312) defines both capture-state setters as promise-returning so pages learn whether the user agent accepted the state change. Chromium shipped them early, returning undefined — code written against the spec (await navigator.mediaSession.setMicrophoneActive(true)) still worked by accident, but rejection handling silently never ran. Chrome 159 returns the real promise, and with it the spec's not-fully-active InvalidStateError.
