MediaSession: Return Promise<undefined> from setMicrophoneActive() and setCameraActive()

Since Chrome 93, navigator.mediaSession.setMicrophoneActive(active) and setCameraActive(active) have told the browser whether a video-call page considers its mic and camera live — so the browser's media controls and capture indicators match the call's mute state. Their WebIDL return type was void. The W3C Media Session spec (PR #312) changed both to return Promise<undefined>, so a user agent can apply a capture pause policy, prompt asynchronously, or refuse an unmute. In Chrome 159 the promise resolves with undefined in a fully active document and is rejected with InvalidStateError when the document is not fully active (for example a detached iframe). Every demo below shows the value your browser really returns.

No flag to flip. This is an unflagged WebIDL signature change: Chromium's media_session.idl declares Promise<undefined> setMicrophoneActive(boolean active) with no RuntimeEnabled gate, and runtime_enabled_features.json5 has only the long-stable MediaSession entry. Chrome 158 and earlier return undefined; Chrome 159+ returns a promise. Safari 18.4+ already returns a promise. The pages detect the shape at run time and label which world you are in.

concepts

  1. Return-shape inspector

    Canonical call plus inspection tool: call each method with true/false and see the raw return value dissected — typeof, instanceof Promise, its [[Class]] tag, whether it is thenable, what it settles to and how long that took. A probe that can, and on Chrome 158 does, say "not a promise".

  2. Video-call controls in sync with the browser

    The practical product case: a call bar with mic, camera and hang-up toggles that awaits each setXActive() before committing its state, registers the togglemicrophone, togglecamera and hangup action handlers (each probed with try/catch, alongside spec-only actions your browser may reject), reverts on a rejection, and optionally drives real capture tracks after you opt in.

  3. Not-fully-active document & WebIDL errors

    Edge and failure behaviour: capture an iframe's navigator.mediaSession, detach the iframe, then call it — the new contract is a promise rejected with InvalidStateError; the old one silently returned undefined. Plus the WebIDL rule that a promise-returning operation turns a missing argument or an illegal receiver into a rejected promise instead of a synchronous TypeError.

  4. Migration: what breaks, and a wrapper that works on both

    Run six common calling patterns — .then(), .catch(), await, Promise.resolve(), an async wrapper, fire-and-forget — against your live browser and against labelled reference models of the old and new shapes, and see exactly which pattern throws TypeError: Cannot read properties of undefined on Chrome 158.

  5. Capture pause-policy lab

    Advanced composition with real capture: opt in to getUserMedia(), then await setMicrophoneActive(false) and read the tracks' muted state and mute/unmute event timeline against the promise's settle time — the ordering the promise exists to give you. Includes the spec's "may reject an unmute while hidden" case with a delayed call you can background the tab for.

why it shipped

When the two methods shipped in Chrome 93 they were fire-and-forget. The spec was then revised (w3c/mediasession PR #312) to run an update capture state algorithm that can be asynchronous: a user agent that pauses all inputs of a kind from its own UI may need to prompt before an unmute, may require visibility or activation, and may reject with NotAllowedError; only after that does it update the capture UI and mute/unmute the matching MediaStreamTracks. A promise is the only way to tell the page when — and whether — that happened. Chromium aligns with the spec (fixing 4 failing subtests in WPT mediasession/idlharness.window.html) and with Safari 18.4; Firefox's position is positive. Compat risk is low because a fire-and-forget caller in a live document never sees a rejection; code that chains on the old undefined was already broken.

the exact API surface

// W3C Media Session (current) — and Chromium media_session.idl from M159
partial interface MediaSession {
  Promise<undefined> setMicrophoneActive(boolean active);
  Promise<undefined> setCameraActive(boolean active);
  // spec-only so far (not in Chromium's IDL):
  // Promise<undefined> setScreenshareActive(boolean active);
};

// update capture state(document, active, captureKind):
//   document not fully active        → promise rejected with InvalidStateError
//   active && document not "visible"  → MAY reject with InvalidStateError
//   UA denies (e.g. prompt declined) → reject with NotAllowedError
//   otherwise update capture UI, resolve with undefined, (pause policy) set track muted

// Works on both the old (undefined) and new (Promise) shapes:
async function setMicActive(active) {
  await navigator.mediaSession.setMicrophoneActive(active); // awaiting undefined is fine
}
