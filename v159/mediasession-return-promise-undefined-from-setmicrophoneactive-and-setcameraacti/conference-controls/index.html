Mute buttons the OS can trust

The setters exist so conferencing pages can publish their real capture state to the browser and OS media UI — and, from Chrome 159, learn via the returned promise whether that publication was accepted. These toggles run the full loop: flip local state, publish through setMicrophoneActive() / setCameraActive() with promise-aware handling, and register the togglemicrophone / togglecamera action handlers the platform calls back into.

No microphone or camera is opened here — the Media Session capture-state surface is about declaring state, so the demo is permission-free by design. On a pre-159 build the publish succeeds silently (legacy undefined return); the log labels which path actually ran.

The callback surface

The other half of the contract: when the user mutes from the OS media controls, the browser fires your togglemicrophone / togglecamera action handler. Registration below is real — the simulate buttons invoke the same registered handler functions so you can watch the loop close without OS chrome.

async function setMicUI(active) {
  ui.update(active);                       // optimistic local flip
  try {
    await Promise.resolve(navigator.mediaSession.setMicrophoneActive(active));
    log("published, accepted");            // 159+: really acknowledged
  } catch (err) {
    ui.update(!active);                    // roll back — the UA said no
    log("rejected: " + err.name);
  }
}
navigator.mediaSession.setActionHandler("togglemicrophone", () => setMicUI(!micOn));
