Not-fully-active document & WebIDL errors

The promise is not only about success: it is how a caller learns the call failed. The spec's first step is "if document is not fully active, return a promise rejected with InvalidStateError", and WebIDL says a promise-returning operation converts every exception — a missing argument, an illegal receiver — into a rejected promise rather than a synchronous throw. This page triggers all three for real and prints the raw outcome.

No flag exists. On Chrome 158 and earlier the detached call silently returns undefined (nothing tells you it did nothing) and argument errors throw synchronously; on Chrome 159+ all of them become rejected promises. The iframe used below is a same-origin, empty srcdoc frame — no network, no permissions.

why it matters

A meeting widget embedded in an iframe that is torn down mid-call (single-page navigation, a closed panel) may still hold a reference to its media session. Under the old signature, its "mute on teardown" call was a silent no-op; now it is an observable InvalidStateError — and, if nothing handles it, an unhandled rejection. The third case shows a non-error edge: "no" is a truthy string, so WebIDL converts it to true; the call succeeds and unmutes.

const session = frame.contentWindow.navigator.mediaSession;
frame.remove();                                   // document no longer fully active
try {
  await session.setMicrophoneActive(false);       // ≤158: resolves (awaits undefined)
} catch (e) {
  e.name === 'InvalidStateError';                 // 159+: "The document is not fully active."
}
