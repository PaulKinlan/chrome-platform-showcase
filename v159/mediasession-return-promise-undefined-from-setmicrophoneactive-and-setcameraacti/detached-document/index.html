Detached-document rejection

The new IDL gives the methods a way to fail. Per spec, if the MediaSession's document is not fully active the call returns a promise rejected with InvalidStateError. Before Chrome 159 the same call returned undefined and silently did nothing. This page builds that state for real: it keeps a reference to an iframe's navigator.mediaSession, then removes or navigates the iframe and calls again.

why this matters

Conferencing apps often host the call UI in an iframe (an embedded meeting widget, a third-party SDK). If that frame is torn down or navigates while a toggle is in flight, the old IDL dropped the update on the floor; the app's button and the browser's indicator could disagree with no signal. With a rejected promise the app can catch InvalidStateError, roll back its UI, and re-issue the state from the live document.

const ms = frame.contentWindow.navigator.mediaSession;
frame.remove();
try {
  await ms.setMicrophoneActive(false);
} catch (e) {
  e.name; // "InvalidStateError" — the document is no longer fully active
}
