Migration: what breaks, and a wrapper that works on both

Your users are split across Chrome ≤158 (returns undefined), Chrome 159+ and Safari 18.4+ (returns a promise). Code written for one shape can throw on the other. This matrix runs six real calling patterns against your live browser and against small, clearly labelled reference models of each signature, so you see every outcome no matter which browser you are on.

About the reference models. They are not the browser — they are three-line stand-ins: void model () => undefined; promise model () => Promise.resolve(); not-fully-active model () => Promise.reject(new DOMException(…, 'InvalidStateError')). Only the live row calls navigator.mediaSession.setMicrophoneActive(false). There is no flag that switches the live shape; it depends only on your browser version.

    the recommended wrapper

    An async function normalises every case: a plain undefined becomes a fulfilled promise, a synchronous WebIDL TypeError (old shape) becomes a rejection, and a real rejection (new shape) passes through to your handler instead of becoming an unhandled rejection.

    const capture = {
  async mic(active) { return navigator.mediaSession?.setMicrophoneActive?.(active); },
  async cam(active) { return navigator.mediaSession?.setCameraActive?.(active); },
};
capture.mic(false).catch((e) => console.warn('mic state not applied:', e.name));
