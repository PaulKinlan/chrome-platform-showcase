Migration patterns

Changing a return type from undefined to Promise is "web compatible" only if existing calling code keeps working. Most does — but not all of it. This page runs six real calling patterns against this browser's setMicrophoneActive() and shows which survive on the old shape, which survive on the new one, and which are safe on both.

recommendations

  • Use await (or Promise.resolve(x).then): it works on both shapes, and on 159+ it surfaces InvalidStateError to your catch.
  • Never chain .then() directly on the return value while you still support Chrome ≤158 — it throws TypeError there.
  • Audit synchronous try/catch: argument errors moved from a synchronous throw to a rejected promise, so a catch without await no longer sees them and the rejection goes unhandled.
  • Detect the shape by calling, not by inspecting the function: length and toString() are identical on both.
