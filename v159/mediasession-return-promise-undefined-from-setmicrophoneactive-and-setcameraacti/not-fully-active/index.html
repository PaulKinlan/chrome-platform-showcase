The rejection the promise exists for

The spec's one defined failure: if the associated document is not fully active, the setters return a promise rejected with an InvalidStateError DOMException. A document stops being fully active the moment its iframe is detached — so this page builds a real same-origin iframe, keeps a reference to its navigator.mediaSession, rips the iframe out, and then makes the call.

Before Chrome 159 the same call returns undefined, so there is no promise to reject and the failure is unobservable — which is precisely why the spec wanted a promise here. Whatever this build does, the readout below reports the actual observed behaviour and labels which world it belongs to.

Detach, then call

  1. Create a same-origin <iframe> and wait for it to load.
  2. Capture iframe.contentWindow.navigator.mediaSession.
  3. Remove the iframe — its document is no longer fully active.
  4. Call setMicrophoneActive(true) and setCameraActive(true) on the captured session.

const iframe = document.createElement("iframe");
iframe.src = "about:blank";
document.body.append(iframe);
await new Promise((r) => iframe.addEventListener("load", r, { once: true }));
const session = iframe.contentWindow.navigator.mediaSession;
iframe.remove();                        // document is no longer fully active

try {
  await Promise.resolve(session.setMicrophoneActive(true));
  // pre-159: lands here (undefined return — failure unobservable)
} catch (err) {
  console.assert(err.name === "InvalidStateError"); // 159+: lands here
}
