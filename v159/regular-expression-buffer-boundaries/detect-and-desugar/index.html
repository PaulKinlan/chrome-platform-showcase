Feature-detect and desugar

How to adopt \A, \z and \Z before every engine has them. Detect support with one guarded new RegExp. When the engine lacks them, rewrite the escapes to the spec's RegExp-modifier synonyms, or to lookaround emulation for engines that lack modifiers too. Then prove the spellings are interchangeable: this page runs a corpus of patterns and inputs through each spelling and compares every match position.

Behind a V8 flag until it ships. ChromeStatus lists this feature in the Chrome 159 "Enabled by default" group (Finch V8Flag_js_regexp_buffer_boundaries). It is a V8 feature, with no Blink runtime flag, and --enable-experimental-web-platform-features does not turn it on. To run it today, launch Chrome with --js-flags=--js-regexp-buffer-boundaries (verified in Chrome 153). In builds where V8 marks it staged, chrome://flags/#enable-javascript-harmony turns it on as well. In Chrome 153 that flag does not.

the code

const hasBufferBoundaries = (() => {
  try { new RegExp('\\A', 'u'); return true; } catch { return false; }
})();
const hasModifiers = (() => {
  try { new RegExp('(?-m:^)', 'u'); return true; } catch { return false; }
})();

function compileBoundaryRegExp(source, flags) {
  if (hasBufferBoundaries) return new RegExp(source, flags);
  return new RegExp(desugar(source, flags, hasModifiers ? MODIFIERS : LOOKAROUND), flags);
}
const MODIFIERS  = { A: '(?-m:^)',    z: '(?-m:$)',    Z: '(?=(?:\\r\\n|\\n|\\r|\\u2028|\\u2029)?(?-m:$))' };
const LOOKAROUND = { A: '(?<![^])', z: '(?![^])', Z: '(?=(?:\\r\\n|[\\n\\r\\u2028\\u2029])?(?![^]))' };
// Never write a /\A…/u LITERAL in shipped code until support is universal: it is a parse-time error.
