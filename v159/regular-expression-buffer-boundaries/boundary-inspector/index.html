Boundary inspector

A regex tester built for this one question: where does each anchor fire? Type a pattern, choose flags, and type an input with real \n, \r\n and \u2028 line terminators. The inspector compiles the pattern with this browser's engine and marks every match position in the input. It also compiles the spec's RegExp-modifier spelling of the same pattern and checks that both find exactly the same matches.

Behind a V8 flag until it ships. ChromeStatus lists this feature in the Chrome 159 "Enabled by default" group (Finch V8Flag_js_regexp_buffer_boundaries). It is a V8 feature, with no Blink runtime flag, and --enable-experimental-web-platform-features does not turn it on. To run it today, launch Chrome with --js-flags=--js-regexp-buffer-boundaries (verified in Chrome 153). In builds where V8 marks it staged, chrome://flags/#enable-javascript-harmony turns it on as well. In Chrome 153 that flag does not.

Probing the RegExp engine…

Pattern and input

\A, \z and \Z are only special in u or v mode. Without those flags, Annex B reads them as the literal letters A, z and Z.

Flags

Escapes are interpreted: \n, \r, \t, \u2028, \u{…}, \x.. and \\. Pressing Enter adds a real \n.

▼ marks a zero-width match, such as a bare anchor. Blue cells are characters inside a match. Line terminators are shown as glyphs (␊ LF, ␍ CR, ⁂LS U+2028, ¶PS U+2029).

Spec synonym (RegExp modifiers)

Each \A becomes (?-m:^), each \z becomes (?-m:$), and each \Z becomes (?=(?:\r\n|\n|\r|\u2028|\u2029)?(?-m:$)). The rewrite skips escapes inside character classes and non-Unicode patterns, and it rejects quantified assertions exactly as the native grammar does.

the code

// what the inspector does with your input
const native = new RegExp(pattern, flags);           // may throw "Invalid escape" without the feature
const synonym = new RegExp(desugar(pattern, flags), flags);
const at = (re) => [...subject.matchAll(new RegExp(re.source, re.flags + 'g'))]
  .map((m) => [m.index, m[0]]);
JSON.stringify(at(native)) === JSON.stringify(at(synonym)); // the proposal's claim
