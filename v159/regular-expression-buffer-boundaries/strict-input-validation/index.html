Strict input validation

A bulk-import box accepts one SKU per line. The legacy validator uses /^SKU-\d{4}$/m because it needs m to reason about lines — and that is the bug: with m, ^ and $ match at any line, so one good line smuggles the rest of the paste through. Buffer boundaries pin the check to the whole input while keeping m-style line logic inside it.

the rule of thumb

  • Legacy /^SKU-\d{4}$/m.test() passes if any line is a SKU. It accepts both junk pastes.
  • Strict, tolerant \A(?:SKU-\d{4}\r?\n)*SKU-\d{4}\Z with u: the whole input must be SKU lines, and a single trailing line terminator from a clipboard copy is forgiven by \Z.
  • Strict, exact the same with \z: nothing may follow the last SKU — useful for signatures, tokens and checksums where a stray newline changes meaning.

Without the proposal you would write (?-m:^) / (?-m:$) (RegExp modifiers) or a lookbehind soup; \A/\z say the same thing in two characters and read identically in PCRE, Ruby, .NET and Python grammars.
