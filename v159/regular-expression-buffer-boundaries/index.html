Regular Expression Buffer Boundaries

Three new escapes for Unicode-mode (u or v) regular expressions. \A matches only at the start of the input and \z only at the end, whether or not the m flag is set. \Z matches at the end, or just before one final line terminator. The spec defines them as exact synonyms for (?-m:^), (?-m:$) and (?=(?:\r\n|\n|\r|\u2028|\u2029)?(?-m:$)). They are the same buffer anchors that Perl, PCRE, .NET, ICU and Oniguruma users already write, so patterns copied from grammars, configs and documentation now mean the same thing in JavaScript.

How to run it today: launch Chrome with --js-flags=--js-regexp-buffer-boundaries (the V8 flag js_regexp_buffer_boundaries, verified in Chrome 153). In builds where V8 lists the feature as staged, chrome://flags/#enable-javascript-harmony turns it on too. This is a V8 feature: there is no Blink runtime flag, and --enable-experimental-web-platform-features does not turn it on. Without the flag, every page below shows the real SyntaxError and runs the spec's modifier synonyms as a clearly labelled fallback.

concepts

  1. \A and \z vs ^ and $

    The canonical comparison. One three-line input and five patterns: ^…$, \A…\z, the two one-sided anchors and the modifier spelling. Flip the m flag and pick a line, and the table shows where line anchors and buffer anchors disagree. The README's mixed /\Afoo|^bar$|baz\z/um example is checked case by case against the README's stated results.

  2. Boundary inspector

    A regex tester for anchors. Type any pattern, choose flags (m u v i s) and type an input with real \n, \r\n and \u2028 terminators. The inspector marks every match position, shows the engine's verbatim compile error, and runs the spec's modifier synonym next to it to check that both find the same positions.

  3. Whole-input validator

    The practical case. A username allow-list from a library that compiles every pattern with m lets "alice\n<script>" through with ^…$, while \A…\z rejects it. \Z's trailing-newline leniency is right for lines read from files and dangerous for header values. A live <input pattern> check shows that an engine without the feature ignores a \A pattern and accepts anything.

  4. \Z terminator matrix

    end\Z, end\z and end$ tested against fourteen suffixes: LF, CR, CR LF, LS, PS, doubled terminators, and the non-terminators NEL, VT, FF and space. Every result is checked against a line-by-line port of the spec's CompileAssertion steps, and a position view marks where a bare \Z fires.

  5. Identity-escape trap

    The failure modes. Without u or v, \A still means the letter A (Annex B), so /\Afoo\z/ matches "Afooz", and the README's own /end\Z/ example needs u. Also covered: [\A] and \A* are still SyntaxErrors, and a regex literal is an early error that stops a whole script in an engine without the feature. Each case is run live and compared with the spec.

  6. Feature-detect and desugar

    Migration. A guarded new RegExp('\\A', 'u') detection and a compileBoundaryRegExp() helper with three strategies you can force: native, the modifier synonym, and lookaround emulation for engines without modifiers. A 10 × 12 pattern×input corpus compares every match position across the spellings.

  7. Log buffer parser

    The novel composition the proposal enables: one /…/gmu pattern in which a header is anchored at \A, entries at any ^…$ line, and a footer at \z. Truncated uploads and concatenated streams show up structurally. Switch the footer anchor to \Z or $ to see what each one lets through.

why it is shipping

Before this, the only way to say "start of the whole input" inside an m-flag pattern was a lookbehind such as (?<![\s\S]) or, since RegExp modifiers, (?-m:^). Both are hard to read, and neither is what any other engine writes. The explainer's motivation is portability. TextMate grammars, JSON and YAML configs, and code written by people or by coding agents already use \A, \z and \Z. Today JavaScript either rejects them in u-mode or, without u, silently treats them as letters. The proposal reached Stage 3 at the May 2026 TC39 plenary, after \Z was reinstated. ChromeStatus lists it as "Chromium catches up", targeting desktop and Android 159 behind the Finch flag V8Flag_js_regexp_buffer_boundaries.

the surface

// Assertion :: (Unicode mode only, i.e. u or v flag)
//   \A   start of input     ≡ (?-m:^)
//   \z   end of input       ≡ (?-m:$)
//   \Z   end, or before ONE final LineTerminator
//                           ≡ (?=(?:\r\n|\n|\r|\u2028|\u2029)?(?-m:$))
/\Afoo|^bar$|baz\z/mu;   // buffer anchors and line anchors in one pattern
/\Afoo/;                 // no u: Annex B identity escape, matches "Afoo"
/[\A]/u; /\A*/u;         // SyntaxError: not a ClassEscape, not quantifiable
