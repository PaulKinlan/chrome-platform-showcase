Log buffer parser

The proposal's headline trick is that m-flag line anchors and whole-buffer anchors can live in one pattern. This parser uses a single /…/gmu expression with named groups. A #log header only counts at \A, entries match at any ^…$ line, and an #end footer only counts at \z. A truncated upload, or two logs pasted together, then shows up structurally. You need no second pass and no index arithmetic.

Behind a V8 flag until it ships. ChromeStatus lists this feature in the Chrome 159 "Enabled by default" group (Finch V8Flag_js_regexp_buffer_boundaries). It is a V8 feature, with no Blink runtime flag, and --enable-experimental-web-platform-features does not turn it on. To run it today, launch Chrome with --js-flags=--js-regexp-buffer-boundaries (verified in Chrome 153). In builds where V8 marks it staged, chrome://flags/#enable-javascript-harmony turns it on as well. In Chrome 153 that flag does not.

the code

const LOG = new RegExp(String.raw`\A#log v(?<ver>\d+) host=(?<host>\S+)$` +
  String.raw`|^(?<level>INFO|WARN|ERROR) (?<msg>.*)$` +
  String.raw`|^#end (?<count>\d+)\z`, 'gmu');

for (const m of buffer.matchAll(LOG)) {
  if (m.groups.host)  header = m.groups;        // only ever at offset 0
  if (m.groups.level) entries.push(m.groups);   // any line
  if (m.groups.count) footer = m.groups;        // only at the very end
}
const complete = header && footer && Number(footer.count) === entries.length;
