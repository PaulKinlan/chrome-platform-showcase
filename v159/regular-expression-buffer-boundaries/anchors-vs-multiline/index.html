\A and \z vs ^ and $

The whole proposal in one table. ^ and $ change meaning when you add the m flag: they start matching at every line. \A and \z never change. They match only at the very start and the very end of the input, with or without m. Pick a word, flip m, and watch which patterns still find it in a three-line input.

Behind a V8 flag until it ships. ChromeStatus lists this feature in the Chrome 159 "Enabled by default" group (Finch V8Flag_js_regexp_buffer_boundaries). It is a V8 (JavaScript engine) feature, so there is no Blink runtime flag, and --enable-experimental-web-platform-features does not turn it on. To run it today, launch Chrome with --js-flags=--js-regexp-buffer-boundaries (verified in Chrome 153). In builds where V8 marks the feature staged (V8 main at the time of writing), chrome://flags/#enable-javascript-harmony ("Experimental JavaScript") turns it on as well. In Chrome 153 the feature is still experimental, and that flag does not turn it on.

the code

const input = "admin\nguest\nroot";
/^guest$/mu.test(input);        // true:  ^ and $ match at line edges under m
/\Aguest\z/mu.test(input);      // false: \A and \z ignore m and only see the buffer edges
/\Aadmin/mu.test(input);        // true:  admin is at index 0
/root\z/mu.test(input);         // true:  root ends the input
/(?-m:^)guest(?-m:$)/mu.test(input); // false: the RegExp-modifier spelling of the same thing
