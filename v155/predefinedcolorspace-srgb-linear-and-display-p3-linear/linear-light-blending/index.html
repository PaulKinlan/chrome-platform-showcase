Blending as light, not as code values

Compositing happens on stored pixel values. Store them sRGB-encoded and half-transparent green over red lands on a muddy dark yellow; store them linear and the same operation mixes actual light. Both stores are below, running the same drawing commands, with the pixels read back to prove which math ran.

What a linear store does not change

Canvas gradient stops are still interpolated the same way regardless of the backing store — measured while building this page (Chromium 141 with the feature enabled behind its flag): the midpoint of a red-to-green createLinearGradient read back as sRGB 127, 128, 0 from both an sRGB store and an srgb-linear store. The backing store changes the arithmetic of compositing, filtering and your own pixel math on getImageData buffers, not the definition of a two-stop gradient ramp.

the code this runs

function blend(colorSpace, alpha) {
  const canvas = document.createElement("canvas");
  const ctx = canvas.getContext("2d", { colorSpace }); // may throw pre-155
  ctx.fillStyle = "#ff0000";
  ctx.fillRect(0, 0, w, h);
  ctx.globalAlpha = alpha;
  ctx.fillStyle = "#00ff00";
  ctx.fillRect(0, 0, w, h);
  // Read back converted to sRGB so both stores are comparable numbers.
  return ctx.getImageData(0, 0, 1, 1, { colorSpace: "srgb" }).data;
}
