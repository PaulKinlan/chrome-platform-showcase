The enum, swept

PredefinedColorSpace is a Web IDL enum, and enums are strict: a value the browser doesn't know is a TypeError at the call, not a silent shrug. That strictness is the feature-detection story — so this page offers every value to every surface that takes one, for real, and reports what each call actually did.

Ships in Chrome 155, enabled for all users. Before that: launch Canary/Dev with --enable-blink-features=ColorSpacePredefinedLinearSpaces, or enable chrome://flags/#enable-experimental-web-platform-features (there is no dedicated flags entry). The sweep below measures your browser either way.

Four values, three surfaces

Each cell is a fresh call — a new <canvas>, a new OffscreenCanvas, a new ImageData — never a cached result. Context cells read the verdict back out of getContextAttributes().colorSpace; ImageData cells read the colorSpace attribute. A value the browser accepted but echoed back as something else would be reported as normalised, which is different from support.

  • echoed — accepted, and read back exactly
  • normalised — accepted, but read back as something else
  • threw — rejected at enum conversion

Offer any string

The rejection is specific and it is the detection path: try { canvas.getContext('2d', { colorSpace }) } catch. Type anything — a legacy value, a typo, a space from a future spec — and see the exact acceptance or the exact TypeError message.

Rejected value vs ignored member

Two failures that look alike and mean opposite things. An unknown enum value in a known member throws — the browser understood the question and said no. An unknown member name is silently dropped by dictionary conversion — the browser never saw the question, and the call "succeeding" proves nothing. A probe that confuses these reports gibberish as support.
