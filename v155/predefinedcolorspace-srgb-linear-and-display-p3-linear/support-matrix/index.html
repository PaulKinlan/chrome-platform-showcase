Four enum values, four API surfaces that accept one, sixteen real calls. Every cell holds what this browser actually did — the value read back after creation, or the exact exception it threw. Nothing here is inferred from a version number.

Before Chrome 155, the two linear values sit behind a flag: enable chrome://flags/#enable-experimental-web-platform-features and relaunch, or launch with --enable-blink-features=ColorSpacePredefinedLinearSpaces. Measured on Chromium 141: the experimental flag enables srgb-linear on all four surfaces below, while display-p3-linear is not in that build's enum at all, so no flag revives it there.

The order of checks matters. A call that does not throw has proven nothing yet: a browser that has never heard of the colorSpace member ignores it and hands back an sRGB canvas without complaint. Only the readback — getContextAttributes().colorSpace, or .colorSpace on the ImageData — says what you actually got. A browser that does know the member but not the value rejects it with a TypeError, and that exception is shown here verbatim.

the code this runs

// One fresh canvas per probe — a canvas keeps its first context forever.
function probeContext(value) {
  const canvas = document.createElement("canvas");
  try {
    const ctx = canvas.getContext("2d", { colorSpace: value });
    const got = ctx.getContextAttributes().colorSpace;
    return got === value ? `supported (${got})` : `created, but reports "${got}"`;
  } catch (error) {
    return `${error.name}: ${error.message}`;
  }
}
