The transfer function, by hand

Everything these color spaces do reduces to one pair of functions from CSS Color 4: encode light for storage, decode storage back to light. Pick a color and follow each channel through them — then, where this browser has the linear spaces, watch the real canvas produce the same numbers.

The first four numeric columns are computed reference values — page JavaScript implementing the piecewise sRGB transfer function from CSS Color 4 (linear = c/12.92 below 0.04045, else ((c+0.055)/1.055)^2.4). They are labelled as computed because they are not evidence about this browser. The last column is evidence: the color is filled into a real srgb-linear canvas and read back with getImageData, where this browser allows one to exist.

Where 8 bits go: the shadow-precision trade

Both strips draw the same dark ramp, 0–25% luminance. The top strip quantizes it through sRGB encoding, which spends most of its codes on dark tones; the bottom strip quantizes through a linear 8-bit encoding, which has only 64 codes for this whole range and visibly bands. This is why 8-bit linear stores band in shadows — and why linear workflows usually pair with the separate float16 canvas feature.

the math this implements

// CSS Color 4 — the sRGB transfer function pair.
// display-p3 and display-p3-linear use the SAME curve on P3 primaries.
function toLinear(c) {
  return c <= 0.04045 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4);
}
function toEncoded(l) {
  return l <= 0.0031308 ? 12.92 * l : 1.055 * Math.pow(l, 1 / 2.4) - 0.055;
}

// The check against reality, where the browser permits it:
const ctx = scratch.getContext("2d", { colorSpace: "srgb-linear" });
ctx.fillStyle = pickedColor;
ctx.fillRect(0, 0, 1, 1);
ctx.getImageData(0, 0, 1, 1, { colorSpace: "srgb-linear" }).data
// each channel ≈ round(toLinear(encoded) × 255)
