Server Side Gemini Powered Scam Checks for Desktop

Chrome on desktop moves its Gemini-powered scam checks from an on-device model to a server-side Gemini model, matching what Android already does. The checks run only for people enrolled in Enhanced Safe Browsing; enterprises control that enrollment with the existing SafeBrowsingProtectionLevel policy. Chrome analyses page text only when a site shows high-confidence scam indicators, and anything sent off the device is processed ephemerally: never logged, kept, or used for training.

Read this first: a web page cannot see this feature. No spec, no JavaScript API, no header and no flag is listed for it. A page cannot tell whether you use Enhanced Safe Browsing, whether a scan ran, or what the verdict was. Nothing on these pages detects your protection level or triggers Chrome's real scam check. The concepts are honest about that: they combine labelled educational models built from public sources, a real policy generator and validator, a manual self-check, and real calls to the web APIs the classifier treats as scam signals (Fullscreen, Keyboard Lock, Pointer Lock).

concepts

  1. Trigger anatomy lab

    A harmless, inert tech-support-scam specimen. Toggle its indicators (fullscreen and keyboard-lock attempts, a fake system dialog, urgency text, a phone number, a payment form) and a live readout maps each one to the Chromium client-side-detection trigger type it matches (KEYBOARD_LOCK_REQUESTED, FULLSCREEN_API, …). It also shows the exact page text a scan would extract. This is an educational model, not Chrome's classifier.

  2. Data-flow explorer

    An accessible stepper through what stays on the device and what leaves it. Choose a protection level, decide whether indicators fire, use up the daily scan quota, and switch between the Chrome 137–154 on-device pipeline and the Chrome 155 server-side one. Every step cites its source, and the no-result reasons come from Chromium's IntelligentScanInfo.NoInfoReason enum.

  3. Enterprise policy builder

    Pick a SafeBrowsingProtectionLevel value (0, 1 or 2), mandatory or recommended, and a platform. You get the exact Windows registry, macOS plist, Linux JSON or Admin console setting, with a copy button. Paste an existing policy JSON and a real validator checks it against the policy schema. Only value 2 enrolls users in the scam check.

  4. Check your own browser

    A manual-observation page. It gives the chrome://settings/security and chrome://management steps, reads the one relevant signal a page can see (navigator.userAgentData.mobile, because this rollout is desktop-only), and offers a self-report checklist saved in this browser only. It never claims to detect your setting.

  5. Don't look like a scam: API hygiene for real sites

    For developers. It makes real calls to requestFullscreen(), navigator.keyboard.lock() and requestPointerLock() twice: on a click, and again after transient activation has expired. You see the browser's actual resolve or reject result, and every lock is released at once. Each call is paired with the client-side-detection trigger it matches and with guidance for legitimate games, kiosks and presentations.

why it shipped

Tech-support scams take over the screen: they go fullscreen, lock the keyboard so Esc stops working, show fake virus alerts and push a phone number. In 2025 (Chrome 137) Chrome began using the on-device Gemini Nano model on desktop to read such pages once a scam-characteristic trigger fired, for example a Keyboard Lock request. The model's summarised security signals were sent to Safe Browsing for Enhanced Protection users. Chrome 155 replaces that desktop on-device model with the server-side Gemini check already used on Android. The server model can be larger and is not limited by whether the device can run Gemini Nano. The ChromeStatus entry describes two limits on data: page text is analysed only when high-confidence indicators are present, and content sent off the device is processed ephemerally. Standard Protection users do not take part, though they still benefit indirectly when newly confirmed scam sites reach the Safe Browsing blocklists.
