Trigger API playground

Chrome’s scam detector does not read every page. It waits for behaviour that tech-support scams rely on — taking over the screen, swallowing the keyboard, hiding the mouse — and only then considers a closer look. Each card below calls one of those web APIs for real and shows exactly what the API returned to this page. Next to it is the ClientSideDetectionType value Chromium uses for that trigger.

What you will not see: whether Chrome started a check. The trigger handlers in client_side_detection_host.cc return early unless the visitor has Enhanced Safe Browsing on, and the result never comes back to the page. This page is a legitimate demo, so even an Enhanced Safe Browsing check should end with no warning. The “check started?” column is always not observable from the page, and that is accurate, not a gap in the demo.

Keyboard lock

KEYBOARD_LOCK_REQUESTED

navigator.keyboard.lock(["Escape"]). Resolves outside full-screen, but only captures system keys while full-screen. Released after 4 s.

Not called yet.

Pointer lock

POINTER_LOCK_REQUESTED

stage.requestPointerLock() hides the cursor. Released after 3 s, or press Esc.

Not called yet.

Vibration

VIBRATION_API

navigator.vibrate(200) returns a boolean. Chromium classifies only once per URL because scam pages call it in tight loops.

Not called yet.

Clipboard copy

CLIPBOARD_COPY_API

navigator.clipboard.writeText() with harmless text. Chromium’s token filter drops this one: no loader, runner or decoder token. See the tokenizer.

Not called yet.

Notification prompt

NOTIFICATION_PERMISSION_PROMPT

Notification.requestPermission(). The trigger is the prompt being shown, so it never fires once permission is already granted or denied.

Not called yet.

The lockdown pattern, harmless version

The Security Blog describes tech-support scams that use “full-screen takeovers and disable keyboard and mouse input to create a sense of crisis.” This button chains the same three calls on the stage above, with harmless content, and releases everything after 6 seconds. While it runs, Chrome’s own “Press and hold Esc to exit” hint is the escape hatch that keyboard lock cannot remove.

Event log

    reading the results

    • Resolved means the browser granted the API call. For Enhanced Safe Browsing users, that is when ClientSideDetectionHost may start pre-classification.
    • Rejected (for example NotAllowedError without a user gesture, or pointer lock refused) usually means the trigger never happened either.
    • Not exposed is common on mobile. Chrome for Android has no Keyboard Lock and no Pointer Lock, and this feature is the desktop rollout anyway.
