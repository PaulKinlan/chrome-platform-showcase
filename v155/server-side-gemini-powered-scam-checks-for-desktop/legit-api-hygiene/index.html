Don't look like a scam: API hygiene for real sites

Games, kiosks, slide decks and remote-desktop apps use the same Fullscreen, Keyboard Lock and Pointer Lock APIs that tech-support scams abuse, and Chromium's client-side detection records each one as a scan trigger. Here are the real calls, made the legitimate way on a click and the scam way after the click's activation has expired. Each result is the browser's actual one, and every lock is released immediately.

Real calls, honest scope. The buttons call the actual APIs and print exactly what the browser returned or threw. Fullscreen and pointer lock end at once. A trigger type can start an intelligent scan only for Enhanced Safe Browsing users, and only Chrome and Safe Browsing decide what happens next. This page cannot see whether a scan ran, and it doesn't pretend to. Tip: Esc always leaves fullscreen and pointer lock here.

1 · Fullscreen FULLSCREEN_API

The spec requires transient activation, a user gesture within the last few seconds (about 5 s in Chrome). Scam pages try to go fullscreen as the page loads. That fails, so they bait a click instead.

Not run yet.

2 · Keyboard Lock KEYBOARD_LOCK_REQUESTED

navigator.keyboard.lock(codes) lets a fullscreen page capture keys like Esc that the browser normally keeps. Chrome then makes users press and hold Esc to exit. Scams lock the keyboard to stop people leaving. This was the trigger Google's 2025 post named.

Not run yet.

3 · Pointer Lock POINTER_LOCK_REQUESTED

Pointer lock hides the cursor and delivers raw movement, which is ideal for 3D games. Scams use it to "freeze" the mouse. Chrome requires a user gesture. Older builds return undefined and newer ones return a Promise, so this code handles both.

Not run yet.

building it the legitimate way

Do

  • Request fullscreen, keyboard lock or pointer lock only from an explicit, labelled control ("Play fullscreen", "Present").
  • Lock only the keys you need, after entering fullscreen, and call navigator.keyboard.unlock() when you leave.
  • Tell users how to get out (Esc, or hold Esc under keyboard lock) and respect fullscreenchange / pointerlockchange.
  • Keep the page's text honest: a scan reads the text, and ordinary game or presentation copy is what makes the difference.

Don't

  • Retry requests in loops after a user exits, or chain them to unrelated clicks.
  • Pair screen takeover with alarming system-style dialogs, countdowns or "call this number" text.
  • Write commands to the clipboard and ask people to paste them (CLIPBOARD_COPY_API is another trigger).
  • Prompt for notifications or payment details while the screen is taken over.

the pattern

playButton.addEventListener('click', async () => {      // transient activation
  await game.requestFullscreen();                         // FULLSCREEN_API
  if ('keyboard' in navigator) await navigator.keyboard.lock(['Escape']); // KEYBOARD_LOCK_REQUESTED
  await normalise(canvas.requestPointerLock());           // POINTER_LOCK_REQUESTED
});
document.addEventListener('fullscreenchange', () => {
  if (!document.fullscreenElement) navigator.keyboard?.unlock();
});
const normalise = (r) => (r && typeof r.then === 'function') ? r : Promise.resolve(r);
