Legitimate fullscreen & keyboard-lock patterns

Keyboard Lock is the trigger Google names for tech-support scam detection, but remote-desktop clients, games and kiosk tools need it too. This page is a working keyboard-shortcut trainer that uses fullscreen and Keyboard Lock the way a trustworthy app should. A live scorecard checks each habit against the real browser state. Two anti-patterns can be switched on so you can watch the browser enforce its own limits.

No verdict, by design. Following these habits makes your app clearer and easier for users to trust. It does not guarantee that Safe Browsing will never evaluate your page, and no page can see whether it did. The scorecard only reports what this page actually did. Keyboard Lock is a Chromium-only API (Chrome and Edge on desktop). Elsewhere the trainer still runs in fullscreen, without capturing system keys, and says so.

why these habits

  • Gesture-started: requestFullscreen() requires transient activation. Scam pages try to grab fullscreen on load or on any stray click. A legitimate app ties it to an explicit "Start" control.
  • Specific keys: lock(keyCodes) takes a list. Lock only what the app needs, and never Escape unless you truly must (Chrome then requires press-and-hold Esc to exit).
  • Visible exit: Chrome shows its own "Press and hold Esc" bubble. Repeating it in your own UI shows users you are not trying to trap them.
  • Release on exit, never re-enter: scam pages bounce straight back into fullscreen. Without a new user activation the browser rejects that, as you can see by enabling the anti-pattern.
