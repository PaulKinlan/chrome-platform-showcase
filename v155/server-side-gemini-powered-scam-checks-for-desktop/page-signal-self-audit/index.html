Page-signal self-audit

Building a kiosk, a game or a training simulator that goes full-screen and locks the keyboard? Those are legitimate uses, and they are also the signals Chrome’s scam detector listens for. Paste your page’s HTML/JS, or fetch any page on this origin, and this tool lists every call site that maps to a Chromium ClientSideDetectionType trigger, line by line.

This is a static text scan written for this demo, not Chrome’s classifier. A match means the page can become eligible for a check for Enhanced Safe Browsing visitors when that code runs. It is not a scam verdict, and nothing here predicts what the server model decides. Rows marked heuristic are pressure tactics described in Google’s tech-support-scam write-up. They are not Chromium triggers.

keeping legitimate uses unambiguous

  • Request full-screen, keyboard lock and pointer lock only after a clear user gesture inside your UI, such as “Start game”. Never on load.
  • Tell users how to get out (“Hold Esc to exit”) and release locks as soon as the activity ends.
  • Avoid alarm copy around these calls: fake system alerts, countdowns, “do not close this window”, support phone numbers.
  • Copy buttons for shell commands are a separate clipboard signal. See Clipboard command check.
