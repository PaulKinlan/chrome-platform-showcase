What gets sent

The move to a server-side model raises a fair question: what leaves the device? Chrome sends a page’s text only after Safe Browsing asks for an “intelligent scan” following a high-confidence trigger, and only for Enhanced Safe Browsing users. ChromeStatus says the text is processed ephemerally, never logged, retained or used for training. This tool renders a page and extracts the same kind of text, rendered and visible only, then applies the gates Chromium’s source defines.

Real part vs modelled part. The text extraction is real: the sample is rendered in a sandboxed frame with scripts disabled, and its body.innerText is read. That is the web-exposed equivalent of the renderer’s inner text that Chrome collects. The decision ladder is modelled from client_side_detection_host_base.cc and features.cc using the inputs you set. This page cannot learn whether your browser has Enhanced Safe Browsing on, has used its quota, or what the server decided.

    source notes

    • kInnerTextMinThresholdBytes = 5. With no screenshot, inner text of 5 bytes or fewer is not scanned: EMPTY_TEXT if empty, else TEXT_TOO_SHORT.
    • The title is prefixed (title + "\n" + text) only when kClientSideDetectionIncludeTitleInInnerText is on and the text is over the threshold.
    • kClientSideDetectionServerModelForScamDetectionDesktop is enabled by default with MaxIntelligentScansPerDayDesktop = 5. Past that, SERVER_SIDE_MODEL_EXCEED_QUOTA.
    • ClientPhishingRequest.url: “The CGI parameters are stripped by the client.”
    • Screenshots (kClientSideDetectionServerModelMultimodal, ≤ 2 MiB) and iframe text (kClientSideDetectionIframeInnerText) are disabled by default, so this tool reads the main document only.
