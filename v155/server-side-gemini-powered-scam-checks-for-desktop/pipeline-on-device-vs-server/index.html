Pipeline: on-device vs server-side

This release swaps desktop's on-device Gemini Nano step for a server-side Gemini call. Everything around that step stays the same: the trigger, the text extraction, the Safe Browsing verdict and the warning page. Step through both pipelines, then explore the documented reasons a scan produces no model output. The field names, enum values and quota default come from Chromium source.

Explainer, not a classifier. The branch explorer maps conditions you choose onto Chromium's documented NoInfoReason values and quota parameter. It never inspects or classifies a real page, and it never shows a scam verdict. Verdicts come only from Google's servers, and no page can read them. The order in which Chrome evaluates the conditions is not documented, so the explorer reports the first matching reason in a reasonable order and labels it that way.

    3 · Measure a page's text (the model's input)

    The scan reads a page's rendered text (innerText). Chromium also has a ClientSideDetectionIncludeTitleInInnerText feature that adds the title. Measure this page, or fetch another page on this site, to see what the model would receive. Very short pages fall into TEXT_TOO_SHORT or EMPTY_TEXT. The threshold is not public.

    4 · If your legitimate site gets a warning

    1. Check for a compromise first. Injected scripts and pop-under ad networks are the usual reason a clean site starts showing scam behaviour.
    2. Check Google Search Console → Security issues for a recorded finding.
    3. Request a review with the Safe Browsing incorrect-warning report (or through Search Console after you fix any issue).
    4. Review your use of trigger-type APIs against the legitimate patterns: gesture-started, specific keys, visible exit, no re-entry.
