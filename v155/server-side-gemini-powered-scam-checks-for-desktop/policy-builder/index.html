Enterprise policy builder

Organisations decide whether the server-side scam check reaches their users through one existing policy, SafeBrowsingProtectionLevel. Choose a value, whether users may change it, and a platform to get the exact deployment snippet. Or paste an existing policy file and validate it against the policy's schema.

The generator and validator are real; deployment is up to you. The snippets follow the Chromium policy definition (int-enum 0/1/2, can_be_recommended: true, per_profile: true, dynamic_refresh: true, supported on desktop Chrome since 83). After deploying, confirm the result on a managed machine at chrome://policy. A web page cannot read a browser's policy.

what each value means for the scam check

    
    
      
  • 2: Enhanced Safe Browsing is always on. This is the only value that enrolls profiles in the server-side Gemini scam check (ChromeStatus: "only for users enrolled in Enhanced Safe Browsing").
    • 
      
  • 1: Standard protection. There is no scam check, but users still get list-based Safe Browsing and benefit indirectly from blocklists. If you set it as recommended, users can opt in to Enhanced themselves.
    • 
      
  • 0: Safe Browsing is never active, so nothing is checked at all.
    • 
      
  • Unset: Standard protection, and users may change it. Anyone who picks Enhanced gets the check.
