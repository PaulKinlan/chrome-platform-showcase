Clipboard command check

“Press Win+R, paste, Enter to verify you are human.” Copy-paste attacks put a malicious command on the clipboard and talk the victim into running it. On desktop, Chrome’s CLIPBOARD_COPY_API trigger tokenises every page-initiated copy. This tool runs the same tokenizer, ported line by line from ExtractClipboardData() with the default token lists from features.cc, so you can see whether your own docs’ copy buttons look like that pattern.

The tokenizer decides only whether the copy becomes a trigger. It does not decide whether the page is a scam; the server model does that, and its verdict is never visible to the page. Two parts are approximated in JavaScript: IsPossibleURL(), which uses Chromium’s URL fixer and the public-suffix list, and FilePath base-name handling. Their rows are marked “approx.” The sample commands are defanged and point at hosts under IANA-reserved example.com / example.net. Those are real registrable domains, so the endpoint rule still matches; a bare .example TLD would not.

    for documentation sites

    • A legitimate curl … | bash installer has a loader, an endpoint and a runner, so it is overall suspicious to the tokenizer. For Enhanced Safe Browsing users that copy can start a check, and the full command is included in the request. The model is what tells a real installer from a ClickFix page.
    • The trigger fires only for copies of 10 to 1000 characters, only once per URL, and only for Enhanced Safe Browsing users.
    • Want to stay off the trigger without hurting users? Link a package manager (npm, brew, winget) as the primary install path, and keep the raw pipe-to-shell command as plain text.
