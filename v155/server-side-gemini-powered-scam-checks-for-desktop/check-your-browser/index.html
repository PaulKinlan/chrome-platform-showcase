Check your own browser

Is your Chrome covered by the server-side scam check? Only you can find out, by looking at Chrome's own settings. A web page cannot read your Safe Browsing level. This page walks you through the check, reads the one related fact a page can see, and keeps your notes in this browser only.

MANUAL OBSERVATION This page does not detect Enhanced Safe Browsing, does not trigger a scan, and nothing you enter leaves this browser. Your answers are saved with localStorage on this device only and never sent with telemetry. Web pages cannot open chrome:// links, so copy each address and paste it into the address bar yourself.

1 · Look in Chrome

  1. Security settings. See which of Enhanced protection, Standard protection or No protection is selected. Only Enhanced protection gets the scam check.
    chrome://settings/security
  2. Is it managed? If the options are greyed out with a building icon, your organisation set them with SafeBrowsingProtectionLevel. Check here:
    chrome://management
  3. The exact policy value. Search for SafeBrowsingProtectionLevel. The value 2 means Enhanced.
    chrome://policy
  4. Version. The desktop server-side check is listed for Chrome 155. Earlier desktop versions (137–154) used the on-device Gemini Nano check instead.
    chrome://version

2 · The one signal a page can read: desktop or mobile?

This rollout is desktop-only (the Chromium feature is compiled out of Android and iOS). navigator.userAgentData.mobile tells a page whether the browser reports a mobile device. It does not reveal Safe Browsing, the Chrome version's feature state, or anything about scans.

edge cases worth knowing

  • Managed browsers: a mandatory SafeBrowsingProtectionLevel of 0 or 1 means you cannot opt in. A value of 2 means you cannot opt out.
  • Per profile: the policy and the setting apply per Chrome profile. A work profile and a personal profile can differ.
  • Quota: even with Enhanced protection, the desktop server check has a per-day scan cap (source default 5). After that, pages are not sent.
  • Mobile: Chrome on Android already uses server-side checks. This entry adds desktop only.
