Saving a file yourself

There are two ways a page can turn bytes into a saved file, and they are opposites. Hand the bytes to the download pipeline and the browser decides everything — including, under a Chrome 155 DLP rule, that "everything" means corp Google Drive instead of disk. Write them through showSaveFilePicker() and the page keeps a live handle and learns each step's outcome. Run both here with the same bytes.

    Path B asks for a real save dialog, so expect it to end differently depending on where you are: on desktop Chromium it opens a picker (cancel it and the page is told that, too — an AbortError); on Android, iOS and Firefox the function does not exist and the row says so. A missing picker here is a platform fact, reported as one — not papered over.

    Why the difference matters to this feature

    Browser-managed download vs. page-managed write
    questionPath A — a[download] / Content-DispositionPath B — showSaveFilePicker()
    Who picks the destination?The browser — settings, prompts, and from Chrome 155, a DLP rule that can enforce corp cloud storage.The user, in a picker; the page then holds a handle to that exact location.
    Does the page learn the outcome?No. No completion event, no path, no verdict — proven in the first concept.Yes, step by step: picker resolved, writable created, bytes written, close resolved — each is an awaited promise.
    Needs a user gesture?No — script can click an anchor.Yes — the call throws outside transient user activation.
    Cross-origin behaviourThe download attribute is honoured same-origin (plus blob: and data:); on a cross-origin link it is ignored and the click navigates instead.Not applicable — the page writes bytes it already holds.
    Where does the File-download DLP rule sit?Exactly here: the OnFileDownloaded connector triggers "when a file is downloaded in Chrome", and Enforce cloud storage is one of its verdicts.On a different code path. Picker writes can still be security-scanned by Chrome, but they are not the surface this Chrome 155 action names.
    AvailabilityEverywhere.Chromium desktop; absent on Android, iOS, Firefox, Safari (Safari has partial, origin-private support only).

    The product lesson for a page that serves downloads: never assume the file reached a local disk, never build UI that says "saved to your Downloads folder", and treat the handoff as final. Under this feature that wording is not just presumptuous — on a managed profile it can be plainly wrong, because the file went to the corp drive.
