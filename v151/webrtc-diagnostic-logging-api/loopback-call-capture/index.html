Loopback call capture

How the API is meant to be used in production: wrap a real call in a diagnostic-logging session. The button below runs a genuine RTCPeerConnection loopback call inside this page — offer/answer, ICE host candidates, a data-channel round trip, live getStats() — bracketed by startDiagnosticLogging() and finishDiagnosticLogging() when the API is exposed. The call itself runs in any modern browser; only the capture wrap needs the flag or origin trial, and the page says honestly which of the two actually happened.

Capture wrap unavailable: neither navigator.rtc (Chrome 151 origin-trial binding) nor RTCPeerConnection.startDiagnosticLogging (spec-draft static) is exposed here. The loopback call below still runs for real — it just won't be bracketed by a diagnostic-logging session. To enable the wrap, launch Chrome 151+ with --enable-blink-features=RTCDiagnosticLogging, enable chrome://flags/#enable-experimental-web-platform-features, or register for the origin trial.

the privacy model: silent resolve

The spec provides no guarantees of success by design. startDiagnosticLogging() resolves with a UUID even when no logging actually begins — in a non-top-level frame, when a session is already active, or when the user/policy never authorized collection. The page cannot distinguish these from a real capture. Try it: the button calls startDiagnosticLogging() twice back-to-back, shows that both resolve with UUIDs (spec: the second starts no new session), then discards with cancelDiagnosticLogging().

Requires the API to be exposed — the silent-resolve behaviour can only be observed against the real implementation, so this page never simulates it.
const rtc = navigator.rtc ?? RTCPeerConnection;  // OT binding vs spec draft
const canCapture = typeof rtc?.startDiagnosticLogging === "function";

// 1 · open the capture bracket (if exposed)
const id = canCapture
  ? await rtc.startDiagnosticLogging({ metadata: { screen: "support-call" } })
  : null;

// 2 · the real call — everything WebRTC does here MAY be logged
const a = new RTCPeerConnection(), b = new RTCPeerConnection();
a.onicecandidate = (e) => e.candidate && b.addIceCandidate(e.candidate);
b.onicecandidate = (e) => e.candidate && a.addIceCandidate(e.candidate);
const dc = a.createDataChannel("diag-ping");
/* … offer/answer, wait for the round trip, read getStats() … */

// 3 · close the bracket; the log stays on the user's machine
if (canCapture) await rtc.finishDiagnosticLogging();
