WebRTC Diagnostic Logging API

The origin trial for navigator.rtc.startDiagnosticLogging() / finishDiagnosticLogging() / cancelDiagnosticLogging() continues in Chrome 151. An authorized app asks the browser to capture internal WebRTC diagnostics into a local log; the page only ever receives a session UUID to pin to a bug report — the log itself never flows back to the app. These v151 concepts pick up where the v150 demos left off: getting enrolled in the trial, wrapping a real call with logging, and tracking a live spec/implementation divergence.

concepts

  1. Origin-trial on-ramp

    The enablement gate, as a working tool: probe the real navigator.rtc binding and secure-context state in your browser, then generate the exact <meta http-equiv="origin-trial"> tag or Origin-Trial header for your token, with the flag and enterprise-policy alternatives (RTCDiagnosticLogging, WebRtcDiagnosticLogCollectionAllowedForOrigins) spelled out.

  2. Live-call logging

    What a capture actually wraps: the page runs a real loopback RTCPeerConnection data-channel call — offer, answer, ICE, messages — bracketed by real startDiagnosticLogging() / finishDiagnosticLogging() calls when the API is exposed. Without the trial, the call still runs and the logging calls report their genuine unavailability.

  3. Spec-vs-implementation tracker

    The WICG draft moved the methods to statics on RTCPeerConnection while Chromium's origin trial ships them on navigator.rtc. This page probes both surfaces live with typeof reads and renders the divergence table your feature-detection code needs today.

why it's in the 151 listing

The origin trial that began around Chrome 150 spans Chrome 151: chromestatus lists the feature under milestone 151's origin-trial section while the estimated stable ship remains later (the feature detail currently estimates desktop 156). During the trial window the surface is navigator.rtc, gated on a secure context plus the RTCDiagnosticLogging runtime feature (origin-trial feature name RTCDiagnosticLogging), and production log collection additionally requires the enterprise policy WebRtcDiagnosticLogCollectionAllowedForOrigins. Chromium's validation caps metadata at 5 entries of ≤ 100 characters and rejects with a RangeError (the draft spec says TypeError — one of the divergences the tracker concept watches).
