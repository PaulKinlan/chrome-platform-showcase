Capability & policy probe

Whether this API works depends on more than the browser version — and on which shape the browser ships. This page probes both known bindings in your current browser: Chrome 151's origin-trial navigator.rtc interface and the current WICG draft's static methods on RTCPeerConnection. Below the probes, the full enablement gate: secure context → flag or origin trial → enterprise policy. No fake success — if neither binding exists, the probe says so.

1 · Secure context

The interface is [SecureContext] — served over HTTPS or localhost. This page: checking…

2 · Flag or origin trial exposes the API

Locally: --enable-blink-features=RTCDiagnosticLogging or chrome://flags/#enable-experimental-web-platform-features in Chrome 151+. For production origins, register for the origin trial (trial name RTCDiagnosticLogging) — ChromeStatus records it on desktop, Chrome 151–156 (API, updated 2026-08-12). The runtime feature — via flag or an origin-trial token — is what makes the binding exist.

3 · Enterprise policy authorizes collection

For real diagnostic collection, the managed-browser policy WebRtcDiagnosticLogCollectionAllowedForOrigins must list your origin. Without it, the methods exist but collection is gated by the user agent — and by design the page can never observe whether collection actually happened.

if (!window.isSecureContext) { /* needs HTTPS or localhost */ }

// Chrome 151 origin trial ships navigator.rtc; the current WICG
// draft moved the methods to statics on RTCPeerConnection.
const rtc =
  (navigator.rtc &&
   typeof navigator.rtc.startDiagnosticLogging === "function")
    ? navigator.rtc
    : (typeof RTCPeerConnection !== "undefined" &&
       typeof RTCPeerConnection.startDiagnosticLogging === "function")
    ? RTCPeerConnection
    : null;

if (rtc) {
  // API surface is present — safe to offer diagnostic capture
