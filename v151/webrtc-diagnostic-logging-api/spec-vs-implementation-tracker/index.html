Spec-vs-implementation tracker

Origin trials exist because APIs are still moving — and this one moved. The current WICG draft defines the three methods as statics on RTCPeerConnection, while Chromium's trial ships them on a navigator.rtc interface (modules/webrtc/rtc.idl). Divergence #1 — where the methods live

Draft: partial interface RTCPeerConnection { static Promise<DOMString> startDiagnosticLogging(…) }. Chromium: interface RTC hung off Navigator as navigator.rtc (with a TODO in the IDL: “Add spec link when available” — crbug.com/481412281). Feature-detect the surface you intend to call, not the one the draft describes.

Divergence #2 — metadata-limit error type

Both agree metadata is capped (5 entries, ≤ 100 chars each). The draft mandates a TypeError; Chromium's rtc.cc rejects with a RangeError ("Too many metadata entries." / "Metadata entry too long."). Robust code catches both.

What both agree on

Secure context only; start resolves with a UUID string; finish/cancel resolve with nothing; the log never reaches the page; and the app can never observe whether the user or policy actually authorized collection.

// Feature-detection that survives the divergence:
const surface =
  typeof navigator.rtc?.startDiagnosticLogging === "function"
    ? navigator.rtc                    // Chromium origin trial (Chrome 150–151+)
    : typeof RTCPeerConnection?.startDiagnosticLogging === "function"
      ? RTCPeerConnection              // current WICG draft shape
      : null;

if (surface) {
  const id = await surface.startDiagnosticLogging();
}
