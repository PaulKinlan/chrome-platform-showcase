Live-call logging

A diagnostic log is only as interesting as the WebRTC traffic it wraps. This page places a real loopback call — two in-page RTCPeerConnections exchanging an offer, an answer, ICE candidates, and data-channel messages — and brackets it with real startDiagnosticLogging() / finishDiagnosticLogging() calls when the API is exposed. The call always runs; the logging calls report exactly what they return.

navigator.rtc is not exposed in this browser — the call below still runs for real, and the two logging steps will report the API's genuine absence rather than pretending. To make the logging calls real too: register for the RTCDiagnosticLogging origin trial, or launch Chrome 151 with --enable-blink-features=RTCDiagnosticLogging, or enable chrome://flags/#enable-experimental-web-platform-features, on HTTPS or localhost.

// 1 — open the capture window before the call
let sessionId = null;
if (typeof navigator.rtc?.startDiagnosticLogging === "function") {
  sessionId = await navigator.rtc.startDiagnosticLogging({
    metadata: { app: "showcase-loopback", stage: "pre-call" },
  });
}

// 2 — the call the log will describe (loopback: A ↔ B in one page)
const a = new RTCPeerConnection(), b = new RTCPeerConnection();
const channel = a.createDataChannel("ping");
a.onicecandidate = (e) => e.candidate && b.addIceCandidate(e.candidate);
b.onicecandidate = (e) => e.candidate && a.addIceCandidate(e.candidate);
await a.setLocalDescription(await a.createOffer());
await b.setRemoteDescription(a.localDescription);
await b.setLocalDescription(await b.createAnswer());
await a.setRemoteDescription(b.localDescription);

// 3 — close the window once the call ends
await navigator.rtc?.finishDiagnosticLogging({
  metadata: { stage: "post-call" },
});
