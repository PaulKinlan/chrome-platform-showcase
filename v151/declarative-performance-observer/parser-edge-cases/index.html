Parser Edge Cases

What does Chrome actually do with a malformed Performance-Observer header? Two very different failure modes exist: a broken structured-field voids the whole header, while an unknown entry type or a mistyped directive value is silently dropped with the rest still honoured. This workbench parses any header value through a faithful re-implementation of Chromium's parser and pins the behaviour against its real unit tests.

Honesty note: this page re-implements net::structured_headers::ParseDictionary (RFC 8941) plus Chromium's ParseDeclarativePerformanceObserverPolicy (services/network/public/cpp/declarative_performance_observer_parser.cc) in JavaScript, and validates itself against all nine cases in Chromium's declarative_performance_observer_parser_unittest.cc. It is a faithful model — not the browser's own network stack. The browser's own parsing is only observable by serving the header with chrome://flags/#declarative-performance-observer (or --enable-features=DeclarativePerformanceObserver, or an OT token) enabled and watching the report arrive at your endpoint.
