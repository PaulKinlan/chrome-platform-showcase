Early Entries Race

The problem this feature exists to solve, measured live: a PerformanceObserver registered late (like a lazy-loaded analytics script) misses every entry emitted before it ran — unless it asks for buffered: true, and even then it can never see a session that dies before JavaScript starts. This page emitted a real performance.mark("dpo-early-mark") from an inline script in <head>; register the late observers below and watch which columns catch it.

Experimental — server-activated. The declarative observer itself has no JavaScript API: it activates only when the navigation response carries a Performance-Observer header, and its only output is a report POSTed to the Reporting-Endpoints URL at session end. This page is served without that header, so the "declarative" column below is the documented contract from the explainer and Chromium implementation, not a live readout. To experiment for real in Chrome 151+: enable chrome://flags/#declarative-performance-observer and relaunch, or launch with --enable-features=DeclarativePerformanceObserver, or --enable-experimental-web-platform-features; as an origin trial, a DeclarativePerformanceObserver OT token on your own server works too — then serve the header pair from the Header Pair Builder.

After registering, switch to another tab and back to emit real visibility-state entries. Any click before registering counts as first input, which is exactly the LCP-finalising race real pages have.

what to look for

  • navigation and the early mark land only in the buffered column — the unbuffered observer registered too late, forever.
  • largest-contentful-paint is observer-only: getEntriesByType() returns nothing for it by spec, and LCP stops emitting after your first click/keypress.
  • longtask is observable imperatively but is not in Chromium's declarative vocabulary (navigation, mark, visibility-state, largest-contentful-paint) — the parser silently drops it from entry-types.
  • No JavaScript strategy — buffered or not — can report a session that crashes or never connects. That terminal session-end report is the declarative observer's unique capability.
