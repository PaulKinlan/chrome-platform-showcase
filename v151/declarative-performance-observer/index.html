Declarative Performance Observer

A browser-resident telemetry system activated by a single HTTP response header, Performance-Observer, paired with Reporting-Endpoints. Once the navigation response carries the header, the browser itself — not page JavaScript — collects the requested performance entries (navigation timing, allowlisted user-timing marks, visibility flips, largest contentful paint) and POSTs one consolidated application/reports+json report when the session ends: tab close, navigation away, BFCache entry, or even a renderer crash. With capture-early-failures, DNS/TLS-level navigation failures that never ran a byte of JavaScript are persisted and reported on the next successful visit.

concepts

  1. Early Entries Race

    Live comparison: a late imperative PerformanceObserver with and without buffered: true versus browser-resident collection — which real early entries (navigation, marks, visibility-state, LCP) each one actually catches.

  2. Header Pair Builder

    Compose the exact Performance-Observer + Reporting-Endpoints header pair with live validation against Chromium's directive vocabulary, then read back the real response headers this very page was served with.

  3. Parser Edge Cases

    Feed malformed, mistyped, and unknown-token header values through a faithful re-implementation of Chromium's structured-field parser — the same nine contracts its unit tests pin down.

  4. Session Report Preview

    Assemble the exact application/reports+json payload from this page's real performance timeline: real navigation timing, allowlist-filtered marks with detail, real visibility-state entries, and the terminal session-end entry.

why it's proposed

Every existing telemetry path — PerformanceObserver, sendBeacon, fetchLater() — depends on JavaScript having successfully started. A DNS timeout, an OOM kill on a low-end phone, or a tab swiped away before script ran is invisible to all of them, so sites cannot compute honest success rates for user journeys. Moving observation into the browser process makes the report survive renderer death, and the capture-early-failures origin flag makes even never-connected navigations reportable. In Chrome 151 this is an experimental dev-trial/origin-trial feature (ChromeStatus status: Proposed, pre-incubation explainer).
