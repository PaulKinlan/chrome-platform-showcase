Session Report Preview

At session end — tab close, navigation away, BFCache entry, or renderer crash — the browser POSTs one application/reports+json payload of type "performance-observer". This page assembles that exact payload from this page's real performance timeline: your actual navigation timing, your actual marks filtered through the include-user-timing allowlist, your actual visibility flips, plus the terminal session-end entry.

What is real vs modelled here: every navigation, mark, visibility-state and largest-contentful-paint entry in the preview is read live from this document's performance timeline — real values, not samples. The envelope and the terminal session-end entry are assembled by this page in the documented format, because the real report is built in the browser process and POSTed only when the session actually terminates (this page is served without the activating Performance-Observer header — see the Header Pair Builder). To watch a real report arrive you need Chrome 151+ with chrome://flags/#declarative-performance-observer (or --enable-features=DeclarativePerformanceObserver, or an OT token) and a server sending the header pair.

format contracts on display

  • Envelope: a JSON array of reports, each { type: "performance-observer", age, url, user_agent, body: { entries } }, sent with Content-Type: application/reports+json.
  • Failed navigations appear as synthesised PerformanceNavigationTiming entries whose unreached milestones are zeroed — a DNS failure ends at domainLookupStart with everything after it 0.
  • Marks carry their detail payload verbatim, so performance.mark("hero-image-loaded", { detail }) is the arbitrary-data channel.
  • The terminal entry is always { name: "session-end-event", entryType: "session-end", duration: 0 } — the proposed PerformanceSessionEndTiming, which reveals nothing but the time the session ended.
