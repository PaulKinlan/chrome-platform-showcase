v157 · css · product use case

Custom widgets that match native ones

A settings card mixes native controls — checkbox, radio, range, progress — with hand-built ones: a pressed chip, a count badge, a custom meter. One accent-color declaration tints the native family; with Chrome 157, background: AccentColor; color: AccentColorText paints the custom family with the browser's own pair, so the two can never drift. And because accent-color inherits, a nested override re-themes both families below it.

On a build without the Chrome 157 resolution, the custom family below honestly falls back to the design-system inks (and this page says so in its readout) while the native family still follows accent-color — exactly the drift this feature eliminates. No part of the custom family is scripted to copy the picker value; it is painted by the keywords or not at all.

code path

.theme-card { accent-color: var(--brand); }      /* native controls tinted */

.chip[aria-pressed="true"] {
  background: AccentColor;                       /* same color the UA tints with */
  color: AccentColorText;                        /* same readable foreground */
}

.urgent { accent-color: #8b0000; }               /* inherits down: native AND
                                                    custom re-theme together */
