← AccentColor & AccentColorText follows accent-color value

v157 · css · behavioral probe

Does your browser follow the value?

Chrome 157's change is observable in one comparison: give a box accent-color: <your pick>, paint a child with color: AccentColor, and read both back with getComputedStyle(). If the two resolved colors are equal, the keyword follows the element's accent — the new behavior. If the keyword resolves but to something else, you are seeing the legacy global OS accent. If the declaration never parses, the keyword isn't available in this context at all.

Chrome ships the follows-accent-color resolution in Chrome 157 with no dedicated runtime flag. On earlier builds the keywords may be missing outside installed web apps (they shipped to stable in web-app scope in Chrome 150, flag CSSAccentColorKeyword / --enable-blink-features=CSSAccentColorKeyword), or may resolve to the OS accent instead of the element's value. The probe below reports whichever of the three states your browser is really in — it never fakes a pass.

box.append(child); document.body.append(box);

const accent  = getComputedStyle(box).accentColor;  // canonical rgb()
const keyword = getComputedStyle(child).color;
