Request shape matrix

What happens at the edges: passive plus credential types Chromium refuses to combine, passwords without a passkey request, the spec’s sibling 'active' value, 'immediate' under conditional mediation, an unknown value, and the pre-146 prototype shape that no longer means “passive”. Each row runs live; nothing that would open a modal is fired.

Developer trial — behind a flag, desktop only. To see the real passive prompt:

  1. Open chrome://flags/#web-authentication-ambient-signin, set it to Enabled, relaunch.
  2. Command-line equivalent: --enable-features=WebAuthenticationAmbientSignin (this also switches on the renderer’s WebAuthenticationAmbient runtime feature).
  3. --enable-blink-features=WebAuthenticationAmbient or --enable-experimental-web-platform-features enable only the renderer half: the request is accepted, but the browser downgrades it to ordinary conditional (autofill) mediation and no capability key is reported.
  4. You need a passkey or saved password for this site. If you don’t have one, the prompt correctly never appears and the promise never settles.

Chromium enables this on Windows, macOS, Linux and ChromeOS only (kOsDesktop flag, desktop-only origin trial list) — on Android the probes below honestly report “not available”.

migration notes

  • Feature-detection key renamed. Chrome 153 with the flag reports ambientGet: true; Chromium main now reports the spec name conditionalPassiveGet (PR #2485). Check both during the transition: caps.conditionalPassiveGet || caps.ambientGet.
  • Opt-in became explicit. Until Chrome 146 the prototype treated any conditional request that also asked for passwords as ambient when the flag was on (per the Chromium team’s own sample). From 146 you must pass uiMode: 'passive'; an old-style { mediation: 'conditional', password: true, publicKey } is plain autofill again.
  • Unsupported browsers degrade safely. Engines that don’t know passive mode either ignore the member or (Chromium without the flag) accept it and run ordinary conditional mediation — never a modal. That is why, unlike uiMode: 'immediate', a stray passive request cannot ambush users with a dialog.
  • Kill switch. If the browser-side feature is disabled while the renderer still accepts the value, Chromium downgrades the request to conditional mediation “so that sites using conditional UI with login forms are not broken” (authenticator_common_impl.cc).
