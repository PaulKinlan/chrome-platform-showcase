Passive sign-in request

The canonical call, for real: navigator.credentials.get({ mediation: 'conditional', uiMode: 'passive', publicKey }) on a page with no sign-in form. If you have a passkey for this site, the browser offers it in a quiet, non-modal suggestion you can ignore. If you have none, nothing appears and the promise simply stays pending — this page shows that pending state live instead of pretending something happened.

Behind a flag — no shipping milestone yet. ChromeStatus lists this as Proposed. To run the real success path: open chrome://flags/#web-authentication-ambient-signin, set it to Enabled and relaunch; or launch Chrome/Canary with --enable-features=WebAuthenticationAmbientSignin (that browser feature also switches on the Blink runtime feature WebAuthenticationAmbient). --enable-blink-features=WebAuthenticationAmbient on its own flips only the renderer half. The prototype targets desktop (Windows, macOS, Linux, ChromeOS).

1 · Is passive mode on in this browser?

Read straight from PublicKeyCredential.getClientCapabilities(). The spec key is conditionalPassiveGet; Chromium's prototype has also reported it as ambientGet, so both are read and the one that answered is named.

2 · Have a passkey for this site? (optional)

A passive request only shows UI when a discoverable credential for this origin exists. This creates a real passkey with navigator.credentials.create() in your chosen authenticator. Delete it later from your password manager.

3 · The passive request

Starts automatically on load when passive mode is reported available — the explainer's intended pattern, since it needs no user activation. You can also start or abort it by hand.

what to expect

  • Flag on + passkey here: a small bubble near the address bar offers the account. Picking it resolves the promise with a real PublicKeyCredential; ignoring it leaves the page fully usable.
  • Flag on + no passkey: no UI at all, and the promise stays pending — by design, so a site cannot learn whether you have an account.
  • Flag off: 'passive' is still a valid uiMode value in Chromium (it shares the enum with 'immediate'), so the call is accepted and quietly runs as ordinary autofill-style conditional mediation. With no webauthn input on this page, nothing appears. That is why support is read from the capability, never from "the call didn't throw".
const caps = await PublicKeyCredential.getClientCapabilities();
if (caps.conditionalPassiveGet) {
  const cred = await navigator.credentials.get({
    mediation: 'conditional',
    uiMode: 'passive',
    publicKey: { challenge, rpId },   // challenge from your server
    signal: controller.signal,        // so you can cancel it later
  });
  // send cred.toJSON() to the server to verify, then show the signed-in view
}
