Web Authentication Conditional UI Passive Mode

Conditional mediation today only surfaces passkeys through a sign-in form's autofill. Passive mode — prototyped in Chrome as "ambient" sign-in — adds uiMode: 'passive' to navigator.credentials.get({ mediation: 'conditional' }): on any page, with no form, the browser shows a quiet, non-modal suggestion of the user's passkeys for the site. No credentials, no UI, and the promise never resolves — so sites can call it on page load without user activation and without leaking whether the visitor has an account. Feature detection is the new conditionalPassiveGet client capability.

Not shipping yet. ChromeStatus: Proposed, no milestone. To run the real thing: chrome://flags/#web-authentication-ambient-signin → Enabled → relaunch; or launch Chrome/Canary with --enable-features=WebAuthenticationAmbientSignin (the browser feature device::kWebAuthnAmbientSignin, which also turns on the Blink runtime feature WebAuthenticationAmbient). --enable-blink-features=WebAuthenticationAmbient or --enable-experimental-web-platform-features alone enables only the renderer half (observed in Chromium 153): the capability key never appears. Chromium source names a WebAuthenticationAmbient origin trial for Windows, macOS, Linux and ChromeOS, but ChromeStatus lists no trial, and Android is not among the prototype's platforms.

concepts

  1. Passive sign-in request

    Basic. The canonical call on a page with no form: reads the capability, starts the real passive request on load when supported, shows the live pending state and elapsed time, and lets you abort it. Create a real demo passkey to see the success path; the resolved assertion's clientDataJSON, challenge echo and authenticator flags are decoded in the page.

  2. Capability inspector

    Inspection tool. Three independent probes — the full getClientCapabilities() map (spec conditionalPassiveGet and Chromium's prototype ambientGet), a TypeError enum probe for the uiMode member, and a with/without differential only the passive code path can produce — combined into a verdict that tells "fully on", "renderer only" and "off" apart.

  3. Paywall unlock

    Practical product use. The explainer's own example: a paywalled article that fires a passive request on load and unlocks in place when the reader takes the suggestion, with focus moved and the change announced. The header "Sign in" button cancels the quiet request before opening the explicit prompt and re-arms it if dismissed; unsupported browsers get only the normal path.

  4. Request edge cases

    Edge, failure & migration. Seven real calls, each with the predicted outcome beside the observed one: an invalid uiMode, passive without publicKey, passive plus federated, an already-aborted signal, aborting mid-flight, two requests at once, and whether adding uiMode: 'passive' to a shipped conditional call is safe before browsers support it.

  5. Passive + autofill on one page

    Advanced composition. One get() call driving two surfaces — the passive suggestion and autocomplete="username webauthn" autofill — with optional password: true. Toggle the parts, arm and cancel the request, and watch a typed password submission abort it cleanly. Results branch on cred.type.

why it is proposed

Sites where signing in is optional but makes things better — news, shopping, social — lose users who never notice they are signed out, or who expect signing in to be a chore. Autofill conditional UI cannot help on a page without a sign-in form, and a modal get() on page load is hostile to visitors who have no passkey. Passive mode fills the gap with a suggestion that is easy to take and easy to ignore. Unlike immediate mode it needs no user activation and never rejects to say "no credentials", which is what makes it safe to call on load. The October 2026 explainer revision adds a louder sibling, uiMode: 'active' (capability conditionalActiveGet), for flows where sign-in is a necessary step.

the proposed surface

// Credential Management: CredentialRequestOptions gains a uiMode member
enum CredentialUiModeRequirement { "active", "immediate", "passive" };   // Chromium IDL
dictionary CredentialRequestOptions {
  CredentialMediationRequirement mediation = "optional";
  CredentialUiModeRequirement uiMode = "active";
  PublicKeyCredentialRequestOptions publicKey;
  boolean password = false;
  AbortSignal signal;
  // …
};
// WebAuthn: two new ClientCapability values (w3c/webauthn#2485)
enum ClientCapability { …, "conditionalActiveGet", "conditionalPassiveGet", … };

const caps = await PublicKeyCredential.getClientCapabilities();
if (caps.conditionalPassiveGet) {
  const cred = await navigator.credentials.get({
    mediation: 'conditional', uiMode: 'passive', publicKey, signal,
  });
}
