Request edge cases

Seven real calls at the edges of the passive-mode contract — invalid values, missing publicKey, unsupported credential mixes, cancellation before and during the request, two requests at once, and the migration question every team asks: is it safe to add uiMode: 'passive' to the conditional call we already ship? Each card prints what the spec or Chromium source predicts next to what this browser actually did. No request is left pending: every probe aborts its own request within a second.

Behind a flag — no shipping milestone yet. Cases 3 and 7 change outcome when chrome://flags/#web-authentication-ambient-signin is enabled (or Chrome is launched with --enable-features=WebAuthenticationAmbientSignin); the rest describe behaviour that is already observable. One edge is described but deliberately not run: uiMode: 'passive' without mediation: 'conditional' is not passive at all — Chromium only takes the passive path for the conditional + passive pair, so it would open the ordinary modal passkey dialog.
