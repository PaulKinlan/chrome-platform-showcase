Passive + autofill on one page

The explainer's compatibility promise, composed: one navigator.credentials.get() call feeds two browser surfaces. With uiMode: 'passive' the suggestion appears immediately; if the user ignores it and focuses the autocomplete="username webauthn" field, the same request also shows its credentials in autofill. Adding password: true lets saved passwords join the same request. Whichever surface the user picks, the one promise settles — and typing a password by hand cancels it cleanly.

Behind a flag — no shipping milestone yet. Enable chrome://flags/#web-authentication-ambient-signin and relaunch, or launch with --enable-features=WebAuthenticationAmbientSignin. Without it the request still runs as ordinary conditional mediation, so the autofill half works in any Chromium with passkeys — the honest fallback. Demo honesty: nothing is sent to a server; a typed password is never read or stored.

    why one request

    Two parallel requests would race: Chromium allows one WebAuthn request per frame, so a separate autofill call would reject or cancel the passive one. The spec PR instead extends the existing conditional algorithm — a conditionalNonAutofillTriggered flag makes the passive prompt fire once, while the form-control branch stays live, and "if the user selects a credential in either of the above prompts" the same assertion flow continues.

    const controller = new AbortController();
const cred = await navigator.credentials.get({
  mediation: 'conditional',
  uiMode: 'passive',          // quiet suggestion now…
  publicKey: options,         // …and webauthn autofill on focus
  password: true,             // saved passwords in the same surfaces
  signal: controller.signal,
});
form.onsubmit = () => controller.abort();   // typed password wins: cancel the request
if (cred.type === 'public-key') verifyAssertion(cred.toJSON());
else if (cred.type === 'password') verifyPassword(cred.id, cred.password);
