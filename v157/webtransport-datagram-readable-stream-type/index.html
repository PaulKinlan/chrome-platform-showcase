WebTransport Datagram readable stream type

Datagrams are messages — zero or more bytes, delivered whole or not at all. A readable byte stream treats data as an undifferentiated byte sequence, which quietly loses empty datagrams and can merge message boundaries. Chrome 157 makes transport.datagrams.readable a default ReadableStream and adds the datagramsReadableType: "bytes" constructor option for applications that want BYOB allocation control badly enough to opt back in.

concepts

  1. Does this build read the option?

    A dictionary roll-call with throwing getters says whether datagramsReadableType is converted by this build's constructor — bracketed by a must-fire and a must-not-fire control — and an invalid enum value shows the TypeError a reading build must raise.

  2. BYOB or not: the observable difference

    Construct one transport with defaults and one with datagramsReadableType: "bytes", then ask each real datagrams.readable for a BYOB reader. Which one throws TypeError is the whole feature, observable with no server at all — and it distinguishes new Chrome, old Chrome, and Firefox.

  3. What byte streams do to messages

    The reason the default changed: feed the same three datagrams — including an empty one — through a real default stream and a real byte stream, and watch the byte stream refuse the empty message and a min read merge two messages into one buffer.

why it shipped

Chromium originally exposed incoming datagrams as a readable byte stream. That looked like a power feature — BYOB readers let an application bring its own buffers and control allocation — but it fought the semantics of datagrams themselves. A byte stream cannot represent an empty datagram (byte-stream chunks must have non-zero length), and a BYOB read with a minimum byte count can span two datagrams, destroying the message delineation the protocol promised. The spec therefore made the default a default readable stream, where each chunk is exactly one datagram, and moved the byte-stream behaviour behind an explicit constructor opt-in: datagramsReadableType: "bytes".

the API

// Default: each read() resolves exactly one datagram, empty ones included.
const t1 = new WebTransport(url);
const r1 = t1.datagrams.readable.getReader();          // default reader

// Explicit opt-in: a readable byte stream, for BYOB allocation control.
const t2 = new WebTransport(url, { datagramsReadableType: "bytes" });
const r2 = t2.datagrams.readable.getReader({ mode: "byob" });
const { value } = await r2.read(new Uint8Array(65536)); // bring your own buffer

The option's type is the Streams spec's ReadableStreamType enum — its only member is "bytes", so any other string throws a TypeError at construction on a build that reads the member.
