Does this build read the option?

Dictionary members are converted synchronously at construction, so an options bag whose property is a getter that throws answers "was this member read?" before any network work happens. Two control members bracket the result; a third probe hands the constructor an invalid enum value, because a build that reads the member must reject it with a TypeError.

Chrome targets datagramsReadableType for Chrome 157 behind the WebTransportDatagramsReadableType runtime flag — launch with --enable-blink-features=WebTransportDatagramsReadableType, or flip chrome://flags/#enable-experimental-web-platform-features and relaunch. Nothing listens at the probe URL, so no session is ever established; only the synchronous dictionary conversion is exercised.

    The invalid-value cross-check

    The option's type is the Streams enum ReadableStreamType, whose only member is "bytes". WebIDL enum conversion must throw a TypeError for any other string — but only on a build that reads the member at all. That makes the throw itself a second, independent detection signal.

    code path

    function memberIsRead(name) {
  const marker = "ROLLCALL_" + name;
  try {
    new WebTransport("https://127.0.0.1:44443/never", {
      get [name]() { throw new Error(marker); },
    });
    return false;                      // getter never fired
  } catch (e) {
    return e.message === marker;       // fired — the member is converted
  }
}

// Independent cross-check: invalid enum value must throw TypeError
// on a build that reads the member, and do nothing on one that doesn't.
try {
  new WebTransport(url, { datagramsReadableType: "not-a-real-type" });
} catch (e) {
  e instanceof TypeError;              // true on Chrome 157+
}
