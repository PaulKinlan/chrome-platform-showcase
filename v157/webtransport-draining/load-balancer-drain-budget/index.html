v157 · webtransport draining

Load-balancer drain budget

When an HTTP/3 server emits DRAIN_WEBTRANSPORT_SESSION (0x78ae), the client still needs enough time to receive the capsule, dial a replacement session, and let its longest tail streams finish before the container orchestrator sends SIGKILL. code path

// Server + client coordination during rolling restart:
// 1. Orchestrator sends SIGTERM to pod (terminationGracePeriodSeconds: 15).
// 2. HTTP/3 server immediately writes DRAIN_WEBTRANSPORT_SESSION (0x78ae)
//    on every open WebTransport CONNECT stream.
// 3. Browser resolves wt.draining, dials replacement session within 1 RTT,
//    and stops opening new streams on the draining session.
wt.draining.then(async () => {
  const nextSession = new WebTransport(endpointUrl);
  await nextSession.ready;
  router.promoteSession(nextSession);
});
