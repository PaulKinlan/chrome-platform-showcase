The opt-in handshake, three ways

An enforcing embedder requires; the framed response decides its own fate. These three frames are navigated with the same connectionallowlist='(response-origin)' requirement, against three real routes on this server: one opting in with a strict-enough Connection-Allowlist, one delegating with Allow-Connection-Allowlist-From: *, and one answering with no headers at all — the frame an enforcing browser must refuse to load. Outcomes below come from real load events and each frame's own postMessage report.

On a build without the origin trial (see the feature banner for the exact flag), the attribute is inert, so all three frames load and say so — the visible difference between a build that enforces and one that doesn't is itself the demo. The frame that must block on an enforcing build is clearly marked.
