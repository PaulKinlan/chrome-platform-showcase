Connect and attach

The first button opens Chrome's device chooser — pick any BLE device in range. The page connects its GATT server, calls server.addEventListener("maxwritewithoutresponsesizechanged", …) when the server is an EventTarget, always attaches the device-level gattserverdisconnected listener, and writes nothing to the device.

code path

const device = await navigator.bluetooth.requestDevice({ acceptAllDevices: true });
const server = await device.gatt.connect();

// New in Chrome 157 — the server-level listener. Attempted for real above.
if (server instanceof EventTarget) {
  server.addEventListener("maxwritewithoutresponsesizechanged", () => {
    // Connection-level fact changed; re-read it off the server.
  });
}

// Unchanged — connection loss still fires on the device.
device.addEventListener("gattserverdisconnected", () => { /* reconnect */ });

Note what the page does when the server is not an EventTarget: it skips the server-level attach and says so in the log, rather than crashing on a missing method — exactly the guard code shipping today needs until 157 is everywhere it runs.

the failure modes, named

Each is a real outcome of the button above, not a hypothetical: NotFoundError — the chooser was dismissed, or no adapter is present; SecurityError — permissions policy or a non-secure context blocked the call; NetworkError — the device went out of range between choosing and connecting; TypeError before any of those — navigator.bluetooth itself is absent, which is where the availability notes on the feature page apply.
