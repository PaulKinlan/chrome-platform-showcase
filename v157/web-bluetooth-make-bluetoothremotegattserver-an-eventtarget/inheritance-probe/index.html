The whole feature is one edge in the prototype graph, which makes it one of the few Web Bluetooth changes measurable without a device, an adapter, or a permission prompt. Four checks, each against the exact surface the spec names, each capable of returning false — and on a pre-157 browser, returning it.

Chrome 157 inserts EventTarget.prototype between BluetoothRemoteGATTServer.prototype and Object.prototype. Before 157 the server's prototype chains directly to Object.prototype; the three methods do not exist on it anywhere.

why the fourth check matters

A library could bolt addEventListener onto BluetoothRemoteGATTServer.prototype as an own method — polyfills for this exact gap exist. The spec change is stronger: the methods must resolve through EventTarget.prototype, so server instanceof EventTarget is true and the functions are identical to the ones every other target shares. The probe therefore checks that the methods are reachable but are not own properties of the server's prototype — the signature of real inheritance, and the reason this could not ship behind a flag: Web IDL cannot conditionally rewire a base interface.
