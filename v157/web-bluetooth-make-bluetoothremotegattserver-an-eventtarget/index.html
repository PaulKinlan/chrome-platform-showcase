The GATT server learns to listen

Chrome 157 changes one line of Web IDL: interface BluetoothRemoteGATTServer : EventTarget. The object that represents an active GATT connection gains addEventListener(), removeEventListener(), and dispatchEvent() — three methods and no events of its own, yet. It is the socket that connection-level events plug into, starting with the separately proposed maxwritewithoutresponsesizechanged.

concepts

  1. The inheritance, probed

    Four exact checks against BluetoothRemoteGATTServer.prototype: is the interface exposed, is its prototype's prototype EventTarget.prototype, do the three methods resolve, and do they resolve by inheritance rather than as copies. Every check can come back false, and on a pre-157 browser it honestly does.

  2. Listeners on a live connection

    The real flow: requestDevice() behind a button, gatt.connect(), then server.addEventListener() — attempted for real, with the exact exception surfaced when the browser, adapter, or permission is not there.

  3. Device listeners vs server listeners

    Today connection loss is heard on the device (gattserverdisconnected). This page puts the old pattern and the new one side by side, feature-detects which your browser has, and lets you drive a plain-EventTarget re-enactment of both — clearly labelled as an illustration, never as real Bluetooth.

  4. The surface, inventoried

    Walk BluetoothRemoteGATTServer's prototype chain in this browser and diff every member against the Chrome 157 spec surface — what is there, what arrives with this feature, and what belongs to the flag-guarded sibling feature instead.

why it shipped

BluetoothRemoteGATTServer represents the live connection to a device — but until now it was a plain interface, so anything that happened to the connection had to be reported somewhere else. Connection loss is delivered as gattserverdisconnected on the BluetoothDevice, one object up, because the device was the nearest EventTarget available. New connection-level facts, like the negotiated write size changing mid-transfer, had nowhere natural to land at all.

Making the server an EventTarget fixes the plumbing. It is deliberately shipped on its own, apart from the maxWriteWithoutResponseSize property and its change event, for a Web IDL mechanics reason: inheritance cannot be conditionally enabled behind a runtime flag, so the base-interface change had to be unconditional and separately reviewed. The guarded property and event ride in a sibling CL and a sibling feature entry.

the API shape

const device = await navigator.bluetooth.requestDevice({ acceptAllDevices: true });
const server = await device.gatt.connect();

// New in Chrome 157: the server is an EventTarget.
server instanceof EventTarget;               // true
server.addEventListener("maxwritewithoutresponsesizechanged", onSizeChange);

// The pre-157 pattern still works — connection loss stays on the device.
device.addEventListener("gattserverdisconnected", onDisconnect);

The inheritance itself adds no events. It adds the standard listener API, so that events proposed at the connection level — starting with maxwritewithoutresponsesizechanged — have a spec-correct object to fire on.

availability

The change ships enabled for all users in Chrome 157 wherever Web Bluetooth exists — there is no chrome://flags entry, no origin trial, and no Finch rollout for the inheritance, because Web IDL inheritance cannot be flag-guarded. On the Chromium these pages were built with (141, Linux), BluetoothRemoteGATTServer.prototype still chains directly to Object.prototype: the probes on these pages measured that and say so rather than pretending. Two separate availability gates matter and the pages keep them apart: Web Bluetooth as a whole is stable on Android, ChromeOS, macOS and Windows but still experimental on desktop Linux (enable chrome://flags/#enable-experimental-web-platform-features or launch with --enable-experimental-web-platform-features), and iOS Chrome / Android WebView do not expose it at all. Firefox and Safari do not implement Web Bluetooth.
