The surface, inventoried

One button walks BluetoothRemoteGATTServer.prototype with Object.getOwnPropertyNames(), hop by hop up the chain, and diffs every member found against the Chrome 157 spec surface — pre-existing members, the ones this feature makes reachable, and the two that belong to a different, flag-guarded feature entirely.

Walk the prototype

The walk runs once on load — it is a synchronous read of property names, prompting for nothing — and the button re-runs it against the current state of the prototype.

Walking…

The two flag-guarded members are listed for completeness but are not part of this feature: maxWriteWithoutResponseSize and onmaxwritewithoutresponsesizechanged ship separately behind the Blink runtime flag WebBluetoothMaxWriteWithoutResponseSize (enable with --enable-blink-features=WebBluetoothMaxWriteWithoutResponseSize on a build that has the CL) and have their own feature entry. The inheritance itself has no flag — Web IDL cannot conditionally change a base interface, which is exactly why it is its own ChromeStatus entry.

reading the diff

On a pre-157 browser with Web Bluetooth, the walk finds the six original members and stops at Object.prototype — the three EventTarget methods show as missing, which is the honest answer. On Chrome 157 they show as found, one hop up, shared with every other target on the platform. On a browser without Web Bluetooth at all, there is nothing to walk, and the table says that instead of showing an empty pass. Anything the walk finds that the spec does not name lands in the unexpected extras count — that is how a vendored polyfill or a leaked global gives itself away.
