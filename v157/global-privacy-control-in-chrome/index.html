Global Privacy Control in Chrome

Chrome 157 gives eligible users a privacy setting that sends a universal opt-out-of-sale/share request to every site: when it is on, Chrome appends the Sec-GPC: 1 request header to outgoing requests and exposes navigator.globalPrivacyControl === true to scripts. Sites read either surface to honour the request, and can declare that they abide by GPC at /.well-known/gpc.json.

concepts

  1. Signal reader — read the real signal both ways: the navigator.globalPrivacyControl property (window and worker scope) and a live server echo of the Sec-GPC request header this page actually sent — then check the two agree, as the spec requires.
  2. Honoring the signal — what a compliant site does with it: a preferences center whose "sale/share of data" default is genuinely driven by the visitor's real GPC signal, with the decision table the spec's header semantics imply.
  3. Well-known compliance — the other direction: origins declare GPC support at /.well-known/gpc.json. Fetch real served variants (valid, refusing, invalid lastUpdate, wrong type, missing) and validate each against the spec's "unknown unless valid" rules.

why it shipped

Several US state privacy laws (starting with the CCPA/CPRA) recognise a universal opt-out preference signal that businesses must honour as a valid do-not-sell-or-share request. Firefox and Brave have sent GPC for years; Chrome 157 adds the user-facing setting, the Sec-GPC header, and the navigator.globalPrivacyControl API so the signal is consistent across the platform. The spec pins the DOM property to the value at navigation time (gpcAtNavigation), so a mid-session settings change only shows up after a reload — one of the edge cases the demos probe.
