Canonicalization, read back with get()

Every Sanitizer canonicalizes its configuration at construction, and get() returns that canonical form — so the javascriptURLs policy is never implicit. The spec fills a missing member with permissive defaults for a bare dictionary (true, keep) but the "default" safe preset carries false (strip). This page constructs four sanitizers, reads all four answers back, and exercises the setJavascriptURLs() changed/no-op return contract.

Chrome ships the option in Chrome 157 (no dedicated flag). The Sanitizer API itself is runtime-flag SanitizerAPI — on a pre-146 build launch with --enable-blink-features=SanitizerAPI or flip chrome://flags/#enable-experimental-web-platform-features. On a build with the API but not the option, this probe reports the member missing from get() — it deliberately never treats "the constructor ignored my unknown dictionary member" as support.

The setJavascriptURLs() return contract

The mutator returns true when it changed the configuration and false when it was a no-op. The run button above also performs this sequence on the "default" preset (starting value false):

const s = new Sanitizer();        // "default" → javascriptURLs: false
s.setJavascriptURLs(true);        // expect true  (false → true: changed)
s.setJavascriptURLs(true);        // expect false (already true: no-op)
s.setJavascriptURLs(false);       // expect true  (true → false: changed)
s.get().javascriptURLs;           // expect false
