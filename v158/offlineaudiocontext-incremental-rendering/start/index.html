Minimal chunked render starter

The smallest working pull loop: build a two-second stereo graph, call startRendering(4096) until the context closes itself, and count what came back. A second button does the open-ended version: a context built with length: null, rendered for one second and stopped with close().

How it works

  1. Detect support with typeof OfflineAudioContext.prototype.close === "function". The explainer recommends this because startRendering's arity did not change, so it cannot be detected directly.
  2. Each startRendering(chunkSize) call renders the next slice of the graph and resolves with an AudioBuffer holding only that slice. Call it again until ctx.state === "closed".
  3. A context with a fixed length closes itself after the last frame. A context built with length: null (or no length) never ends, so you stop it with await ctx.close().

Common errors and fixes

  • NotSupportedError from the constructor with length: Infinity: the explainer text says Infinity, but Chrome 158 only accepts null or an omitted length.
  • NotSupportedError "chunk size cannot be zero": startRendering(0) throws. Pass a positive size, or no argument.
  • Chunks bigger than you asked for: Chrome renders whole 128-frame render quanta, so startRendering(300) returns 384 frames. Use multiples of 128 for a hard cap (see quantum rounding).
  • InvalidStateError "in a stopped state": you called startRendering after the context closed. Check ctx.state in the loop condition.
  • oncomplete hands you a short buffer: with chunked pulls, event.renderedBuffer is only the final chunk. Keep the chunks the promises resolve with instead. After an explicit close(), complete does not fire at all.

Findings

Chrome for Testing 158.0.8127.36, no flags, 2026-11-27: the 2 s stereo context at 48 kHz (96,000 frames) came back as 24 chunks, 23 of 4096 frames and a final one of 1,792, and the context read "closed" after the last pull. The length: null context reported length === null, rendered 12 chunks of 4096 frames (49,152 frames, just over one second) and read "closed" after close(). Headless runs have no audio output, so these are frame counts, not listening tests.
