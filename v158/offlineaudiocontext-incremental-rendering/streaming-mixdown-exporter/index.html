A mixdown exporter with real progress

This is what incremental rendering is for: a bounce-to-file flow that shows honest progress and never holds the whole mix in memory. A three-second arrangement (three detuned oscillators under an amplitude envelope) renders in 8192-frame chunks; each chunk advances the progress bar, extends the waveform, and is immediately converted to 16-bit PCM and appended to the growing WAV — the float chunk is then garbage. On a pre-158 build the same page falls back to one labelled one-shot render, so the exporter stays useful everywhere.

The downloadable WAV is produced either way; what changes is the memory shape. Chunked: largest live audio allocation ≈ 8192 frames (32 KB of floats). One-shot: the full 132 300-frame buffer (~529 KB here — and ~1.27 GB for an hour of stereo at 44.1 kHz, which is the point). Flag for pre-158 builds: --enable-blink-features=OfflineAudioContextIncrementalRendering.

const ctx = new OfflineAudioContext({ numberOfChannels: 1, sampleRate: 44100, length: 44100 * 3 });
buildArrangement(ctx);

const pcmParts = [];                       // Int16 chunks, not floats
let rendered = 0;
while (rendered < ctx.length) {
  const chunk = await ctx.startRendering(8192);
  pcmParts.push(toInt16(chunk.getChannelData(0)));   // 8192 frames live at a time
  rendered += chunk.length;
  progress.value = (rendered / ctx.length) * 100;    // real progress, no suspend() hacks
}
const wav = new Blob([wavHeader(rendered), ...pcmParts], { type: "audio/wav" });
