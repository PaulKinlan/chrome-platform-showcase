The chunk loop, timed and trimmed

One second of mono audio at 8000 Hz — 8000 frames — rendered by calling startRendering(2048) in a loop. The shipped contract has three visible fingerprints: every chunk is its own small AudioBuffer, requested sizes round up to the render quantum (2048 happens to be 16 quanta, so it stays 2048), and the final chunk is trimmed to the 1856 frames that remain. The probe is behavioral: if the first call comes back with all 8000 frames, your browser ignored the argument — the pre-158 one-shot.

Chrome ships incremental rendering in Chrome 158. On earlier builds, enable it with --enable-blink-features=OfflineAudioContextIncrementalRendering (or chrome://flags/#enable-experimental-web-platform-features) — if the build predates the flag entirely, this page runs the loop anyway and reports the honest one-shot outcome it observes.

const ctx = new OfflineAudioContext({ numberOfChannels: 1, sampleRate: 8000, length: 8000 });
const osc = new OscillatorNode(ctx, { frequency: 220 });
const gain = new GainNode(ctx, { gain: 0.8 });
osc.connect(gain).connect(ctx.destination);
osc.start();

let total = 0, calls = 0;
while (total < ctx.length) {
  const chunk = await ctx.startRendering(2048);  // 158: ≤2048 frames each
  total += chunk.length; calls++;
  draw(chunk);                                   // 2048, 2048, 2048, 1856 (trimmed)
  if (calls === 1 && chunk.length === ctx.length) break; // pre-158: one-shot, arg ignored
}
