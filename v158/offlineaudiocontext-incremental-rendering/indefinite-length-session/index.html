No length, no limits (and the error ladder)

The quiet half of this feature is in the constructor: OfflineAudioContextOptions.length is now optional. Omit it and you get an indefinite context — length reads null and rendering continues for as long as you keep calling startRendering(), one render quantum per unspecified chunk. On every pre-158 build, that same constructor call throws a TypeError, which makes this the cleanest honest probe the feature has. Below it: the full error ladder the shipped implementation enforces.

Chrome 158 ships this by default; earlier builds need --enable-blink-features=OfflineAudioContextIncrementalRendering or chrome://flags/#enable-experimental-web-platform-features. Every probe on this page calls the real constructor/method and prints the real exception name and message — nothing is predicted.

code path

// 158+: constructs an indefinite context          // pre-158: TypeError
const live = new OfflineAudioContext({ numberOfChannels: 1, sampleRate: 8000 });
live.length;                        // null — no predetermined end

await live.startRendering();        // one render quantum (128 frames) per call
await live.startRendering(0);       // NotSupportedError: chunk size cannot be zero
await live.startRendering(2 ** 31); // NotSupportedError: chunk size too large

const done = new OfflineAudioContext({ numberOfChannels: 1, sampleRate: 8000, length: 512 });
await done.startRendering();        // renders all 512 remaining frames
await done.startRendering();        // InvalidStateError: already rendered all frames
