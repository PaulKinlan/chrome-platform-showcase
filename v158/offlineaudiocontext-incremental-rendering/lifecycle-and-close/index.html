Lifecycle, close(), and the indefinite context

Incremental rendering reshapes the OfflineAudioContext lifecycle: startRendering() becomes repeatable, a finite context closes itself when the last frame is delivered, close() exists to stop an open-ended render, and length can describe a context with no end at all. Every experiment below runs the real call on this build and reports the real result — including the errors.

Chrome targets incremental rendering for Chrome 158 behind the OfflineAudioContextIncrementalRendering runtime flag (--enable-blink-features=OfflineAudioContextIncrementalRendering, or chrome://flags/#enable-experimental-web-platform-features). On a pre-158 build the experiments still run — their outcomes are the old contract, which is exactly what makes the difference visible.

The explainer's feature-detection advice is to check for close(). This runs typeof OfflineAudioContext.prototype.close, and — where it exists — creates a context, renders one chunk, closes it, and tries to render again.

Experiment 2 · The second startRendering() call

Pre-158, a second call is always an InvalidStateError — one shot is all you get. With incremental rendering, repeat calls are the whole point until the context closes; after that the same error returns. This renders a tiny context to completion, then calls again.
