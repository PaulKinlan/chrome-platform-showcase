Return-shape probe: what does this build hand back?

setMicrophoneActive() and setCameraActive() have existed since Chrome 93, so typeof tells you nothing about this feature. The Chrome 158 change is what the call returns: undefined before, a Promise<undefined> after. This page makes both calls for real and inspects the value that actually comes back — and when it is a promise, awaits it and shows the resolution value the spec requires.

This change ships in Chrome 158 with no dedicated runtime flag — it is a WebIDL return-type alignment in Blink>Media>Session, so there is nothing to enable in chrome://flags. On an older build the calls below simply return undefined; that legacy result is the honest answer, not a demo failure. Passing false declares "this page considers the microphone/camera inactive" — with no capture running it is a no-op declaration, safe to call.

Make the real calls

Each run calls navigator.mediaSession.setMicrophoneActive(false) and navigator.mediaSession.setCameraActive(false) and records String(ret), ret instanceof Promise, and — when a promise came back — its awaited settlement.
