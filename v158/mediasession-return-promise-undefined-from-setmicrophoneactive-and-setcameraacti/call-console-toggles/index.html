Call console: toggles, action handlers and the acknowledgement

In a real call UI the capture-state setters run constantly: every mute click calls setMicrophoneActive(), every camera click calls setCameraActive(), and "togglemicrophone" / "togglecamera" action handlers let the browser or OS media hub drive the same toggles from outside the page. The Chrome 158 promise is the missing acknowledgement: the moment it resolves, the page knows the user agent has accepted the declared state.

Ships in Chrome 158, no runtime flag. This control bar declares capture state and registers real action handlers, but deliberately starts no actual microphone or camera capture — the changed surface is the setters' return value, and it is observable permission-free. During real capture, these declarations keep the tab's mute indicator and the OS media controls truthful; the panel below is this page's own labelled state readout, not a mock of browser UI.

    async function declareMic(active) {
  // Safe on 93–157 (undefined) and 158+ (Promise<undefined>):
  await Promise.resolve(navigator.mediaSession.setMicrophoneActive(active));
  ui.micPressed = active;            // flip UI only once acknowledged
}

navigator.mediaSession.setActionHandler("togglemicrophone", () => {
  declareMic(!ui.micPressed);        // browser/OS UI drives the same path
});
