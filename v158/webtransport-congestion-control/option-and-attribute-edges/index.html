Dictionary edges and the readonly attribute

Three sharp corners, each probed with a real call: an invalid enum string must throw a TypeError synchronously at construction; the attribute lives on WebTransport.prototype as a readonly accessor (so a strict-mode write must throw, and the value is per-instance but the getter is shared); and on pre-158 builds the option is an ignored unknown dictionary member — the constructor swallowing it proves nothing, which is exactly why the probe below never counts it as support.

Chrome 158 ships both surfaces (flag WebTransportCongestionControl on earlier builds). The invalid-enum probe behaves differently in a useful way: on a build with the feature, Web IDL enum conversion rejects "fastest" with a TypeError; on a build without it, the whole member is unknown and the bogus value sails through silently — run it and see which browser you have.
