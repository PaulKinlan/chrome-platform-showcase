Ask, then read back what you got

The spec makes the negotiation synchronous: the constructor resolves your congestionControl preference against the algorithms the user agent actually has, downgrades to "default" if nothing optimizes for your request, and stores the answer in an internal slot — all before any packet is sent. So the attribute is readable the instant new WebTransport() returns, even on a session that will never connect. This page constructs one session per enum value against a dead endpoint and tabulates the readbacks.

Chrome ships the option and attribute in Chrome 158 (runtime flag WebTransportCongestionControl; on earlier builds launch with --enable-blink-features=WebTransportCongestionControl or flip chrome://flags/#enable-experimental-web-platform-features). No HTTP/3 endpoint is reachable from this page, which is fine — the readback happens at construction, and each attempted session is closed immediately after.

for (const pref of ["default", "throughput", "low-latency"]) {
  const t = new WebTransport("https://127.0.0.1:44443/never", {
    congestionControl: pref,
  });
  t.ready.catch(() => {});          // dead endpoint — expected to fail
  console.log(pref, "→", t.congestionControl);  // readable immediately
  t.close();
}
