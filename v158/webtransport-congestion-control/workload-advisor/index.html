What the hint does not do

  • It names no algorithm. RFC 9002 §7 lets endpoints pick any controller; the enum expresses an optimisation goal, not "use BBR". (Chromium's implementation notes map the preference onto BBR-family controllers, but that is an implementation detail, not a contract.)
  • It is per-session, sender-side. It shapes how this endpoint sends. The server's sending behaviour is the server's business — ask your server operator for the matching knob.
  • It is resolved once, in the constructor. There is no setter; you cannot flip a live session from throughput to low-latency. Reconnect to renegotiate.
  • Pooling shares the controller. With allowPooling: true your session may share a connection — and its congestion state — with other sessions on the same origin.
  • Check the attribute, not your assumption. A request the user agent cannot optimise for resolves to "default" silently — the attribute is the only honest readout.
