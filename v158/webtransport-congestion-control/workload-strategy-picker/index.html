Pick the profile for the workload

The enum is small because the decision is: when the network gets tight, would you rather wait or shrink? Choose a workload below — the page explains which profile fits and why, shows the exact constructor line, and then actually constructs a session with that preference so you can see what this browser reports honoring.

The mapping is engineering judgment grounded in RFC 9002 §7 (a sender may use any compliant controller) and the explainer's use cases — it is advice, not spec. What is spec: the preference is only a hint, and transport.congestionControl is the readback that tells you whether it stuck (Chrome 158+; earlier builds need the flag on the feature overview).

the cheat sheet

"low-latency"  → queue depth beats goodput
  cloud-gaming input · voice · interactive video · multiplayer state
  (one stale update is worthless; backing off early keeps the queue short)

"throughput"   → goodput beats queue depth
  file sync · bulk upload/download · log shipping · prefetching
  (nobody is waiting on any single packet; fill the pipe)

"default"      → mixed or unknown traffic
  the platform default is tuned for exactly this case — and it is what
  you silently get anyway when the UA can't optimize for your request
