One base rule for every highlight

Three named highlights, each with its own background, and one ::highlight(*) rule that gives all of them the same underline and text colour. Add a fourth category at runtime and it picks up the base rule with no new CSS. Turn the base rule off and every category loses it at once.

How it works

  1. Each category is a Highlight of Ranges registered by name in CSS.highlights. No <span> is added to the text.
  2. Each name gets its own ::highlight(name) rule for what differs (the background).
  3. One ::highlight(*) rule carries what is shared (underline, text colour). The * adds no specificity, so a named rule overrides any property it also sets, whatever the source order: the name rule's solid underline beats the base rule's dotted one.

Common errors and fixes

  • The whole rule is dropped in older Chrome: an unknown selector invalidates the rule. Put ::highlight(*) in its own rule, never in a selector list with named highlights, or the named ones disappear too.
  • ::highlight(*):hover or ::highlight(*)::after throws: highlight pseudo-elements take no pseudo-classes or further pseudo-elements.
  • Nothing changes with font-size or padding: only color, background-color, text-decoration and its longhands, text-shadow and the stroke/fill colours apply to highlights.
  • ::selection is not affected: * matches custom highlights only, not ::selection, ::spelling-error or ::target-text.
