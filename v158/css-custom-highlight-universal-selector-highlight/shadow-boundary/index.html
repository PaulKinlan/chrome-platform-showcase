Across a shadow boundary

A page-wide glossary script finds terms in the article and inside the open shadow roots of two <quote-card> components, and registers them all as one glossary highlight. Document CSS cannot normally reach into a shadow tree. So: does a document-level ::highlight(*) rule paint the terms inside the cards, does a rule inside the card's own shadow root win, and does getComputedStyle report what is painted?

How it works

  1. CSS.highlights is one registry per document. A Range can sit entirely inside an open shadow tree, so one Highlight can cover light-DOM text and text in several components.
  2. The glossary script walks the article with a TreeWalker and then walks each element.shadowRoot it meets, building a range for every term.
  3. The rule toggles add or remove constructed stylesheets: two on document.adoptedStyleSheets, one on each card's shadowRoot.adoptedStyleSheets.
  4. The table reads the computed style of the highlight pseudo-element on the light paragraph and on a paragraph inside each card. Compare it with what you see.

Findings

Chrome for Testing 158.0.8127.36, headless, no flags, 2026-11-27. Paint was measured by counting pixel colours in screenshots of the shadow-tree text; computed values come from the table above.

  • Document ::highlight(*) paints inside the shadow trees. The terms in both cards took the document rule's background and colour.
  • But getComputedStyle disagrees for that case. For shadow-tree text it reported the initial values (rgba(0, 0, 0, 0) background) while the screenshot showed the universal rule's colour. In the light DOM the universal rule's computed value matched the paint.
  • A document named rule does not have that gap: ::highlight(glossary) from the document painted inside the cards and getComputedStyle reported it.
  • The card's own ::highlight(*) beats the document's universal rule inside the card, and its computed value matches the paint.
  • A document named rule beats the card's universal rule in paint, but not in getComputedStyle. With ::highlight(glossary) on the document and ::highlight(*) in the card, the card's terms painted blue (the document rule, pixel colour 197,204,250) while getComputedStyle reported the card's rose rule. Turn on the second and third toggles to see it.
  • Practical upshot: test highlight styling inside components with screenshots, not only getComputedStyle, until the universal case reports correctly. No Chromium issue found for this yet; recorded on the friction ledger.
