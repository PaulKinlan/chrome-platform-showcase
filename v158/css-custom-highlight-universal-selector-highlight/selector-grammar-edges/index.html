How it works

The spec grammar is ::highlight( <custom-highlight-name> | * ): one identifier or one bare *, with optional whitespace. A selector list inside the parentheses, a * with a suffix, or any pseudo-class after the pseudo-element is a syntax error. An escaped \* is an ordinary identifier whose value is the string "*", so it is a named highlight selector with normal specificity, not the universal one.

The * reaches custom highlights only. ::selection, ::spelling-error, ::grammar-error and ::target-text are separate highlight pseudo-elements and keep their own rules.

Findings

Chrome for Testing 158.0.8127.36, no flags, 2026-11-27:

  • Accepted: ::highlight(*), ::highlight( * ) (serialised without the spaces), p::highlight(*), :root ::highlight(*), *::highlight(*) (serialised as ::highlight(*)) and the escaped ::highlight(\*). Rejected with SyntaxError: ::highlight(*a), ::highlight(a, *), ::highlight(* *), ::highlight(), ::highlight(*):hover, ::highlight(*)::after. CSS.supports agreed with insertRule every time.
  • * does not reach ::selection, ::spelling-error or ::target-text. getComputedStyle(el, "::highlight(never-registered)") still reports the universal rule's values, because computed style does not check the registry.
  • Escaped name: in a screenshot the "*" line painted with the escaped rule's background and the "plain" line with the universal one, so \* is a named selector that wins over *. But getComputedStyle(el, "::highlight(*)") cannot ask about the highlight named "*": the argument is parsed as the universal selector and reports the universal rule, and "::highlight(\\*)" is the spelling that returns the escaped rule's value.
