Reliability, read across a session's lifetime

The spec pins the lifecycle down precisely: reliability is "pending" from the moment the object is constructed, and only becomes "supports-unreliable" or "reliable-only" when a connection actually establishes. A session that never establishes stays "pending" forever. This page reads the real attribute at each lifecycle moment and timestamps what came back.

Chrome targets these attributes for Chrome 158 behind the WebTransportReliability runtime flag. On an earlier or unflagged build, launch with --enable-blink-features=WebTransportReliability, or flip chrome://flags/#enable-experimental-web-platform-features and relaunch. No HTTP/3 endpoint is reachable from this showcase, so the session attempt below fails at connect — which is exactly what makes the "stays pending" rule observable.

The static half: WebTransport.supportsReliableOnly

This is a static attribute — it lives on the constructor itself and answers for the whole user agent, before any session exists: can this browser run WebTransport over an exclusively reliable (HTTP/2) connection?
