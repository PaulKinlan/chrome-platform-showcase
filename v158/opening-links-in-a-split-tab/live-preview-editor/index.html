Live preview editor

An editor and its live preview, laid out as two real tabs side by side rather than an iframe. The explainer argues the preview then gets a full top-level navigable: its own viewport, top-level-only APIs, and no ancestor styling or embedding restrictions. The editor opens the preview with "popup=0,split,splitposition=right,splitsize=50" and keeps the returned handle. It streams every edit over postMessage, checking both event.source and event.origin, receives the preview's viewport reports, and collapses the split with preview.close().

why a split and not an iframe or a popup

An iframe shares the editor's viewport and inherits embedding restrictions (frame-ancestors, sandboxing, no top-level-only APIs). A popup is a detached window the user must arrange by hand. A split tab sits in the same window as the editor, with the browser's own resize handle, tab-strip grouping and lifetime, and it is still a script-closable, opener-linked view. If the browser declines the split, the same code still works with an ordinary tab, because the popup=0 guard keeps older browsers from opening a popup.
