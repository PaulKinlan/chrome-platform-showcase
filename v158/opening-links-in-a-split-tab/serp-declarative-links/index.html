Search results with windowfeatures links

The headline use case in the explainer: on a search results page, open a result beside the results instead of navigating away. The proposal's declarative form keeps these as real links (middle-click and the context menu still work) with a new windowfeatures attribute on <a>, <area> and <form>. In a browser that does not know the attribute, the link is an ordinary target="_blank" link. The popup=0 trick is not needed here.

    markup

    <a href="https://example.com/result"
   target="_blank"
   windowfeatures="split,splitposition=right,splitsize=40">Result title</a>

<!-- the IDL attribute reflects the content attribute -->
link.windowFeatures  // "split,splitposition=right,splitsize=40" in supporting browsers
                     // undefined elsewhere (the attribute is simply ignored)

    Allowed in the attribute: split, splitposition, splitsize, popup, width/height, left/top. Not allowed: noopener/noreferrer (use rel) and the legacy bar features. If target is missing, a split or popup request implies _blank, ahead of any <base target>.
