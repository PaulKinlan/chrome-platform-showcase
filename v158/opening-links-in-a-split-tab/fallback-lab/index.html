Fallback and edge-case lab

The proposal's value lies in its fallbacks: a split is only ever requested. Each card runs one real window.open() that exercises a rule from the explainer's Behavior section. It records the return value and what the opened view reports, next to what the explainer says a supporting browser would do. The legacy rows double as a migration guide for shipping split today.

    rules exercised

    • Legacy popup trap: in older browsers an unknown split still makes the feature string non-empty, which means "popup". popup=0,split avoids it.
    • split + popup: split wins. If the split is not created, the fallback is a popup, because that was the author's other request.
    • noopener: unchanged. open() returns null and the view has no opener.
    • Named targets: an existing named navigable is navigated and the window features are ignored. Use _blank.
    • Invalid hints: an unknown splitposition or an out-of-range splitsize is ignored and the browser default is used.
    • Activation: split requests go through the same popup blocker as any window.open().
    • Not testable from a page: "the window is already split → new tab", and "the browser declines on narrow windows or mobile". Those are user-agent decisions, so check them by hand in a flagged desktop Chrome.
