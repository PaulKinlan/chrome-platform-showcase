BarProp fallback matrix

Script can never learn whether a split happened — but the opened document’s window.locationbar.visible (and the other BarProps) still reveal one bit: popup (false) or tab-or-split (true). That bit is exactly what the web-platform-tests use, and it exposes the migration trap: in an engine that does not know split, the string "split" is a non-empty unknown feature string, so HTML’s popup heuristic fires and you get a popup window.

the migration rule this proves

// Unsafe during rollout: legacy engines open a POPUP window.
window.open(url, "_blank", "split");

// Safe: popup=0 short-circuits the popup heuristic everywhere,
// so legacy engines open a normal tab and split-aware ones split.
window.open(url, "_blank", "popup=0,split");

// Deliberate: split if possible, otherwise a popup.
window.open(url, "_blank", "split,popup");

The declarative attribute needs no guard: an engine that does not know windowfeatures ignores the whole attribute and the link opens as an ordinary tab (see Declarative windowfeatures).
