Every result below is a plain anchor carrying windowfeatures="split,splitposition=right,splitsize=50", so Enter, middle-click, Ctrl/Cmd-click and “Open link in new tab” all still work — and the user’s modifier keys still win over the split request.

where results open

    Open a result. The opened article reports back through window.opener, and the list marks the one you are reading.

    the markup each result uses

    Why rel="opener": a targeted anchor implies noopener, and this pattern wants the article to tell the list what is being read. Leave it off if you do not need the channel — the split request works either way.

    Why a named reader: once this tab is in a split, a second _blank split request falls back to an ordinary tab (the explainer will not evict whatever is on the other side). Targeting the name of the pane you opened navigates that pane instead — and an existing named target always ignores windowfeatures.
