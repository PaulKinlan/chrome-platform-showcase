Implement CSS random-item() function

random-item(--key, a, b, c) picks one of its arguments at random and substitutes it into the property, like var(). Each item can be any run of CSS tokens, so it can pick colours, font stacks in braces, grid-column spans or whole shorthand values. The required first argument is a <random-key> that decides which elements and properties share a pick. Chrome's implementation is still in review, so this page shows the spec contract, the live state of your browser, and a random() + if() fallback that Chrome 158 runs today.

Not in any Chrome build yet (checked 2026-11-28). The implementation, CL 8816057, is still in review. It adds the runtime flag CSSRandomItemFunction with status experimental, so once it lands in Canary you can turn it on with chrome://flags/#enable-experimental-web-platform-features or by launching with --enable-blink-features=CSSRandomItemFunction. ChromeStatus lists Safari Technology Preview 251 as shipping it and Firefox as prototyping it behind layout.css.random-item.enabled. Probing this browser…

why it shipped

Authors asked for randomness in CSS for years (CSSWG issue #2826) for things like scattered decorations, varied card styling and generative patterns, often in places where script is not allowed, such as SVG images or sandboxed embeds. The Working Group added the random() family to CSS Values 5. random() picks a number in a range and has shipped in Chrome; random-item() picks from a list, which covers values that are not numbers, such as colours, keywords and font stacks.

Progressive enhancement: keep the fallback declaration first and put the random-item() rule inside @supports (color: random-item(--x, red, blue)). Do not rely on the cascade alone if any item contains var(); see the parse lab.
