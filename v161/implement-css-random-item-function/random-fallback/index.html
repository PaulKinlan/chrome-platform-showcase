random() + if() fallback generator

Enter a list of items and a key. The page writes CSS that picks one item per element with random() and if(), which Chrome 158 runs today, plus the native random-item() rule behind @supports, then applies it to a grid of tiles and counts the picks.

Not in any Chrome build yet (checked 2026-11-28). The implementation, CL 8816057, is still in review. It adds the runtime flag CSSRandomItemFunction with status experimental, so once it lands in Canary you can turn it on with chrome://flags/#enable-experimental-web-platform-features or by launching with --enable-blink-features=CSSRandomItemFunction. ChromeStatus lists Safari Technology Preview 251 as shipping it and Firefox as prototyping it behind layout.css.random-item.enabled. Chrome 158 already ships random(), which this page uses for the labelled fallback. Probing this browser…

    How it works
    
    
      
      
    1. The question: can random() plus if(), both in Chrome 158, stand in for random-item() today, and pick the same item once both exist?
      2. 
      
    2. CSS Values 5 §9.3 picks item i of N as round(down, R × N, 1). For random(key, 0, N - 1, 1) the step index is the same expression, so with the same key (same R) the two functions agree on the index.
      3. 
      
    3. The generator registers --ri-idx as <integer> so the result of random() is a number that style(--ri-idx: 1) can match, then writes one if() branch per item. Braced items lose their braces inside if(), where commas are already allowed.
      4. 
      
    4. The native declaration goes inside @supports (color: random-item(--x, red, blue)), so it never replaces the working fallback in a browser that would only accept it because of a var().
      5. 
      
    5. Where random-item() exists, the page also reads the native pick for each tile and counts how many agree with the fallback.

    Findings
    
    
    Tested 2026-11-28 in Chrome for Testing 158.0.8127.36 (Linux, headless). The generated fallback works in all four property modes: every tile resolves to one of the items, and over 240 tiles with three items each item was picked roughly a third of the time. random(fixed R, 0, N - 1, 1) matched round(down, R × N, 1) for every row in the live checks, including R = 1, which the spec clamps to just under 1. random() in Chrome 158 rejects the by <step> spelling, and its fixed-key results go to the last step for R = 1. Whether native random-item() agrees index-for-index with this fallback in Chrome: not verified, no Chrome build has it yet.
