Who shares a pick?

random-item() requires a <random-key>, and that key decides whether two elements, or two properties on one element, get the same item. This page measures all six kinds of key and checks each against the spec.

Not in any Chrome build yet (checked 2026-11-28). The implementation, CL 8816057, is still in review. It adds the runtime flag CSSRandomItemFunction with status experimental, so once it lands in Canary you can turn it on with chrome://flags/#enable-experimental-web-platform-features or by launching with --enable-blink-features=CSSRandomItemFunction. ChromeStatus lists Safari Technology Preview 251 as shipping it and Firefox as prototyping it behind layout.css.random-item.enabled. Chrome 158 already ships random(), which this page uses for the labelled fallback. Probing this browser…

Live demo: which keys make picks match?

Each row styles four boxes with the same <random-key> for both width and height, over the same range. A square means the two properties drew the same random value; four identical boxes mean the elements shared it. The boxes use random(), because random-item() interprets its key identically (CSS Values 5 §9.2) and Chrome 158 has only random(). Where random-item() exists, each verdict also reports it, measured on hidden elements with a 100-item list.

How it works

  • --name alone: one random value per name, shared by every element and every property that uses it.
  • element-scoped adds the element, so each element draws its own value; properties on one element still share.
  • property-scoped adds the property name, so width and height differ; elements still share.
  • auto (or no key, for random()) is element-scoped property-index-scoped: everything differs.
  • fixed <number> skips the cache and uses the number as the base value, so everything is identical.

For random-item() this decides, for example, whether a card's background and its badge pick the same index (give both the same --name element-scoped) or pick independently (use different names, or auto).

Findings

Tested 2026-11-28 in Chrome for Testing 158.0.8127.36 (Linux, headless) with random(): all six rows matched the sharing the spec describes. --a property-scoped gave four identical rectangles, --a element-scoped four different squares, and auto four different rectangles. The random-item() columns: not verified, no Chrome build has the function yet.
