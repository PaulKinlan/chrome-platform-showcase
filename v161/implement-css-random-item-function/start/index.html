Pick one of three

The smallest useful example: random-item(--key, a, b, c) picks one of its items for each element. Here it gives six notes a random stripe colour, typeface and tilt, next to the same effect built from random() and if(), which Chrome 158 already runs.

Not in any Chrome build yet (checked 2026-11-28). The implementation, CL 8816057, is still in review. It adds the runtime flag CSSRandomItemFunction with status experimental, so once it lands in Canary you can turn it on with chrome://flags/#enable-experimental-web-platform-features or by launching with --enable-blink-features=CSSRandomItemFunction. ChromeStatus lists Safari Technology Preview 251 as shipping it and Firefox as prototyping it behind layout.css.random-item.enabled. Chrome 158 already ships random(), which this page uses for the labelled fallback. Probing this browser…

Each note sets border-inline-start-color, font-family and rotate with random-item(). element-scoped in the key gives every note its own pick; Reshuffle swaps in a new key name, which draws new random values.

      How it works

      .note {
  border-inline-start-color: random-item(--tint element-scoped, blue, green, crimson);
  font-family: random-item(--tint element-scoped, {Georgia, serif}, {system-ui, sans-serif}, {ui-monospace, monospace});
  rotate: random-item(--tilt element-scoped, -2deg, 0deg, 2deg);
}
      1. The first argument is the <random-key>, and it is required: without it the parser could not tell a key from the first item. auto, a --dashed-ident, element-scoped, property-scoped and fixed <number> all work.
      2. Every other argument is one item: any run of tokens. Wrap an item that contains commas in braces, as in {Georgia, serif}.
      3. random-item() is an arbitrary substitution function like var(). The declaration is accepted at parse time and the chosen item is substituted at computed-value time, so children inherit the item, not the function.
      4. The colour and the font share the key --tint element-scoped, so they draw the same random number and pick the same index: a blue stripe always comes with Georgia. The tilt uses a different key and varies on its own.
      5. Picking index i of N items is round(down, R × N, 1). random(--tint element-scoped, 0, N - 1, 1) computes the same index from the same R, which is why the fallback lane is a faithful stand-in where random() and if() are supported.

      Common errors and fixes

      • Forgetting the key: random-item(red, blue) is valid, but red is taken as the key, which is not a valid <random-key>, so at computed-value time the property becomes invalid and falls back to its inherited or initial value.
      • An item with a comma and no braces becomes two items.
      • An empty item (random-item(auto, red, , blue)) is valid; if it is picked, the property is invalid at computed-value time.
      • A var() inside any item defeats the cascade fallback. A browser without random-item() rejects color: random-item(--k, red, blue) at parse time, so an earlier color declaration still applies. But color: random-item(--k, var(--a), var(--b)) contains var(), so the same browser accepts it at parse time and only finds it invalid at computed-value time, by which point the earlier declaration has lost. The property becomes unset: this page's native lane shows black stripes in Chrome 158 for exactly this reason. Guard such rules with @supports (color: random-item(--x, red, blue)).
      • Detect it with @supports (color: random-item(--x, red, blue)), using literal items so the test does not pass just because of var().

      Findings

      Tested 2026-11-28 in Chrome for Testing 158.0.8127.36 (Linux, headless), with no flag and with --enable-experimental-web-platform-features: the parser rejects every random-item() declaration with literal items and CSS.supports() returns false. The native lane's declarations contain var(), so Chrome 158 accepts them at parse time and then treats them as invalid at computed-value time: the stripes render in currentColor (black) instead of the grey the rule above them set. The fallback lane works: random(--tint element-scoped, 0, 2, 1) gives each note 0, 1 or 2, and if(style(--pick: 1): …) selects from it. Chrome 158 does not accept the newer by <step> spelling of the step argument; the plain fourth argument works. Native random-item() in Chrome: not verified, because no Chrome build contains it yet.
