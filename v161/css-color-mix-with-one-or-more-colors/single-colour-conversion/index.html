One colour: convert and fade

color-mix() now accepts a single colour. With no percentage it converts the colour to the mixing space; with a percentage under 100% it fades it. This page compares both with the idioms you used before.

Ships in Chrome 161. Before that, enable chrome://flags/#enable-experimental-web-platform-features (there is no dedicated flags entry), or launch Chrome/Canary with --enable-blink-features=CSSColorMixVariadic or --enable-experimental-web-platform-features. How it works

CSSWG issue #12234 settled what color-mix() with one colour means: convert it to the interpolation space, then apply any shortfall from 100% as transparency. Two practical uses:

  • Convert a token to a known space without knowing how it was authored: color-mix(in oklch, var(--brand)). The page compares it with relative colour syntax (oklch(from var(--brand) l c h)), which does the same conversion but only for spaces with a colour function.
  • Fade a token: color-mix(in srgb, var(--brand) 40%). Before Chrome 161 the usual idiom was color-mix(in srgb, var(--brand) 40%, transparent). The page computes both so you can check they agree.

The question: is the one-colour form exactly equivalent to the older idioms, in every space Chrome supports?

Findings

Tested 2026-11-26 on Chrome for Testing 160.0.8184.0 with --enable-experimental-web-platform-features: color-mix(in oklch, teal) computes to oklch(0.543115 0.092684 194.767), the same as oklch(from teal l c h). color-mix(in hsl, teal) serialises as color(srgb 0 0.501961 0.501961), not hsl(...), because HSL is a legacy sRGB form and serialises as sRGB. color-mix(in srgb, teal 50%) gives alpha 0.5. At 0% the one-colour form keeps the channels with alpha 0 (color-mix(in oklch, #0a8f5c 0%) gives oklch(0.5741 0.129422 159.149 / 0)), while the older , transparent idiom gives oklch(0 0 159.149 / 0): lightness and chroma collapse to zero. So the two idioms are not interchangeable at 0%; the page’s verdict line reports “different” there. The one-colour form is rejected in Chrome 158 with or without the flag. Not verified in Chrome 161.
