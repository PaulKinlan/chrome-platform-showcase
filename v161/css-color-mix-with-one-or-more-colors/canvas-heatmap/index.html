Canvas heatmap in a Worker

Style sheets are not the only place CSS colours are parsed. This page paints a heatmap of its own text with variadic color-mix() strings as Canvas 2D fillStyle values, on the main thread and inside a Worker’s OffscreenCanvas.

Ships in Chrome 161. Before that, enable chrome://flags/#enable-experimental-web-platform-features (there is no dedicated flags entry), or launch Chrome/Canary with --enable-blink-features=CSSColorMixVariadic or --enable-experimental-web-platform-features. Firefox 150 and Safari 27 already ship it. Probing this browser…

Live demo: letter-frequency heatmap of this page

The page counts the letters a–z in its own text and paints one cell per letter. Each cell’s colour is a single variadic mix of the site’s three accent colours, weighted by that letter’s frequency, passed straight to CanvasRenderingContext2D.fillStyle. The left canvas is painted on the main thread; the right one by a Worker through OffscreenCanvas.

How it works

  1. The three stops are read from --accent-blue, --accent-emerald and --accent-rose with getComputedStyle(), so the scale follows the site theme.
  2. A frequency t from 0 to 1 becomes three weights (a hat function per stop), and the cell colour is color-mix(in oklab, blue w1%, emerald w2%, rose w3%).
  3. Canvas parses fillStyle with the CSS colour parser. An unparseable string is ignored and fillStyle keeps its previous value, so the page sets a sentinel first and checks whether the assignment took.
  4. The Worker gets the canvas with transferControlToOffscreen() and parses the same strings without a DOM, which tests whether the runtime flag reaches worker parsing.

The question: does every CSS-colour consumer in Chrome accept the variadic grammar, including Canvas 2D in a Worker, or only style sheets?

Findings

Tested 2026-11-26 on Chrome for Testing 160.0.8184.0 with --enable-experimental-web-platform-features: Canvas 2D accepts the variadic grammar on the main thread and in a Worker’s OffscreenCanvas, and fillStyle reads back as the computed colour (color(srgb 0.333333 0.333333 0.333333) for red, lime and blue), not the authored string. So the runtime flag reaches worker-side colour parsing too. In Chrome 158 every variadic assignment is silently ignored: no exception, and fillStyle keeps the sentinel, which is why a canvas fallback has to compare the value after assigning. Timing from the stress button depends on the machine; we did not record a number, because headless timings in this environment are not representative.
