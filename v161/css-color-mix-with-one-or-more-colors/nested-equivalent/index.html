Nested-form calculator

Before Chrome 161, mixing three colours meant nesting color-mix() calls and working out each weight by hand. This tool converts any variadic mix into its exact nested equivalent and checks that Chrome agrees.

Ships in Chrome 161. Before that, enable chrome://flags/#enable-experimental-web-platform-features (there is no dedicated flags entry), or launch Chrome/Canary with --enable-blink-features=CSSColorMixVariadic or --enable-experimental-web-platform-features. How it works

  1. Normalise (CSS Values 5 “normalize mix percentages”, forced): omitted percentages get (100% − specified sum) / omitted count; the list is scaled to 100%; anything the total fell short of 100% becomes leftover.
  2. Fold left (CSS Color 5 §3.3): mix item 1 with item 2 at progress p2 / (p1 + p2), carry the result forward with weight p1 + p2, mix with item 3, and so on.
  3. Alpha: multiply the result’s alpha by 1 − leftover. In the nested form that becomes the outermost pair’s percentages, which add up to less than 100%.

The question this page tests: is Chrome’s variadic result identical to the nested form built from that algorithm, for every space and any percentages?

Findings

Tested 2026-11-26 on Chrome for Testing 160.0.8184.0 with --enable-experimental-web-platform-features: for every case in the live checks, including the polar oklch case where order matters, the variadic value and the nested value built from the spec algorithm compute to the same colour to within 0.002 per channel. That is the strongest evidence that Chrome implements the left-to-right fold the spec describes rather than a weighted average. A three-colour mix with every percentage at 30% computes to color(srgb 0.333333 0.333333 0.333333 / 0.9): the 10% shortfall turns into alpha, exactly as with two colours. In Chrome 158 the nested column still computes and the variadic column is rejected, so the page doubles as a fallback generator.
