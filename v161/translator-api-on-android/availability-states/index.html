Availability states on this device

Translator.availability() is the one call a mobile page can always make cheaply. It never downloads anything and needs no gesture. It's how a page decides whether to show a translate button, offer a download, or hide the feature. Pick a pair and read the raw value your browser returns.

reading the four values on a phone

  • available: the language pack is on the device. create() works without a gesture, and translation works offline.
  • downloadable: Chrome can fetch the pack, but create() needs a tap (transient user activation) and will use data and storage. On Android, say so before the tap. Chrome also reports downloadable for packs that are installed but that this site hasn't used yet. This is the privacy masking described in the spec (§6.2), so a site can't learn which minority languages you've installed.
  • downloading: a download is already running, maybe started by another tab. It still needs a gesture to attach.
  • unavailable: the pair isn't supported, the identity pair (en→en) was requested, an iframe isn't allowed the translator feature, or the TranslatorAPIAllowed policy is off. A page can't tell these apart from availability() alone.
