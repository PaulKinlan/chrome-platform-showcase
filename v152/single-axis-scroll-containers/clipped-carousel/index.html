Clipped Carousel vs Hidden Carousel

Straight from the explainer's second example: a horizontal carousel whose cards are taller than the strip, so the vertical axis is visually cut off. With the legacy overflow: scroll hidden, the hidden axis is still a scrollable axis — scrollIntoView() or any script can shift it, and because users cannot scroll a hidden axis, the top of every card stays chopped off with no way to recover. With overflow: scroll clip the vertical axis can never leave 0. Same markup, same buttons, different physics.

Legacy: the workaround that leaks

.strip { overflow: scroll hidden; height: 150px } — hidden is a scrollable value

scrollLeft 0 · scrollTop 0

Single-axis: the clip axis is pinned

.strip { overflow: scroll clip; height: 150px } — new in Chrome 152

scrollLeft 0 · scrollTop 0

what to look for

Press scrollIntoView(card 8) on each strip. Card 8 sits lower inside the strip (extra top margin), so block: "nearest" asks the browser to bring its bottom edge into view. In the legacy strip the vertical readout jumps above 0 and the blue top labels vanish — and since hidden blocks user scrolling, wheel or touch can't bring them back (only Reset can). In the single-axis strip, when this browser supports it, scrollTop stays exactly 0: the inline axis still centres the card, but the clipped axis refuses to move. The scrollTop += 40 button shows the same contract without scrollIntoView() in the loop.
