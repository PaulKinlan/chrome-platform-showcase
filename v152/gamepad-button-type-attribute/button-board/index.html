Button Board

A live board for every connected controller: each button's index, its Standard Gamepad role (the spec's §14 table for indices 0–16), a pressed/touched/value meter polled with requestAnimationFrame, and a badge showing the browser's actual type string for that button — or an honest "not exposed" state when the accessor is missing.

Flag required: the type column only fills in on a Chrome build containing CL 7760763 with --enable-blink-features=GamepadButtonTypes (or chrome://flags/#enable-experimental-web-platform-features). Everything else on the board works on any browser with the Gamepad API.

GamepadButton.type exposed: checking… connected pads: 0 poll: idle
No gamepad detected yet. Plug in (or pair) a controller and press any button on it — the browser deliberately keeps pads invisible until a button press, as a fingerprinting mitigation. The board appears the moment gamepadconnected fires. Works with Xbox, PlayStation, Switch Pro, and generic HID pads on desktop and on Android over USB-C/Bluetooth.

Rows highlight while their button is pressed. The value meter shows the analog range [0..1] — pull the triggers slowly to see it sweep. The type badge prints the raw returned string; an unrecognised future value renders in its own "unexpected" badge rather than being bucketed into a known one.

the code

function poll() {
  for (const pad of navigator.getGamepads()) {
    if (!pad) continue;
    pad.buttons.forEach((button, i) => {
      render(i, {
        role: STANDARD_ROLES[i] ?? "—",       // spec §14 table, indices 0–16
        pressed: button.pressed,
        touched: button.touched,
        value: button.value,
        // Chrome 152 + GamepadButtonTypes flag:
        type: "type" in button ? button.type : undefined,
      });
    });
  }
  requestAnimationFrame(poll); // sample at animation rate, per spec best practice
}
