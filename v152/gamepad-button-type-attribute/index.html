Gamepad button type attribute

The Gamepad API's Standard Gamepad mapping defines 17 well-known button indices — but real controllers ship extra inputs, most famously the DualShock/DualSense touchpad. The new readonly GamepadButton.type attribute classifies every button as "standard", "non-standard", or "trackpad", so apps can show "Press the touchpad" without maintaining per-controller index tables. Behind the GamepadButtonTypes flag in Chrome 152.

concepts

  1. Exact-surface probe

    Feature-detect the precise shipped surface — 'type' in GamepadButton.prototype — separately from baseline Gamepad support, with the exact chrome://flags / --enable-blink-features=GamepadButtonTypes steps when the attribute is absent. The probe can genuinely fail; nothing is inferred from browser version.

  2. Live button console

    Plug in a real controller and watch every button render live — index, standard-mapping name, pressed/touched/value — plus the real type value per button when the flag is on, or an honest per-button "attribute missing" readout when it isn't. Includes the type-driven prompt pattern from the explainer.

  3. Standard-mapping atlas

    An interactive reference for the 17 standard button indices: pick any button to see its index, mapping position, and what type reports for it — and why the touchpad (a common index-17 extra) gets its own "trackpad" classification instead of drowning in "non-standard".

why it shipped

Cloud-gaming services, browser games, and accessibility tools all need to answer "what is this button, really?" Today that means vendor-specific index tables: the DualSense touchpad happens to be index 17 on Chrome, but nothing in the API says so. The type attribute gives that answer a standardized vocabulary agreed across engines (Chromium and WebKit are both implementing), reduces mapping-table maintenance, and deliberately avoids exposing model or manufacturer identifiers — classification only, no new fingerprinting surface beyond what button counts already reveal.

enabling it

In developer trial in Chrome 152. The runtime feature name is GamepadButtonTypes (status experimental in runtime_enabled_features.json5): launch with --enable-blink-features=GamepadButtonTypes, or enable chrome://flags/#enable-experimental-web-platform-features and restart. A controller must be connected and a button pressed before navigator.getGamepads() exposes it — that user-activation rule is unchanged.
