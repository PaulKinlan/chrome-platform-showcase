Gamepad button type attribute

The Gamepad API defines standard indices for 17 common gamepad buttons, but says nothing about the extras — touchpad clicks, paddles, mute buttons. This proposal adds a read-only type attribute to GamepadButton with a three-value enum — "standard", "non-standard", and "trackpad" — so a page can identify a controller touchpad (or any non-standard button) interoperably instead of hard-coding per-controller button indices. Behind the GamepadButtonTypes runtime flag; the Chromium implementation is still in review, so every demo below detects honestly and explains exactly how to enable it.

concepts

  1. Live Button Inspector

    Connect a real controller: gamepadconnected + rAF polling shows every button's value, pressed, touched — and its type when the flag is on.

  2. Type Support Probe

    Probe the exact surface — 'type' in GamepadButton.prototype — plus a keyboard-driven, clearly-labelled illustration of the enum vocabulary.

  3. Semantic Prompts & Remapping

    A game binding screen that turns button.type into human prompts like “Press the touchpad” — real API when a pad is present, labelled simulation otherwise.

why it shipped

Cloud gaming services, browser games, and accessibility software all need to know what a button is, not just its index. The DualShock 4 and DualSense touchpad click is the canonical case: today it lands at a controller-specific index past the standard 17, and every app carries its own mapping table. A standardized GamepadButtonType enum lets applications say button.type === "trackpad" once and have it work across controllers and engines — Chromium and WebKit are both implementing. It is fully backward compatible: existing content never reads type, and the enum deliberately stays small (additions need Working Group consensus).
