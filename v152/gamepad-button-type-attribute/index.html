Gamepad button type attribute

The Gamepad API defines standard indices for 17 common buttons — and nothing for everything else. The new readonly GamepadButton.type attribute classifies every button as "standard", "non-standard", or "trackpad", giving cloud-gaming prompts, browser games, and accessibility software an interoperable way to recognise inputs like the DualSense touchpad without vendor-specific index tables.

Chrome 152 development status: Chromium gates this behind the experimental runtime flag GamepadButtonTypes (implementation in review: crrev.com/c/7760763). To exercise it for real you need a Chrome build that already contains the implementation (Canary/Dev in the 152 timeframe), launched with --enable-blink-features=GamepadButtonTypes — or enable chrome://flags/#enable-experimental-web-platform-features. On builds without the implementation, the flag alone does nothing; every demo below probes the real surface and says exactly what it found.

concepts

  1. Type Probe

    The canonical feature check: does GamepadButton.prototype expose the readonly type accessor? Runs the exact IDL probe, prints the property descriptor, lists the GamepadButtonType enum from the spec, and — when a real pad connects — reads each button's raw type value live.

  2. Button Board

    A live inspection board for every connected gamepad: per-button pressed/touched/value meters polled with requestAnimationFrame, the Standard Gamepad role for indices 0–16, and a type badge showing the browser's actual returned string — or an honest "not exposed" state.

  3. Adaptive Prompts

    The cloud-gaming use case: choose between "Press the touchpad" and a fallback prompt by looking for a button with type === "trackpad", with the legacy vendor-ID + index-17 heuristic shown as the labelled fallback path. Composes with vibrationActuator haptics on hardware, and announces prompt decisions via a live region.

  4. Mapping Migration

    Edge cases and migration: run the old id-sniffing index-table classifier and the new type-based classifier side by side over the same button list, diff their verdicts, and see the forward-compatible pattern — feature-detect the attribute, never bucket unknown enum values, degrade to the table only when type is absent.

why it shipped

The Standard Gamepad mapping standardises 17 button indices — but modern controllers keep growing inputs the mapping never named: the DualShock/DualSense touchpad, share and capture buttons, voice-assistant keys, paddles. Today a web app that wants to show "Press the touchpad" has to sniff gamepad.id for vendor strings and hard-code per-controller index tables, which breaks with every new device. The type attribute moves that classification into the platform: "standard" for buttons the Standard Gamepad mapping defines, "trackpad" for touchpad inputs with known cross-device semantics, "non-standard" for everything else — fully backward compatible, with WebKit implementing the same proposal in parallel.
