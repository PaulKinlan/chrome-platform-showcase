Type Probe

The smallest real use of the shipped surface: check whether this browser exposes the readonly type accessor on GamepadButton.prototype, inspect its property descriptor, and — the moment a real controller connects and you press any button on it — read each button's actual type string back from the browser.

Flag required: needs a Chrome build containing CL 7760763 (Canary/Dev in the Chrome 152 timeframe) launched with --enable-blink-features=GamepadButtonTypes, or chrome://flags/#enable-experimental-web-platform-features set to Enabled. On builds without the implementation the flag has no effect — the probe below reports whatever is really there.

the enum, straight from the spec

GamepadButtonType values (w3c/gamepad PR #196, §14.1.1)
ValueMeaning
"standard"The button has a type defined in the Standard Gamepad mapping (indices 0–16).
"non-standard"The button exists on the controller but has no standard name — share/capture keys, paddles, assistant buttons.
"trackpad"A trackpad input, like the DualShock 4 / DualSense touchpad press.

The live readout above prints the browser's raw returned string for every button — it never maps an unrecognised value into one of these three, so if a future spec revision adds a fourth value you will see it verbatim.

the code

// Feature-detect the exact IDL member — no instances needed.
const supported =
  typeof GamepadButton !== "undefined" &&
  "type" in GamepadButton.prototype;

// Readonly IDL attribute ⇒ an accessor with a getter and no setter.
const d = Object.getOwnPropertyDescriptor(GamepadButton.prototype, "type");

// With hardware connected (after a button press wakes the pad):
window.addEventListener("gamepadconnected", (e) => {
  const pad = navigator.getGamepads()[e.gamepad.index];
  for (const [i, button] of pad.buttons.entries()) {
    console.log(i, button.type); // "standard" | "non-standard" | "trackpad"
  }
});
