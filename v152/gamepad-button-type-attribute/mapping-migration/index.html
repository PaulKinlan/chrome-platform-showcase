Mapping Migration

Run the two worlds side by side over the same button list: the legacy classifier (sniff gamepad.id for vendor strings, hard-code per-controller index tables) versus the Chrome 152 classifier (read button.type, feature-detected). The diff table shows where they disagree, and the migration pattern handles the three edge cases that break naive code: the attribute being absent, a pad with no trackpad, and a future enum value your code has never seen.

Flag required for the modern column to use real type values: a Chrome build containing CL 7760763 with --enable-blink-features=GamepadButtonTypes (or chrome://flags/#enable-experimental-web-platform-features). On other browsers the modern classifier honestly reports "attribute absent" and falls back.

legacy — id sniffing + index tables

// Breaks on new hardware, remaps,
// clone pads, and future browsers.
const SONY = /054c|dualshock|dualsense/i;
function isTouchpad(pad, i) {
  return SONY.test(pad.id) && i === 17;
}

migrated — feature-detect, never bucket unknowns

function classify(button, pad, i) {
  if ("type" in button) {
    switch (button.type) {
      case "standard":     return "standard";
      case "trackpad":     return "trackpad";
      case "non-standard": return "non-standard";
      default:
        // Forward-compat: surface new enum
        // values, do NOT fold them into an
        // old branch.
        return "unknown:" + button.type;
    }
  }
  // Attribute absent → legacy fallback,
  // clearly marked as a guess.
  return isTouchpad(pad, i)
    ? "trackpad (legacy guess)"
    : "unclassified";
}
