Warning Decision Tree

Chrome decides between nothing, the new bypassable suspicious-site pop-up, and the classic red interstitial from three real inputs: the user's Safe Browsing level, the real-time lookup verdict Google returns, and the SuspiciousSiteWarnings feature state. Set each input below and follow the exact pipeline Chromium runs.

A web page cannot trigger or observe a real Safe Browsing verdict against itself — verdicts come from Google's server-side real-time lookup. This walkthrough executes the documented decision logic (mirrored from url_lookup_service_base.cc) on your choices, and the pop-up shown for the WARN outcome is an annotated recreation, not the real Chrome UI.

    This site may be trying to trick you

    Chrome's Enhanced protection found signals that this site may be dangerous. You can go back, or continue if you trust it.

    The real pop-up is browser chrome: it sits above the page, must be acknowledged before continuing, and the page itself keeps loading behind it (threat type 29 is documented as "a nonblocking warning"). Wording varies by platform and release.

    No choice recorded yet. Chromium records whether the warning was heeded or bypassed, and an optional HaTS survey captures did_proceed.

    the mapping, straight from source

    // components/safe_browsing/core/browser/realtime/url_lookup_service_base.cc
if (rt_threat_type == RTLookupResponse::ThreatInfo::SOCIAL_ENGINEERING &&
    rt_verdict_type == RTLookupResponse::ThreatInfo::WARN) {
  return base::FeatureList::IsEnabled(kSuspiciousSiteWarnings)
             ? SB_THREAT_TYPE_WARNABLE_SUSPICIOUS_SITE   // = 29, "a nonblocking warning"
             : SB_THREAT_TYPE_SAFE;
}
