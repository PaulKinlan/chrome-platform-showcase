Observability Probe

Safe Browsing verdicts are deliberately invisible to page JavaScript: exposing "this user's browser thinks I'm suspicious" to the page would tell attackers exactly when they've been caught. This tool runs real, falsifiable probes in your browser and reports the actual values returned — if Chrome ever web-exposed a verdict surface, these probes would start failing.

live probes

Each probe evaluates a candidate surface a page might hope to read a Safe Browsing state from, and prints the browser's actual returned value — not an assumption.

what a page experiences during a suspicious warning

  • No blocking, no unload: threat type 29 is documented in sb_protocol_manager_util.h as "a nonblocking warning" — unlike an interstitial, the navigation is not replaced. The page loads and runs while the pop-up sits above it in browser chrome.
  • No event, no header, no API: there is no DOM event, response header, or JavaScript surface that tells the page a warning was shown, heeded, or bypassed. The probes above verify the API absence live.
  • Where the state actually lives: in the browser process — the omnibox security state becomes MALICIOUS_CONTENT_STATUS_WARNABLE_SUSPICIOUS_SITE (chrome_security_state_util.cc) and the histogram SafeBrowsing.SuspiciousSiteWarning.VerdictReceived is recorded. A user (not a page) can inspect both — see the Field Verification Lab.

code

// There is deliberately nothing to call. These all hold in every browser today:
typeof navigator.safeBrowsing        // "undefined"
'safeBrowsing' in window             // false
typeof document.securityState        // "undefined" — pages cannot read security UI state
window.chrome?.safeBrowsing          // undefined — chrome.* extension APIs are not page-exposed
