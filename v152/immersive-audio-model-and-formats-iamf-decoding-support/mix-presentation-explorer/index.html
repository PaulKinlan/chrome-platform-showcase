Mix presentation explorer

IAMF's core idea: one stream carries channel beds, Ambisonics scenes, and dialogue objects as audio elements, plus several pre-authored mix presentations — and the decoder, not the server, picks the rendition that fits your loudspeakers, headphones, and language. Change the playback setup below and watch the §7.3.1 selection walk a worked descriptor set.

What is real here and what is a model: browsers expose no JavaScript surface for parsed IAMF descriptors — selection happens inside the decoder — so the descriptor set below is a clearly-labelled worked example implementing the spec §7.3.1 selection guidance in page script. The decodingInfo() probe underneath it is a real call: it answers whether this browser could actually decode the modelled sequence.

the model in spec terms

IA Sequence
├─ Descriptors
│  ├─ Codec Config OBU      (one per sequence — here: Opus, 48 kHz)
│  ├─ Audio Element OBUs    (channel-based bed / scene-based Ambisonics / …)
│  └─ Mix Presentation OBUs (each: language annotations, sub-mixes that
│        reference audio elements with element + output mix gains,
│        and measured loudness per authored layout)
└─ IA Data: Audio Frame OBUs (+ Parameter Blocks: animated gains, demixing)

Playback: parse OBUs → SELECT a mix presentation (§7.3.1: match language
annotations + authored loudness layouts to the playback layout) → decode the
referenced audio elements → render each to the layout (§7.3.2) → mix with
the authored gains (§7.3.3) → loudness-normalise (§7.5.1).
