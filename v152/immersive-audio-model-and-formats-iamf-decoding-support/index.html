v152 · media · spatial audio

Immersive Audio Model and Formats (IAMF) decoding support

Chrome 152 adds decoding and playback of the Immersive Audio Model and Formats (IAMF) container inside HTML media elements via Media Source Extensions. IAMF is AOM's open, royalty-free spatial audio format carrying channel-based, scene-based (Ambisonics), and object-based presentations over Opus, AAC-LC, FLAC, or LPCM substreams — so one delivery format can render to stereo, 7.1.4, or binaural without proprietary codecs or hand-rolled JavaScript channel routing.

concepts

  1. Codec string support matrix

    Probe the exact iamf.PPP.AAA.<codec> parameter strings from IAMF §6.3 through canPlayType, MediaSource.isTypeSupported, and MediaCapabilities — each API's raw answer shown separately, including strings the grammar must reject.

  2. decodingInfo() playground

    Assemble an IAMF codec string field by field, validate it against the spec grammar, and ask navigator.mediaCapabilities.decodingInfo() for real supported / smooth / powerEfficient answers.

  3. MSE playback pipeline

    Fetch a real IAMF test asset (Chromium's alternating-sine-waves clips, stereo and 7.1.4), append it through a MediaSource SourceBuffer, and play it — with every pipeline step and failure mode reported honestly.

why it shipped

Immersive audio on the web previously meant proprietary formats or decoding discrete channels in JavaScript and routing them through Web Audio by hand. IAMF gives streaming services a single open standard: the bitstream describes audio elements plus mix presentations, and the decoder renders the best mix for the listener's actual output layout — loudspeakers or binaural headphones. Chrome 152 wires IAMF demuxing (ISO-BMFF iamf sample entries) and software decoding via AOM's iamf-tools into the MSE pipeline, gated by the IamfAudioDecoding runtime feature.
