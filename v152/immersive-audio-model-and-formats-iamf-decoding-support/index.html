v152 · media · spatial audio

Immersive Audio Model and Formats (IAMF) decoding support

Chromium's media pipeline learns to decode IAMF — AOM's open, royalty-free container for channel-based, scene-based, and object-based spatial audio — inside MP4 via Media Source Extensions. Web pages negotiate it with the codec string iamf.xxx.yyy.<codec> through MediaSource.isTypeSupported() and navigator.mediaCapabilities.decodingInfo().

Status: proposed, not yet in stable Chrome. ChromeStatus anticipates Chrome 153 (desktop, Android, WebView); the work is tracked under the v152 and v153 milestones. There is no chrome://flags entry and no origin trial: decoding lives behind the IamfAudioDecoding media feature (media/base/media_switches.cc, disabled by default) in Chromium builds compiled with ENABLE_IAMF_TOOLS — launch such a build with --enable-features=IamfAudioDecoding. Builds with ENABLE_PLATFORM_IAMF_AUDIO (platform decoders, e.g. some Android devices) enable it unconditionally. On today's stable Chrome every probe on these pages honestly reports unsupported — that is the correct current answer, not an error.

concepts

  1. Codec probe matrix

    Run real decodingInfo() queries for every IAMF substream codec (Opus, mp4a.40.2, fLaC, ipcm) across the three IA profiles (Simple 000, Base 001, Base-Enhanced 002), next to non-IAMF baseline codecs, and read this browser's actual supported / smooth / powerEfficient answers.

  2. Probe surface triptych

    The same codec string asked through the platform's three capability front doors — canPlayType(), MediaSource.isTypeSupported(), and decodingInfo() — with each surface's literal return value, so you can see why MSE support (the shipping surface) can differ from progressive-playback answers.

  3. MSE sample player

    A real Media Source Extensions playback attempt of Chromium's own IAMF test asset (iamf.000.000.Opus + avc1.640028 in fragmented MP4): probe, fetch, addSourceBuffer(), append, play — each step reporting its true outcome, and stopping honestly where this browser stops.

  4. Codec string lint

    An interactive linter for the IAMF codecs parameter grammar (spec §6.4): see exactly which rule a malformed string breaks — profile digits, range, foreign substream codec, non-AAC-LC mp4a — and compare the grammar verdict against this browser's real isTypeSupported() / decodingInfo() rejection.

  5. Mix presentation explorer

    IAMF's core idea — one stream, many renditions — as an interactive model: choose a playback layout and language, watch the §7.3.1 mix-presentation selection walk a worked descriptor set, and run the real decodingInfo() probe for the sequence it selects.

why it shipped

Delivering immersive 3D audio on the web has meant proprietary formats (Dolby Atmos) or hand-rolled JavaScript channel routing over discrete tracks. IAMF is AOM's standardized, royalty-free answer: a single container that carries channel beds, Ambisonics scenes, and audio objects together with mix presentations — pre-authored renditions the decoder selects per playback layout and language, with loudness metadata attached. Decoding it in Chromium's media pipeline (via MSE) gives gaming, AR/VR, and streaming sites one consistent spatial-audio path across devices, aligned with the open web ecosystem.
