Codec string lint

The IAMF codecs parameter has a strict grammar — iamf.xxx.yyy.<codec>, three-digit profiles 000–255, substream codec one of Opus / mp4a.40.2 / fLaC / ipcm — and a conformant browser must reject anything else. This linter checks each rule of spec §6.4 and puts the grammar verdict next to this browser's real answer.

On a browser without IAMF decoding, valid and malformed strings BOTH report unsupported — so the browser columns cannot distinguish them here, and the page says so instead of pretending. The grammar column is exact regardless: it implements spec §6.4, the same rules Chromium enforces in ParseIamfCodecId() (media/base/audio_codecs.cc). One deliberate Chromium quirk: bare "iamf" is accepted by Chromium for test purposes only — it is not valid spec grammar.

the grammar, rule by rule

codecs = "iamf" "." xxx "." yyy "." codec
  xxx   → primary_profile:    exactly 3 decimal digits, value 0–255
  yyy   → additional_profile: exactly 3 decimal digits, value 0–255
  codec → the string the substream would use in its OWN track:
          "Opus" | "mp4a.40.2" | "fLaC" | "ipcm"
          (mp4a MUST be object type 40, audio object type 2 = AAC-LC)

profiles today: 000 Simple · 001 Base · 002 Base-Enhanced (IAMF §4)
