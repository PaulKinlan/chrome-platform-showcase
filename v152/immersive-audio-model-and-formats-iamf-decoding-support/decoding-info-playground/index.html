v152 · media capabilities

decodingInfo() playground

Media Capabilities is the API a streaming player should use before committing to an IAMF rendition: unlike a boolean type check it answers supported, smooth, and powerEfficient for a concrete configuration. Assemble the iamf.PPP.AAA.<codec> string field by field — the page validates it against the §6.3 grammar exactly the way Chrome's parser does, then queries the real API and prints the real booleans.

Availability: IAMF decode targets Chrome 152 behind the IamfAudioDecoding media feature (no chrome://flags entry). If valid configurations report supported: false, relaunch with --enable-features=IamfAudioDecoding on a build compiled with IAMF support (media_use_iamf_tools). An unsupported answer below is the API's real answer, not a demo failure.

Build the configuration

supported: —smooth: —powerEfficient: —
Adjust the fields and query. The exact configuration object sent, and the raw answer (or rejection), appear here.

the grammar Chrome enforces

Chrome's parser (media/base/audio_codecs.cc, ParseIamfCodecId) requires: the string starts with iamf; the profile fields are exactly three digits each, values 0–255; the substream codec is one of Opus, mp4a (which must continue .40.2 for AAC-LC), fLaC, or ipcm — matched case-insensitively. Profile meanings from the spec: 0 = Simple, 1 = Base, 2 = Base-Enhanced (IAMF v1.1), 3–255 reserved. Try 256, or a one-digit profile, to watch validation and the API both reject it.

code path

const info = await navigator.mediaCapabilities.decodingInfo({
  type: "media-source",
  audio: {
    contentType: 'audio/mp4; codecs="iamf.000.000.Opus"',
    channels: "2",
    samplerate: 48000,
    bitrate: 128000,
    spatialRendering: true,
  },
});
info.supported; info.smooth; info.powerEfficient;
