MSE sample player

The exact pipeline a streaming site would run, against Chromium's own IAMF test asset: probe the codec string, fetch the fragmented MP4, open a MediaSource, addSourceBuffer(), append, play. Every rung reports its true outcome — and the ladder stops, honestly, at the first rung this browser refuses.

On a browser without IAMF decoding the ladder stops at rung 1 with isTypeSupported → false. That is the correct, verified state on today's stable Chrome: the ladder above rung 1 only ever runs on a Chromium build with ENABLE_IAMF_TOOLS launched with --enable-features=IamfAudioDecoding (~Chrome 153 territory). Nothing below simulates playback.

code path

const TYPE = 'video/mp4; codecs="avc1.640028, iamf.000.000.Opus"';
if (!MediaSource.isTypeSupported(TYPE)) stopHonestly();   // rung 1

const buf = await (await fetch('../iamf_alternating_sine_waves_stereo.mp4')).arrayBuffer();
const ms = new MediaSource();
video.src = URL.createObjectURL(ms);
await once(ms, 'sourceopen');
const sb = ms.addSourceBuffer(TYPE);                      // throws NotSupportedError if refused
sb.appendBuffer(buf);
await once(sb, 'updateend');
ms.endOfStream();
await video.play();                                        // real decode or a real error event
