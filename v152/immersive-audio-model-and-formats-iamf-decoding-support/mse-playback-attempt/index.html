MSE playback attempt

The explainer's whole point: IAMF needs no new API — just the standard MSE workflow with a new codec string. The button runs that exact workflow step by step against a real <audio> element and reports each call's genuine outcome. On a build without the decoder, step 3 throws a real NotSupportedError — that error is the honest result, not a bug.

This browser reports no IAMF support (MediaSource.isTypeSupported is false for iamf.001.001.Opus). The attempt below still runs every real step so you can see exactly where and how it fails. To try the real path: Chrome 152+ built with iamf-tools, launched with --enable-features=IamfAudioDecoding (or try chrome://flags/#enable-experimental-web-platform-features).
