Prompt & outcome walkthrough

subApps.add() never throws synchronously — everything arrives through the promise, at two scopes: batch rejections that kill the whole call (including the user declining the confirmation prompt), and per-path exceptions inside failedApps when only some sub-apps fail. The button runs a real call attempt; the table maps every exception the explainer defines to the moment it fires — including which ones the new v152 policies make disappear.

exception scope fires when… policy interaction
subApps undefined before any callcontext The page is not an installed IWA — [IsolatedContext] hides the whole interface. This page's honest state. No policy can expose the API to a normal tab.
SecurityError batch The sub-apps permissions-policy is missing or disallowed for the calling frame. Unaffected by the prompt policies.
NotAllowedError batch The user declined the batch installation prompt that lists every requested sub-app. The v152 story: under AllowSubApps (default = 1, or the origin is in the allow list) no prompt is shown, so this rejection can no longer happen; under BlockSubApps the call fails without prompting.
NotSupportedError batch Called from inside another sub-app's frame — sub-apps cannot nest. Unaffected.
QuotaExceededError batch The request would exceed the platform's per-parent sub-app limit. Unaffected — silent installs still count against quota.
TypeError batch An install path is invalid (must be a relative path starting with /). Unaffected.
ConstraintError per-path (failedApps) Scope overlap: the sub-app's scope prefixes another sub-app's (or the parent's scope prefixes it, or the manifest is the parent's own). Unaffected.
DataError per-path (failedApps) The referenced web manifest is invalid or unparseable. Unaffected.
InvalidStateError per-path (failedApps) That sub-app is already installed. Unaffected.
OperationError batch or per-path A generic system/database failure. Unaffected. 
try {
  const { installedApps, failedApps } = await window.subApps.add(["/calc", "/docs"]);
  // per-path outcomes:
  for (const [path, manifestId] of Object.entries(installedApps)) { /* success */ }
  for (const [path, exception] of Object.entries(failedApps)) {
    console.warn(`${path} failed: ${exception.name}`);   // ConstraintError | DataError | …
  }
} catch (batchError) {
  // NotAllowedError ⇒ the user said no to the batch prompt
  // (never shown when policy exempts this origin from prompting)
}
