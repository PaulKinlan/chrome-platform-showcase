v152 · sub apps for iwas

Install response map

window.subApps.add() takes a list of install paths and resolves to a SubAppsAddResponse that reports each path's fate separately: installedApps maps a path to the new sub app's ManifestId, and failedApps maps a path to the DOMException that stopped it. This demo runs the spec's full “valid relative path” validation and the Chrome 152 quota checks, calls the real API, and maps the response path-by-path.

Real API requirement: window.subApps.add() only exists inside a secure Isolated Web App (isolated-app:// origin) with the sub-apps permission policy. In Chrome 152 no feature flag is needed — the API is enabled by default for IWAs — but a real call also needs a user gesture and shows a confirmation prompt unless enterprise policy waives it. Outside that context this page reports the unsupported branch and the payload it would have sent — it never pretends an install happened.

batch-level validation (what rejects the whole promise)

Before anything installs, the spec rejects the entire add() promise when:

TypeError
Any path is not a valid relative path: empty, a valid absolute URL, missing its leading /, starting with //, or unparseable against the document base URL.
QuotaExceededError
New in the Chrome 152-era spec text: more than 20 paths in one add() call, or the parent would end up with more than 50 sub apps.
SecurityError
The document is not allowed to use the sub-apps permission policy.
NotSupportedError
The call came from inside a sub app — only the parent IWA may manage sub apps.
NotAllowedError
The user declined the unified install confirmation prompt.

per-app failure taxonomy (what lands in failedApps)

DataError
The referenced web manifest failed to fetch or parse.
InvalidStateError
A sub app with that ManifestId is already installed.
ConstraintError
Scope overlap: the sub app's scope nests with the parent's or another sub app's scope, or the path points at the parent's own manifest.
OperationError
A system or database failure during that specific install.

Illustrative response shape (reference only — not a live result)

When the real API runs inside an IWA, a partially-successful add() resolves to something like this:

{
  "installedApps": {
    "/mail/index.html": "/mail/",
    "/calendar/index.html": "/calendar/"
  },
  "failedApps": {
    "/mail/index.html": DOMException { name: "InvalidStateError" }
  }
}
