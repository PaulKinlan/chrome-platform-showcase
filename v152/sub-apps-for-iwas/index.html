Sub apps for IWAs

Chrome 152 ships the Sub Apps API by default for Isolated Web Apps: one installed IWA can add child apps — each with its own name, icons, shelf presence, and OS integrations — through window.subApps.add(), all updated as a single package. The 152 story is governance: three new enterprise policies decide whether adding sub-apps prompts the user, silently proceeds, or is blocked outright. The v150 and v153 demo sets cover the core call surface; these concepts cover the policy layer and the surface's migration.

concepts

  1. Policy prompt planner

    An admin's decision tool: set DefaultSubAppsWithoutPromptsSetting (1 allow · 2 block · 3/unset ask) and toggle an IWA origin's membership in the allow/block origin lists — the planner computes the effective outcome with the real precedence rules (Blocked ≻ Allowed ≻ Default) and emits copyable policy JSON.

  2. Prompt & outcome walkthrough

    What add() can actually return, exercised for real where possible: a live call attempt (honest SecurityError/absence outside an installed IWA), plus the full error model — the batch prompt's NotAllowedError decline, QuotaExceededError, and the per-path failedApps exceptions.

  3. Surface migration probe

    The API moved: early experiments exposed navigator.subApps; what ships is window.subApps gated on [IsolatedContext]. Live typeof reads of both surfaces show your browser's truth, and the page explains why both are absent in a normal tab — by design, not by bug.

why it shipped

Enterprise software suites (think a virtual-desktop client, an office bundle, a POS system) want one install and one update pipeline but several icons on the shelf, each with its own file-type associations and window identity. Sub apps deliver exactly that inside the IWA security model — signed bundles, isolated contexts — and the new policies let admins choose between silent fleet-wide provisioning (AllowSubApps), user-confirmed installs (AskSubApps, the default), or a hard block (BlockSubApps), per origin where needed.

trying it

The API only exists inside an installed Isolated Web App (an isolated-app:// isolated context on ChromeOS): a normal browser tab — including this page — genuinely has no window.subApps, and the demos here treat that as the honest probe result. To exercise the real calls, build and install an IWA (see the IWA guide) or start from the subapps-demo sample, then call window.subApps.add(["/subapp/"]) from the parent app.
