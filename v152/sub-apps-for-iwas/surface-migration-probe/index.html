Surface migration probe

Early Sub Apps experiments and blog posts hung the API off navigator.subApps. What actually shipped is a window.subApps attribute — partial interface Window in Chromium's sub_apps.idl, gated [SecureContext, IsolatedContext]. Both cells below are live reads from this browser; in a normal tab both are rightly undefined, and the gate list explains which requirement hides it.

the three gates on window.subApps

  • [SecureContext] — this page: window.isSecureContext === ….
  • [IsolatedContext] — only pages inside an installed Isolated Web App (isolated-app://, signed bundle) qualify. A normal https tab — like this one — never does, which is the usual reason the attribute is absent even in Chrome 152.
  • RuntimeEnabled=SubApps — shipped enabled for IWAs in Chrome 152; earlier channels needed chrome://flags/#enable-desktop-pwas-sub-apps or --enable-blink-features=SubApps (inside an IWA — the flag alone never exposes it to a tab).
// Migration-safe detection — probe where it ships, not where the blog post said:
const subApps = window.subApps ?? navigator.subApps;   // legacy fallback read
if (subApps) {
  const { installedApps, failedApps } = await subApps.add(["/calc"]);

  // deliberately invisible here. Do not treat this as a browser bug.
