    Two traps worth running back-to-back: run the same valid SSM join twice — the second stops at the duplicate-membership step with InvalidStateError; then try joining 232.1.1.1 without a source after an SSM membership exists — mixing ASM and SSM on one group address is rejected with InvalidStateError (explainer rule). And leaveGroup of an SSM membership must repeat the exact sourceAddress used to join, or the membership is not found. The SSM convention ranges — IPv4 232.0.0.0/8, IPv6 ff3x::/32 — are IANA-reserved recommendations; the bench flags, but does not reject, SSM joins outside them, exactly like the API.
