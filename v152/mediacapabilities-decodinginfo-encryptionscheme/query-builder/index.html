Encrypted Decode Query Builder

Compose a real navigator.mediaCapabilities.decodingInfo() call with a keySystemConfiguration — pick the codec, key system, robustness, and the new encryptionScheme member — then read the exact configuration sent and the real result that came back, including whether a MediaKeySystemAccess was granted.

Availability. encryptionScheme in decodingInfo() is enabled by default from Chrome 152. On earlier builds the dictionary conversion silently drops the member, so queries behave as if it were null ("any scheme"). To test before 152, relaunch Chrome/Canary with --enable-blink-features=KeySystemTrackConfigurationEncryptionScheme, or enable chrome://flags/#enable-experimental-web-platform-features (equivalently --enable-experimental-web-platform-features) — there is no dedicated chrome://flags entry for this feature. Builds that predate the flag entirely ignore the member regardless; the detector below reports what your browser actually does.

const info = await navigator.mediaCapabilities.decodingInfo({
  type: 'media-source',
  video: { contentType: 'video/webm; codecs="vp09.00.10.08"',
           width: 1280, height: 720, bitrate: 2500000, framerate: 30 },
  keySystemConfiguration: {
    keySystem: 'org.w3.clearkey',
    initDataType: 'keyids',
    video: { robustness: '', encryptionScheme: 'cenc' }  // <- new in 152
  }
});
// info: { supported, smooth, powerEfficient, keySystemAccess | null }
