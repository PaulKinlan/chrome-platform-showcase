MediaCapabilities.decodingInfo.encryptionScheme

Chrome 152 adds the encryptionScheme member to the KeySystemTrackConfiguration dictionary used by navigator.mediaCapabilities.decodingInfo(). A streaming site can now ask, before it fetches a single segment, whether encrypted decode with a specific scheme — "cenc" (AES-CTR full-sample), "cbcs" (AES-CBC pattern), "cbcs-1-9", or null for "any scheme" — is supported, smooth, and power-efficient, and get the matching MediaKeySystemAccess in the same answer. The backend already existed; this launch plumbs the member through the Blink IDL layer.

why it shipped

The EME dictionaries (MediaKeySystemMediaCapability) have carried encryptionScheme since the encryption-scheme-query addition, but decodingInfo() — the API that also answers smooth and powerEfficient — silently dropped the member, so sites had to make two different queries and could still pick content a device could not decrypt. Different schemes are generally incompatible with one another (a cbcs-only pipeline cannot play cenc content), so asking up front avoids fetching undecryptable media. Chrome 152 aligns decodingInfo() with the W3C Media Capabilities spec's KeySystemTrackConfiguration, where encryptionScheme defaults to null meaning "any scheme is acceptable" — keeping unaware callers backward compatible.
