Encryption Scheme Support Matrix

Run real decodingInfo() queries for null vs "cenc" vs "cbcs" vs "cbcs-1-9" vs a deliberately bogus scheme, across three codecs, and compare the answers side by side. The bogus column doubles as an honesty check: a browser that honors the member must answer no there. A second matrix cross-checks the same grid through EME's requestMediaKeySystemAccess(), which has honored encryptionScheme since Chrome 74.

Availability. Enabled by default from Chrome 152; earlier builds silently drop encryptionScheme from decodingInfo() so every scheme column will match the null column. To test before 152: --enable-blink-features=KeySystemTrackConfigurationEncryptionScheme, or chrome://flags/#enable-experimental-web-platform-features / --enable-experimental-web-platform-features (no dedicated chrome://flags entry). The EME cross-check matrix below gives real per-scheme answers even on older builds. Note: this sandbox/headless Chromium may lack the Widevine CDM — pick ClearKey for a key system that ships inside Chromium itself, and expect honest no answers for Widevine.

code

for (const scheme of [null, 'cenc', 'cbcs', 'cbcs-1-9']) {
  const { supported, smooth, powerEfficient } =
    await navigator.mediaCapabilities.decodingInfo({
      type: 'media-source',
      video: { contentType, width: 1280, height: 720, bitrate: 2500000, framerate: 30 },
      keySystemConfiguration: {
        keySystem: 'org.w3.clearkey', initDataType: 'keyids',
        video: { robustness: '', encryptionScheme: scheme },
      },
    });
}
