Sub apps

The Sub Apps API lets an installed Isolated Web App programmatically install, list, and remove auxiliary apps that share its origin, storage, permissions, and update cycle — while appearing to the OS as fully distinct applications with their own names, icons, shelf windows, and file/protocol handlers. The surface is window.subApps with three promise-returning methods: add(), remove(), and list(). Exposure is gated on Isolated Contexts, so a normal browser tab — including this one — never sees the API; every demo below makes the real call anyway and explains the honest result.

  4. Error Taxonomy Explorer

why it shipped

A single Isolated Web App install previously had to squeeze suite-like products — an office suite, a multi-app streaming portal — under one launcher icon, one name, one shelf window. Sub apps give one signed bundle many distinct OS-level entry points without separate installs, fragmented storage, or divergent update cycles. Three enterprise policies (DefaultSubAppsWithoutPromptsSetting, SubAppsWithoutPromptsAllowedForOrigins, SubAppsWithoutPromptsBlockedForOrigins) control whether installs need a user prompt.
