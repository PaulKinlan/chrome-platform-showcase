Resilient Adoption

The API is designed to "naturally degrade to existing behavior" — but only if your code respects three sharp edges: undefined is not false, addEventListener can never detect support, and events you weren't listening for yet are gone forever, which is exactly why the readonly catch-up property exists. Each panel below runs the real pattern against this browser and reports what actually happens.

Flag / origin trial required for the real path: the surface ships behind --enable-blink-features=UAImageReplacementAPI on a build containing the implementation, or the planned Chrome 152–157 origin trial. All four panels run honestly on any browser — including this one, where the probes below can and do return the unsupported result.

1 · undefined is not false

On an unsupported browser img.replacedByUserAgent reads undefined. Code like if (!img.replacedByUserAgent) can't tell "author content showing" from "API absent" — use strict comparison or feature-detect first.

Not run yet.

2 · addEventListener is not a probe

addEventListener("uareplacestart", …) succeeds in every browser — unknown event types are legal. That makes attachment harmless (good for progressive enhancement) and useless as detection (a confirmed past regression class in this showcase). The only real probe is the prototype member check.

3 · the missed-event race

A replacement can start before your script runs. This panel dispatches a synthetic uareplacestart first, then wires the listener — which misses it — then attempts the catch-up read the explainer prescribes.

4 · you cannot trigger or probe replacement

By design (explainer non-goals + anti-fingerprinting): no author API starts a replacement, no API enumerates the browser's replacement features, and the events fire only on explicit user intent. This panel searches the real objects for any such surface.

the code

// SAFE: feature-detect the exact member, then branch.
const supported = "replacedByUserAgent" in HTMLImageElement.prototype;

// SAFE: strict comparison — undefined never passes as "replaced".
if (img.replacedByUserAgent === true) hideModelDetails();

// UNSAFE: truthy/falsy check — on an unsupported browser undefined is
// falsy, so this "works"… until you invert it:
if (!img.replacedByUserAgent) {
  // runs BOTH when author content is showing AND when the API
  // simply doesn't exist. Those need different handling.
}

// NOT A PROBE: this line succeeds everywhere, support or not.
img.addEventListener("uareplacestart", onReplace);

// THE RACE: events before your script ran are gone. The readonly
// property is the catch-up — and script cannot forge it.
if (supported && img.replacedByUserAgent) onReplace();
