User Agent Image Replacement API

Browsers are starting to replace images on the user's behalf — think a generative virtual try-on swapping a product photo. This API lets the page observe (never trigger) that: two events on HTMLImageElement — uareplacestart and uareplaceend — plus a read-only replacedByUserAgent boolean, so authors can hide overlays and copy that no longer match the pixels. Origin trial UAImageReplacementAPI in Chrome 152.

concepts

  1. Surface probe & trial on-ramp

    Probe the exact shipped members — 'replacedByUserAgent' in HTMLImageElement.prototype, onuareplacestart, onuareplaceend — with the origin-trial token steps and the UAImageReplacementAPI flag name from runtime_enabled_features.json5. The probe genuinely fails where the trial is off.

  2. Coordinated product card

    The explainer's e-commerce scenario, wired for real: a product image whose zoom control and size copy react to genuine uareplacestart/uareplaceend listeners. Because pages can't trigger UA replacement (by design), a clearly-labelled rehearsal mode dispatches synthetic events through the same listeners — with isTrusted honestly displayed.

  3. Observability contract

    What the page can and cannot know, proven live: replacedByUserAgent is read-only (assignment provably does nothing), synthetic events are isTrusted: false, and no call exists to request a replacement — the anti-fingerprinting rule that events only fire on real user intent, made observable.

why it's in the trial

Chrome features that substitute media (generative try-on and similar) got feedback from sites that silent replacement breaks the page around the image: zoom lenses render the wrong pixels, "model is 6'1" wearing size M" copy becomes wrong, analytics can't tell the experiences apart. The API is deliberately minimal: observation only, no replacement-content access, no page-initiated replacement, no capability probing — the events fire only when a real user actually uses such a browser feature. The trade-offs (and the possible future notransform-style hints and :replaced-by-user-agent pseudo-class) live in the explainer.

enabling it

Origin trial in Chrome 152: register for UAImageReplacementAPI and serve the token, or launch with --enable-blink-features=UAImageReplacementAPI (the exact runtime_enabled_features.json5 name), or enable chrome://flags/#enable-experimental-web-platform-features. Note: exposing the members does not make events fire — only a real user-initiated replacement feature does, which is the API's anti-fingerprinting contract.
