Replacement Monitor

The explainer's recommended pattern for tracking replacements page-wide: one capturing listener on document observes uareplacestart for every image at once, then each replaced element is watched for its own uareplaceend. The capture-vs-bubble counters below show why it must be a capturing listener.

Flag / origin trial required for real events: real uareplacestart/uareplaceend events come only from a user-invoked browser feature on a build with --enable-blink-features=UAImageReplacementAPI (or the Chrome 152–157 origin trial). The dispatch buttons fire synthetic, clearly-labelled events — created with bubbles: false, matching how Chromium creates the real ones (Event::Create in html_image_element.cc) — so the monitor's plumbing is exercised with the same propagation semantics.

why the listener must capture

Two document-level listeners for uareplacestart:
capture phase (capture: true)0
bubble phase (default)0

The events are created non-bubbling, so they pass document only on the way down (capture). A default bubble-phase listener on document never fires — the count above stays 0 no matter how many events you dispatch.

    the code

    const replaced = new Set();

// One capturing listener sees uareplacestart for EVERY image —
// capture is required because the events do not bubble.
document.addEventListener("uareplacestart", (e) => {
  const img = e.target;
  replaced.add(img);
  updateBadge(img, true);

  // Watch this element for the end of its own replacement.
  img.addEventListener("uareplaceend", () => {
    replaced.delete(img);
    updateBadge(img, false);
  }, { once: true });
}, { capture: true });

// Snapshot scan for replacements that predate the listener:
for (const img of document.images) {
  if (img.replacedByUserAgent) replaced.add(img);
}
