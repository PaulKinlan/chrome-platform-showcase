Try-On Storefront

The explainer's own scenario, wired for real: a product page listens for uareplacestart / uareplaceend on its hero image and adapts — hiding the model-dimensions caption and the zoom widget while substitute content is showing — and feeds the same events into the analytics stream the explainer says sites asked for.

Flag / origin trial required for the real path: only the browser can start a replacement (a user-invoked feature such as virtual try-on), and only on a build with --enable-blink-features=UAImageReplacementAPI or an origin-trial token (Chrome 152–157). This page attaches real listeners to the real event names; the "synthetic dispatch" buttons below fire new Event("uareplacestart") at the image so you can watch the page-side adaptation code run today. A synthetic event exercises your handlers — it does not make the browser replace anything, and it cannot set the readonly replacedByUserAgent property.

    the code

    const imageEl = document.querySelector("img.product-view");
const zoomLens = document.querySelector(".zoom-lens");
const modelNote = document.querySelector(".model-note");

// The page reacts to replacement, whoever initiated it.
imageEl.addEventListener("uareplacestart", () => {
  zoomLens.hidden = true;        // magnifies the ORIGINAL photo — now wrong
  modelNote.hidden = true;       // "model wears size M" — now wrong
  analytics.track("ua-replace-start");   // the explainer's analytics use case
});

imageEl.addEventListener("uareplaceend", () => {
  zoomLens.hidden = false;       // replacement reverted/finished — restore
  modelNote.hidden = false;
  analytics.track("ua-replace-end");
});

// Replacement may have happened before this script ran:
if (imageEl.replacedByUserAgent) {
  zoomLens.hidden = true;
  modelNote.hidden = true;
}
